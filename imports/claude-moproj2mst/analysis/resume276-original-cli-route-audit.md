## Safe distinct offline route

Use immutable copied-image disassembly and retained CP214 agent semantics to test whether each omitted guard can be removed **without changing the CP264 observation contract**. This is a proof task, not an observer run:

1. Freeze and cite the original image hash, disassembly extraction provenance, the exact CP214 hook predicates/counters, and the CP264 selected clone/path contract. Work only on local copies already retained in this checkout. Do not patch the original or start a REA session.
2. For every interval in the CP269 frontier schedule, list each disarmed entry address, its selected-caller and frame filter, active spans, and the positive or poisoning event that would be missed. Include the activation interval's five-address conflict and creator/helper reentry while acceptance is active.
3. Build complete control-flow and call-target evidence for each claimed impossible event, including indirect callbacks, exception/unwind paths, recursion, other owned threads, and caller-site ambiguity. A positive CP214 trace or short copied call window does not prove absence. If the proof cannot cover one interval, record the concrete counterexample/unknown; keep the full four-slot schedule no-go.
4. Only if every removed guard has a target-specific proof may a **separate** schedule review reconsider four-slot coverage. It must retain caller/frame/order/overlap predicates, exact creation identity, selected helper QString and normal returns. That review would still precede source-frozen native implementation, harmless-surrogate API/cleanup qualification, instrumentation-neutrality assessment and independent policy review. It would not authorize an original run by itself.

The smallest safe CP276 conclusion is therefore precise: offline CFG analysis may eliminate or substantiate the scheduling blocker, but no currently established route yields the missing runtime witness. Continue independent converter implementation and tests under their own ownership rules while this witness remains gated. Do not infer full Open, Save, accepted Close, negative-ID causation or application parity from any retained positive-prefix event or directory delta.
