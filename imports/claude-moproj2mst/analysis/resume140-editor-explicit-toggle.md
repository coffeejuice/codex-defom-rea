## Implementation

`explicitSolverToggled(binding,checked)` requires same live Project/OPI generation/GuiModel/remesh, completed private page metadata/source-model/remesh tokens, and a matching qualified cached selected radio: true→solver6, false→one of0/1/2/4/5. Unsupported cached values or mismatched boolean refuse before projection. These are candidate event-profile guards, not native validation.

The method then assigns only IterationPage.explicitControlsVisible=checked and returns Completed. It does not call pageState/simCtl, inspect sourceControl or dimension, read parameters, normalize CG, populate defaults, alter any other control/text/model/OPI/remesh field, perform I/O or invoke Apply. The same live model's actual step may be absent/replaced while completed controls remain; this callback has no SC prerequisite.

Root's Fill assignment false matches native Iteration Fill's unconditional initial hides for all currently admitted nonexplicit solvers. It does not imply a delivered toggle. The optional field defaults unknown on unfilled/manual page values rather than inventing physical state.

Visibility does not establish the four explicit edit values. Native solver6 Fill formats the first two as g6 doubles and last two via signed32 conversion/int formatting; native Apply reads all four through toDouble. No edit state, conversion domain or setup/history value was fabricated here. Existing solver6 Fill/Apply refuses remain before candidate model stores, and public palette/6504abb0/completeForPublicSave=false are unchanged. Their retained refusal is not described as original native solver6 behavior.
