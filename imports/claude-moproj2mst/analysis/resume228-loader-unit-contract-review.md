# CP228 loader unit owner contract review

## Verdict: PASS, with test-seam and evidence-boundary corrections

The proposed owner command is compatible with the current source path. `GuiModel` is allocated as a `shared_ptr` using `projectDb(p)` and `dim`; its constructor allocates `step` and completes `guiSimCtrlInit(step->sim_ctrl)` before control returns to `newModel`. The loader then calls `def::key::set_model_unit(*m->step, p.unit, true)` and returns the same shared pointer. An inline/non-inline `void GuiModel::setModelUnit(std::int32_t, bool)` delegation preserves that sequence and removes the caller's raw-step alias. `engine.hpp` already includes `<cstdint>`, and `gui_model.cpp` already includes `<defkey/item_writers.hpp>`; no extra include appears necessary. No same-named API conflict was found.

`set_model_unit` changes `sim_ctrl.unit` only when it differs. On a changed unit with `reset=true`, it invokes `reset_unit_defaults`; on equality, it is a no-op even with reset true. Existing Testkit coverage in `source/port/defkey/tests/test_item_writers.cpp` checks both the changed-unit reset fields (`envtmp`, `unte2h`) and equality preserving a seeded value. The proposed owner test should compare equivalent independently initialized steps (or explicitly seed both identically), since a `GuiModel` constructor initializes defaults from the current GUI startup profile before the owner command runs. The exact project `unit=0` case is useful for the equality path; changed units 1 or 2 cover reset.

The report's suggested `tests/mdt` location is valid: `source/apps/moproj2mst/CMakeLists.txt` discovers `test_*.cpp` under each test subdirectory with `CONFIGURE_DEPENDS`. Use `TEST_CASE`, `CHECK_EQ`, and `REQUIRE` from Testkit; there is no need for C `assert`. For the loader-level assertion, the concrete seam is `m2m::mst::g_loaderSlots.newModel`: declare/call `mst::installLoaderSlots()` in the test (as existing MDT loader tests do), then invoke the installed pointer with a `Project` whose `unit` is set. `projectDb(p)` lazily creates `p.dataDb`, so a corpus fixture is not inherently required for this narrow behavior. Assert the returned owner's `step->sim_ctrl.unit`, not a newly exposed native pointer. This would directly exercise the `newModel` caller, which `test_gui_startup_unit.cpp` currently does not.

Failure semantics need a narrow qualifier. The source order establishes that allocation/constructor failure happens before the setter and no model is returned; ordinary C++ unwinding destroys the local `shared_ptr` if a later call throws, and the exception is not caught here. However, the current setter and constructor provide no injected failure seam in the proposed test, and no native/original failure or rollback experiment is cited. Do not describe this as runtime-verified native rollback behavior. It is a code-derived exception/ownership consequence only; no transaction or special rollback should be added.

The authored contract otherwise correctly preserves `reset=true`, avoids a pre-equality check and constructor/factory redesign, and leaves the C ABI untouched. Source review only: no source, test, build, shared state, original, GUI, or REA changes were made.
