# CP214 DOE queue: keep the two Type 2 paths distinct

## Decision

There is no safe public Type 2 increment source-closed at this checkpoint. Preserve the current guards. The next implementation-sized step is to thread a checked live Session/Project/SUB/StudyIo context through the actual lazy keyword reader, then reproduce only the suppression/flag90 notifier entry prefix before the existing key/receiver guard. This is the CP145-admitted seam, not completion of `SetOprHasDoe`.

The empty-study Save prefix and nonempty-variable `SetOprHasDoe` path are different encounters. Empty Save already reaches XML open/write/close/status before refresh delivery refusal; that does not qualify any nonempty keyword codec, key construction, receiver population or callback. Conversely, source facts about nonempty notifier dispatch cannot authorize relaxing the empty-study Save guard or claiming B120 output.

## Why B120 is not an acceptance case

`analysis/resume93-next-diff-acceptance.md` and `analysis/resume98-retained-mode-binding-audit.md` establish that B120's before tree has a Type 0 project and no DOE study, while the retained after-state includes a UI-created Type 2 study and seven control files. That is a study-creation action sequence, not Open→Save on the before input. Candidate conversion from the before tree cannot synthesize those effects. The retained after-state may support bounded lower-level training only; it is not evidence that public lifecycle conversion may create/select a study.

`analysis/wave3-doe-next-active-study-dependency.json` still identifies the native Report/QObject factory prefix as the blocking dependency for task/sample execution and says not to implement detached active-study behavior ahead of it. This queue item does not own that native Report dependency.

## Smallest independently implementable increment

Implement CP145's notifier-entry boundary only after the real per-call owner context is available at the actual lazy-read call site. Owned files proposed by CP145 are `source/apps/moproj2mst/src/doe/variable_notify.hpp/.cpp`, `variable_record.cpp`, and `keyword_reader_prefix.hpp/.cpp`, plus one focused `tests/doe/test_keyword_notifier_entry.cpp`; coordinate exclusive ownership before editing. Preserve the existing `M2M_E_UNSUPPORTED` after the committed keyword/operation prefix until there is evidence for the key, ordered weak receiver list, backend, and callback return. The notifier's native suppression check and unsuppressed flag90 reset are source-qualified; constructing host-equivalent strings or an empty receiver list is not.

Acceptance should cover actual ConversionSession/Type2 lazy-read ownership and stale Session/Project/SUB/StudyIo/notifier refusal; suppressed entry leaves flag90 unchanged, unsuppressed entry resets it before the key guard; prior keyword append remains committed on refusal; no fabricated key/map/list/receiver/nominal-text, sample I/O, DOM or public Save continuation; and direct legacy byte callers retain their existing behavior. Run owner preflight for Testkit entry/includes/macros and no C `assert`; root owns grouped build, full source-stable suite and freeze.

## Evidence needed to go farther

For `SetOprHasDoe` continuation, obtain one same-occurrence original witness binding exact key and `(int operation ID, bool true)` argument order, codec/key result, ordered live weak receivers and first receiver backend/logical-list state, then normal callback return/exception and the caller's subsequent named-keyword lookup. CP145 states why static metadata and registration-constructor evidence do not establish a live receiver census or callback result. Any original capture remains root-serialized under the GUI release lifecycle policy; none was run here.

For B120, the useful witness is a same-occurrence trace of Add Study, selection/activation, sample generation and Save from a fresh original process, with the retained after-state's exact study/files bound to that process. Until then, keep the public no-study path as-is. Do not treat a retained file hash match for an empty Save prefix as full Type 2 Save acceptance.
