## Callback and ordering audit

The old `ownerSimCtl(Project&, Props&)` raw-return helper is absent from `l6_slots.cpp`. Its replacement `withPropsSimCtl` requires an exact bool result and invokes the supplied reader inline. A nonnull explicit `sc` is handled first, before inspecting `pr.owner` or calling `opModel`; this preserves the no-lookup route. For null `sc`, missing owner invokes the reader once with null; present owner enters `engine::withOpStep` at the former lookup point and passes `step ? &step->sim_ctrl : nullptr` directly to the reader while the step callback is active. `withOpStep` invokes synchronously, and no lambda stores or returns the nested address. No new `GuiModel::simCtl()`/`GuiModelAccess::withStep` geometry refusal or common-block allocation was introduced.

`propsReadSteps`, `propsReadEnvTemp`, `propsReadStepBy`, and `propsReadConvection` each call the helper separately, so the reached Distortion slot still performs four independent model lookups in its original sequence. Each callback returns false on null before any common-block dereference or `base::setStepBy`. Nonnull paths retain the same field offsets, value formatting, StepBy branch and writes. `distortionPropsLoad` still calls those four readers and then writes fixture/pass counts. There is no cache1 or selected-length code in the changed source. The explicit-`sc` branch has no current reached production caller; its no-lookup behavior is source-qualified, not runtime-proven by this fixture.
