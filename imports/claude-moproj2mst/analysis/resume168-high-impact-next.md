# CP168 independent high-impact queue audit

## Decision

No **new public Open→Save→Close or original failure-parity source edit** is admitted by the retained evidence after CP167, outside the separately owned CP168 connector cut. The highest-impact independent work is a bounded **Report document owner evidence closure**, not a production patch: trace the actual lazy `SubProject+0x30` producer in Report Open, its parent/constructor returns and first payload producers, then reconcile fresh Save lookup and Close's two guard reads. This is the common missing owner for three public commands. A static pass can narrow it without GUI control, but only a same-instance original occurrence can establish the changing owner, callback, Qt and modal outcomes needed for public admission.

This decision uses `analysis/takeover-state.json`'s 15 `recovery_queue` entries, CP164–167 integration reports and current source. The target original is **DEF_GUI_MO_64 v11.0.2**, SHA-256 `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`. Addresses below are preferred-image VAs. No new original occurrence, REA result, candidate build, deployment or parity result is claimed.

## Why Report is the first high-impact evidence boundary

The selected original Report Open `0x1412ae070..0x1412ae3c7` (range SHA-256 `7b7367a63dfd914fbb4fb85b8a7710484e39a8fabb645f500d08af621dc51818`) forms the sibling `.DS` path **before** a fresh document lookup. `0x1412b0f70` selects the current active SubProject; `0x1400b5ad0` reads its current `+0x30`, or allocates `0x70`, calls `SfSessionManager` constructor `0x140643100` with a proposed current-main QObject parent, stores the returned document into that selected slot, and rereads it. The Open caller then uses the saved document for reset, read and traversal. Those are conditional static edges, not proof of allocation, accepted parent, parser success or identity across callbacks. See `analysis/resume165-report-owner-next.md`, including the qualified byte-range hashes, and `analysis/resume164-close-next.md`.

Current `source/apps/moproj2mst/src/ops/report.cpp` (SHA-256 `e378d472550bbe9f6a109baa330f6612277328ac425853cf5e17ba316252b43a`) refuses Report Open at the document accessor. `src/engine/report_document_slot.cpp` (SHA-256 `1f004f5f797fc0abeed34b0a90a0a58059c7763e9ea61576eaa0a7c4fb7251b4`) stores only a diagnostic initial null/non-null observation; it cannot publish, rebind or destroy a live document. `src/engine/save_current.cpp` (SHA-256 `bc77d02830ac0c75ea5fa669f303b818178610291fdbda837f1a1abb08185129`) retains the Report `vt+0x68` Save guard. Close `0x1400b5bb0` rereads `S+0x30` twice before the deleting virtual and clear. Constructor `D+0x48` DOM, later `D+0x20` model, `+0x30` interactive payload, `+0x40` parts, `+0x58` XML copy and Save branch `+0x68` cannot be replaced by an immutable KnownNonNull token. `analysis/resume165-report-owner-next.md` corrects older path-before-owner ordering and explains why the existing `.DS` helper is already the source-ready pure prefix.

The next **independent evidence work** is to inspect the complete default Report Save branch `0x14064ab80..0x14064b14f` (retained range SHA-256 `bbfdcd500aa6585078f8914046bdad1b0fb08d6909035c6dcf72642701e87c8c`) and intervening `D+0x68` writers/indirect callback receivers, then produce an owner/ordering contract linking Open's selected `S/D` with Save's fresh lookup and Close's two reads. A negative direct-call scan is insufficient. Public implementation requires one natural same-instance Open→Save→accepted-Close receipt with actual `P/S/D`, constructor and QObject-parent results, document slot writes/rereads, reset/read/traversal returns, payload/DOM results, Save branch/callbacks and Close admission/deletion order. The parent repository's supported GUI-control release plus verifiable receipt remains a prerequisite for that original GUI occurrence. No GUI session should be acquired for this audit.

After that witness, the implementation seam is the actual owning SubProject/document producer, followed by Report Open, Save and Close callsites; do not add another detached slot helper. Focused tests should cover same-SubProject publication/reuse, changed active SubProject between commands, failed allocation/parent acceptance, reset/read failure after publication, current DOM/SessionRoot append result, and Close's first-null versus changed second-read cases. Retain Report Open/Save/Close public guards until the owner and callback-sensitive order are represented. Use the existing `tests/mdt/test_report_document_slot.cpp`, `tests/p16/test_report.cpp`, `tests/s/test_report_ds_path.cpp`, Report Save tests and normal source-stable focused/full/freeze gate for any later source change. These are prospective tests, not a claim that a patch is admitted now.

## Source-ready versus executable

An independently executable static Report owner investigation is valuable because it targets the shared public owner rather than another private helper. It is **evidence work**, not a source-ready implementation. R300's pending-call barrier is the one substantial private design/implementation candidate outside CP168, but its first cache write deliberately ends in guarded refusal and cannot by itself advance an actual public Save or the original reader tail. The RIO conjunction regression, B98 headless rerun, ShapeOptim path effect, numeric parser and FRCROT value handoff were already implemented or frozen. For every remaining public or native-failure continuation in the table, the named original owner/branch/occurrence witness is absent. A production edit now would choose an unobserved result or lifetime and widen admission without evidence.

This pass only wrote this report. It did not edit source, tests, fixtures, shared plan/state, build outputs or evidence; run tests or a build; start the original application; acquire GUI control; or use live REA.
