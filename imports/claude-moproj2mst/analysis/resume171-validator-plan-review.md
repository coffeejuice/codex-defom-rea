# CP170 constructor validator plan: independent architecture review

## Decision

**Approve a file-local extraction as a separate source checkpoint, conditionally on CP170 acceptance and a stable source/test snapshot.** The four existing branches at `task_factory.cpp:205-314` share the same owner, pending Report, private identity, address-point, QList/QString, and completion checks. Their sparse-field predicates, writes, phase advances, and `M2M_E_UNSUPPORTED` strings differ. A read-only common qualifier followed immediately by each branch's own prewrite condition preserves the selected CP167-170 effect order. The helper is a reviewability change, not a new native behavior claim or a prerequisite for the CP171 QVector cut.

The relevant native qualification is limited to the selected normal, non-null private path. `resume170-connector-next.md` identifies the zero stores at private `+0x40`, `+0x48`, `+0x50`, `+0x58` and the stop before the QVector load at RVA `0x1311c7`. It expressly does not establish exceptional cleanup, a live constructor occurrence, or later container and QObject effects. The proposed helper should carry none of those claims.

## Why the extraction can preserve behavior

- `initializeNativePrefix()` uses sequential `if` blocks, so one call can commit all four zero observations before the final stop (`task_factory.cpp:203-326`). Keep four separate calls and four separate field/phase writes; a loop or one combined write would hide the intermediate committed states and change later malformed-frame refusals.
- Each current branch checks `ownsWidgetRuntime(widgets)`, which compares both shared ownership and pointee identity (`task_runtime.cpp:30-37`). It also compares the locked QList and QString bindings to the two records on that exact root and checks their module hash and symbol RVAs (`task_factory.cpp:211-223,238-250,264-276,292-304`). A common qualifier can retain these checks, including the independent `allocatedPrivateIdentity` comparison. Pointer equality to the current `privateState` alone is insufficient.
- The four local predicates in the proposal match the current sparse contract: later fields must remain disengaged, and each predecessor field must equal an engaged zero (`task_factory.cpp:223-225,250-252,277-280,305-309`). No default zero may be inserted into an unknown optional. Both earlier shared-null commit markers are evidence of prior effects; the helper must not increment either symbolic delta or demand an absolute delta of one, because independent frames can share the root.
- Keep the exact branch-specific refusal strings (`task_factory.cpp:227-228,253-254,281-282,310-311`) and the existing fallback stop (`:315-326`). The common qualifier should return failure to its caller; it should not introduce a generic error, mutate a marker, or authorize the next phase. Earlier QList, final private address-point, and QString admissions remain separate because their effect and refusal order differ (`:137-204`).

## Implementation hazards and required gates

The proposed `QualifiedZeroPrefix` is *read only*, but its strong references are not an immutable copy of the mutable root or frame. Use it only within the current branch, release it before the next phase branch, and do not cache it or treat it as permission for CP171. The retained private pointee is owned by the pending Report, not by the snapshot. The present code has no synchronization around these mutable objects; the extraction should not imply thread-safe admission. Verify that no new throwing operation is placed after qualification and before the one field write, and preserve the existing prelude's allocation-store errors instead of catching and replacing them.

Run a before/after static comparison of all common predicates and all four local predicates, messages, writes, and phases. A missed `addressPointWritten`, `taskAddressPointWritten`, binding commit marker, `qobjectBaseCompleted`, `complete`, or backlink term would broaden admission. A qualified clone of the private object must still fail through `allocatedPrivateIdentity`; an aliasing foreign root must still fail through `ownsWidgetRuntime` or binding pointer identity. Test refusal at **each** zero-field seam with no change to fields, phase, bindings, markers, identities, root deltas, counts, maps, or completion flags. Also retain first-call one-time effects, same/different-key reentry, independent-frame root deltas, and actual `ConversionSession` pairing. Then run focused factory/root-owner tests and the source-stable checkpoint, regression, and original-comparison gates before CP171 source work proceeds.
