# CP217 plain runner implementation checkpoint

## Scope

`admin/original_uninstrumented_directory_compare.mjs` is a new one-use runner for a sequential B98 control and exact two-operation negative-ID variant. The original-launch guard is the literal `false`; no original executable, project clone, or GUI was launched while preparing this runner. The existing owned-process helper and the existing source fixture were not changed.

The runner pins the original executable and helper SHA-256 values, rejects existing destinations and paths outside short `C:\PROBLEM` roots, copies the source independently, inventories full file/directory entries, verifies the required pre-existing project directories and absence of `Lubricants`, and independently parses each copied project with Python's standard XML parser. The variant mutation inserts only the two ASCII minus signs before operation IDs 1 and 2 and verifies reconstruction from the source bytes. Its operation structure check preserves `Name`, ordered IDs, `Type`, and order.

Each case computes the actual clone's four-hex-digits-per-UTF-16-code-unit `-f` argument and round-trips it. It starts only through `admin/owned_suspended_process.py`, requires the exact created suspended identity and one-count resume receipt, observes for up to five seconds, and retains raw helper stdout/stderr, parsed events, parse errors, per-clone before/after manifests, per-clone effect deltas, source-after manifest, executable/helper after hashes, and the raw Windows process-query response. FILETIME decimal text is preserved before JSON parsing. Cleanup requires the helper's verified exit, signaled wait, closed handles, zero helper exit, no cleanup error, and a successful zero-row Windows process query. Cases run sequentially; failure leaves the clone and receipts in place.

## Independent-review repairs

The initial review found the missing exclusive JSON writer, missing asynchronous child/stream error and early-close handling, incomplete manifest comparison, and ungated after-run hashes. These are repaired in the new runner revision. It now writes JSON receipts with exclusive creation; installs child and stream error plus close listeners immediately after spawn; drains and records JSONL in `finally`; treats an unobserved bounded close as unresolved cleanup; and stops before the next case on any incomplete result. It requires the explicit `terminate_command` endpoint after the full observation interval, the helper's `termination_requested` receipt, successful held-handle cleanup, and a zero-row process snapshot. A returned process row is conservatively treated as present; its image and creation date are retained as an unqualified PID snapshot.

The control must equal the source manifest and project bytes. The variant must have the same complete path/kind set and exactly one changed project entry whose bytes equal the constructed two-minus variant. Source is pinned to a 33-entry manifest SHA-256 and the known project SHA-256. Physical-path checks walk existing ancestors with `lstat`, reject symlink/reparse points, resolve existing paths, and check generated/copy paths for the 100-character limit. Source, executable, and helper hashes are checked before each launch and after each case; any drift blocks progression.
