# CP477 shared QTextStream Text-mode decision seam

The copied QtCore4_64.dll evidence in `cp476-qtcore-writer-review.md` binds `QTextStreamPrivate::flushWriteBuffer` at preferred VA `0x670C2F50` and the QIODevice Text-mode bit. On a nonempty, healthy device-backed flush, it queries Text mode. When enabled, it disables Text, replaces each buffered UTF-16 LF with CRLF, obtains/uses the locale codec, converts to bytes, clears the buffered QString, and calls QIODevice::write. A nonpositive write sets stream status 3 and leaves Text disabled without QFile flush. A positive write restores Text before conditional QFile flush; a short write or false QFile flush sets status 3. `endl` first appends LF and then attempts this flush. This is conditional static code behavior, not a particular runtime codec or filesystem result.

The shared `m2m::mst::Stream` now follows that decision order when its `OutputDevice` reports Text enabled. `OutputDevice` gained default-false Text query and default no-op setter hooks; existing binary FileDevice and other callers keep their prior behavior. The Stream still uses its supplied codepage as a host codec projection. It checks the original strict `>0x4000` threshold on pending UTF-16 length before newline expansion. Tests cover opt-in CRLF including an existing CR, 16,384 pending LFs followed by one character, disable/write/restore/flush order, nonpositive sticky failure with Text left off, positive short-write restoration and unchanged binary default. The new hooks represent device state in the shared seam; no native Qt object is attached.

Independent source review found and corrected two new test expectations before build: the threshold expected bytes initially omitted repeated LFs, and the disabled residual-state test initially used a positive short write.
