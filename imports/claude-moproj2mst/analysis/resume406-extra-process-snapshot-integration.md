# CP406 failure-only extra-process snapshot

CP405's exact CP331 inner outer-job PID list contained the runner, WORKER and one additional PID, but gave no executable name or parent. CP406 preserves the strict outer=2 rejection and enriches only that failure branch. The accepted path calls no Toolhelp API.

CP321 now declares the Win64 `PROCESSENTRY32W` layout and typed `CreateToolhelp32Snapshot`, `Process32FirstW` and `Process32NextW` system32 exports. CP332 creates one noninheritable `TH32CS_SNAPPROCESS` snapshot only after a complete exact-job PID list identifies one extra PID. It scans at most 1024 entries, selects only those three job-list PIDs, and records the extra PID's executable basename (24 printable characters maximum) and reported parent PID. It opens no process by PID. Missing, duplicated or raced entries become `unavailable` or `invalid`; the snapshot name and parent are diagnostic correlations, not creation-time proof or acceptance evidence. [Microsoft's Toolhelp snapshot contract](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-createtoolhelp32snapshot) describes the read-only process snapshot and required handle closure.

CP332 closes the snapshot immediately on ordinary and query-fault paths. A failed `CloseHandle` retains the exact handle for retry in `close()`. A raised `CloseHandle` outcome is marked uncertain and retained without blind retry, because it might have closed before the exception. All paths still raise the original strict accounting Hold before process waits and ACK. The CP333 trace marker remains bounded; a representative three-PID message is 90 characters before the existing 120-character message cap.
