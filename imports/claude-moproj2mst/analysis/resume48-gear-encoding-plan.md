# Checkpoint 48: Gear_blank encoding path and disposable probe plan

## Source fixture qualification

The retained source copy `evidence/gui_mo/s1/corpus/57_Gear_blank/Gear_blank.moproj` is a 12,326-byte XML project. Its `<Name>` elements (for example `Workpiece`, `Top Die`, `Bottom Die`) and the visible `Value` text are ASCII; the source file has no bytes >= 0x80. The Oracle-B Save case `109_B_FE7` has a separate captured `Gear_blank.moproj` (20,941 bytes), also with no bytes >= 0x80. Therefore neither file already contains a non-ASCII fixture name. The numeric anchor is available: the saved file includes floating tokens such as `<CenterX>719.409</CenterX>`, `<CenterY>126.955</CenterY>`, and view-vector values (`0.0813343`); the source project also has ASCII numeric-valued MDT/property fields. This is suitable as a disposable base, but not yet an encoding acceptance case.

## Current converter name and path serialization

- Project names and display names remain Unicode in the loaded model. On Save, `source/apps/moproj2mst/src/moproj/write.cpp` updates `<Title Name>` from `p.title`, serializes item names via `write_items.cpp` / `write_ops.cpp`, and converts the DOM with `xml::toString(doc, 1)`. The source comment identifies that as `QTextStream UTF-8`; the native writer uses `mst::Stream(65001, output)` and a `FileDevice` opened on the Unicode project path. The output bytes are UTF-8, not ACP. Thus a changed `<Title Name>` or `<Name>` field should be compared as UTF-8 XML bytes; a mismatch there alone does not prove the original ACP.
- The project file's path is passed to Qt/file APIs as a Unicode path (`p.path`, `FileDevice`); it does not take the narrow CRT path branch in this writer.
- Other Save side-files do have narrow-path consumers. The current source retains separate explicit-codepage conversions for local8Bit / `toAscii`-derived paths. The best specific contract is `analysis/wave3-native-simctrl-contract.json`: original SimCtrl.KEY wrapper at `0x0597d0` calls `QString::toLocal8Bit`, then `0x895920` opens with CRT `fopen("wt")`; successful open writes banner/group records. `analysis/wave3-ht-native-contract.json` independently binds HeatTreatWizard.HTWZ to local8Bit followed by CRT open at `0x1411b3d87..0x1411b3dbd`. The Cogging writer has a distinct `toAscii` path contract (`analysis/wave3-cogging-native-io-contract.json`). Do not apply the local8Bit profile to XML output or `toAscii` consumers.

## Exact PE point that needs original ACP observation

The relevant Qt implementation chain is `QString::toLocal8Bit` at QtCore VA `0x6706e4b0` -> `QTextCodec::fromUnicode` at `0x6714ad30` -> observed `QWindowsLocalCodec` virtual `fromUnicode` at `0x6714abb0` -> imported `WideCharToMultiByte` at QtCore IAT `0x671a8330`, called with `CP_ACP` (0), flags 0. This chain is retained in `analysis/wave3-editor-observed-language-binding.json`. Qt startup at original executable VA `0x1400024f0` selects explicit codecs only for language values 1/2/3/4/7 (Shift-JIS, Big5, KOI8-R, EUC-KR, GBK); default startup leaves the codec unset for Qt's system locale behavior (`analysis/wave3-editor-translator-codec-observation-contract.json`). `analysis/wave3-original-manifest-codepage-qualification.json` found no embedded or adjacent `activeCodePage` override, but that does not supply the numeric process ACP. An original-process `GetACP()` observation is still required before claiming which bytes the `CP_ACP` call produces. It must be recorded after the startup codec selection point and at a stage where the locale codec is initialized; raw null codec storage can be lazy.

## Minimal disposable fixture mutation (proposal only)

Copy the whole `57_Gear_blank` project tree to a short path under the converter `build/` scratch namespace. Keep the evidence copy immutable. In the copied `.moproj` only, change one simple, round-tripped name such as the first top-level `<Name>Workpiece</Name>` to `Café-中 Workpiece`. Preserve every other byte/value in the input, especially numeric fields. Use a disposable project folder whose basename also contains the accented `é` (for example `build/format_probe/Café/`), while keeping the eventual full absolute path under the local project path limit. The Unicode project file itself is opened through a wide/Qt path; the changed folder name exercises any downstream side-file branch that converts project-derived paths to local8Bit. Before executing that scenario, statically verify which generated path actually reaches SimCtrl.KEY or HTWZ so the mutation does not accidentally claim an unrelated path branch.

For a converter-only byte check, save the copied project to a second file and compare raw output: full-file SHA-256/length, byte offset and hex window for the changed `<Name>`, and exact numeric tokens for `CenterX`, `CenterY`, and the view-vector values. The name is expected to serialize as UTF-8 under the current project writer; record this as implementation behavior, not original ACP parity. For the narrow side-file probe, record the exact attempted filename/path bytes and resulting SimCtrl.KEY or HTWZ bytes separately. Never normalize XML line endings, numeric spelling, or path bytes before preserving the raw comparison.

This plan proposes a mutation only inside a disposable future `build/` copy. No evidence fixture, source, build output, app session, or REA database was changed for this audit.

## Acceptance boundary

The proposed name/path mutation is useful only if the same output path is reached by both implementations. Original validation must record target-process `GetACP()` and ensure it is after startup codec selection; for the narrow path branch, compare the original emitted filename bytes and side-file bytes to the candidate using the observed ACP profile. Keep the UTF-8 `.moproj` field comparison separate. The existing numeric values do not distinguish C-locale from comma-decimal output by themselves; use a numeric test value only if an existing reached Save field demonstrably passes through CRT numeric formatting. Otherwise rely on the source-qualified Qt `QTextStream` C-locale contract for its own output closure and leave CRT numeric locale open.
