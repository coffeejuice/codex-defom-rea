# Resume 202 uninstrumented baseline

## Proposed single attempt

The comparison is a no-Frida, no-GUI-input startup of the same original GUI executable and same B98 disposable project used by the passive trial: `C:\Program Files\SFTC\DEFORM\v11.0.2\DEF_GUI_MO_64.exe`, SHA-256 `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`; cwd `C:\PROBLEM\p202a`; arguments `-m open -f C:\PROBLEM\p202a\Gear_blank.moproj`. The retained `disposable-before.json` identifies the exact 27-file B98 disposable, and `source-before.json` binds its source tree. The GUI receives no stdin or GUI actions. The helper resumes the primary thread and allows a five-second observation window for natural startup behavior, then sends the helper's exact owned-process termination command if the target has not exited. Its independent watchdog remains capped at 20 seconds.

The runner is `admin/original_uninstrumented_baseline.mjs`. Its `RUN_UNINSTRUMENTED_BASELINE` constant is `false`, so direct invocation exits before fixture access or process creation. An authorized operator would need to enable the guard explicitly after the helper is released. The script records strict before/after hashes for all files and directory names in both the source and disposable trees, executable/helper hashes, JSONL helper receipts, exact process identity, and an independent Windows process-absence check. It refuses a fixture mismatch, executable mismatch, helper hash mismatch, unexpected symlink/reparse entry, or nonzero file-count change. It creates a unique evidence directory under the converter’s analysis folder.

The helper protocol is the pinned `admin/owned_suspended_process.py` (SHA-256 `8f770388862580700063254663ac029eaf45ee269a3528aec3e61f946c32411d`). It creates suspended and retains the process handle, reports PID plus exact creation FILETIME, canonical image, cwd, launcher PID, and image SHA-256. The script requires `state: suspended` and `exit_verified: false`, and validates that identity receipt against its own launcher and intended image/cwd before sending exactly one JSONL `resume` command. It also pins hashes and expected roots for both retained source and disposable manifests. If the target remains alive after five seconds, it sends the helper's `terminate` command; EOF also causes held-handle cleanup. The script requires a successful helper exit and a cleanup receipt with verified exit and closed handles, then makes a strict PowerShell CIM query. Explicit successful zero-row results establish absence. Any row for the exact PID counts as present, and missing/malformed rows or query errors mean unknown; CIM creation-time precision is not used to infer PID reuse. Raw helper stdout/stderr, parsed receipts, parse errors, and after-state are retained even on failure. It never attaches to an existing process and never uses process-name-wide termination.

## Interpretation

A natural exit or survival through the five-second observation window can be compared with the instrumented startup’s checkpoints; the 20-second bound is a safety watchdog, not the planned observation duration. A baseline that survives the five-second window while the instrumented run fails makes instrumentation interference more plausible, but one run does not establish causation. A comparable spontaneous failure supports a natural startup issue. Fixture changes, mismatched identity, helper cleanup errors, failed process-absence checks, or missing evidence make the result inconclusive.
