# CP116 DOE Geometry reader and payload boundary

## Result

The retained Geometry reader establishes a precise in-memory order but does not establish a geometry-payload import. On a direct `Geometry` child, it first constructs `QFileInfo` from the actual InputTable filename QString and asks for `QFileInfo::path()`. It then retrieves and converts `GeoOperation` (base 10, null `ok` pointer), reads the remaining Geometry attributes and file-name values, inserts or finds the keyed Geometry row, writes its tail flags and variable MorphMethod, and only then traverses Upper/Lower correspondence children. Each PointPair is split and its four tokens are converted to doubles before the corresponding in-memory receiver append. The bounded reader contains no identified `QFile`/`QIODevice` open/read of the stored `.GEO` paths.

The path-value and receiver-prefix helpers now cover conditional values and in-memory row/pair effects, but the public Geometry gate still cannot be released. QFileInfo construction has engine/handler/ref/cache effects outside the path-value helper; the default-locale result/provider used by every `QString::toDouble` is process state; and the later payload consumer is not identified. The native method order is closed statically; the successful native constructor/conversion/payload occurrence is not.

## Reader order and evidence

The source-bound original GUI PE is `analysis/resume48-distortion-vt198-rea-session/DEF_GUI_MO_64.exe`, SHA-256 `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`. Reader disassembly is retained in `analysis/resume50-doe-variable-body-pe-annotated.asm` and bound by the existing CP50 receipt.

1. Tag dispatch recognizes `Geometry` at `0x1409114f8..0x140911532`. The reader loads the actual source filename from its argument at `0x140911532`, invokes the imported `QFileInfo(QString const&)` constructor at `0x140911542`, then calls imported `QFileInfo::path()` at `0x140911559`. This precedes even the `GeoOperation` attribute lookup at `0x140911560`.
2. `GeoOperation` is retrieved by `QDomElement::attribute` (`0x1409115bc`) and converted by `QString::toInt(ok=null, base=10)` (`0x1409115da..0x1409115ea`). Later numeric attributes and file-name attributes are read before the row receiver call. The qualified path projection report `analysis/resume113-doe-geometry-path-projection.md` binds the literal parent/attribute join and its conditional normal-return domain; it explicitly does not bind a native QFileInfo completion or public parser admission.
3. The reader sends the three joined path values, operation/object keys and selected Var to `0x1408175c0` at `0x140911f68..0x140911f99`. CP114 evidence closes that routine's key lookup/append behavior, tail flag order and variable MorphMethod write.
4. The child loop begins at `0x14091201c`. UpperCorrespondence text is split on literal `", "`, KeepEmptyParts, case-sensitive at `0x14091219a..0x1409121cc`; token access occurs at indices 0,1,2,3 and four calls to `QString::toDouble(ok=null)` occur at `0x1409121f5`, `0x14091221b`, `0x140912241`, and `0x140912267`. Two QPointF constructors consume `(0,1)` then `(2,3)` at `0x140912290` and `0x1409122b0`; receiver append call is `0x1409122fe`. Lower correspondence repeats the sequence at `0x1409124e8..0x14091264c` and calls `0x140818080`. Both receiver calls pass row index zero.
5. `analysis/resume114-qt-default-locale-trace.md` binds the retained QtCore `QString::toDouble` implementation: it constructs a default QLocale, queries a QSystemLocale-backed process profile and attempts that parse first; only on failure does it try the explicit C locale. The parser caller passes null for `ok`, and the actual selected default-provider/table profile is not bound for a fresh application process. The evidence therefore closes provider **order**, not the numeric value/result for all original runs or inputs.
6. The reader exits by advancing DOM siblings and destroying local QDom/QString/QFileInfo wrappers (`0x1409126f9..0x1409127b2`); normal return is at `0x140912a0e..0x140912a10`. In the bounded function body there is no identified QFile/QIODevice open/read using the recorded paths. `analysis/resume106-geometry-first-file-effect.md` and `analysis/resume107-geometry-receiver-owner.md` document the same negative boundary and the unresolved external receiver owner.

## File/payload boundary

`QFileInfo` construction and `path()` do not show that the corresponding geometry payload was opened. Constructor/handler/file-engine work can still occur: CP113's retained QtCore trace shows the constructor resolving an engine/handler and updating the entry before the normal getter path. The reader capture has the constructor at `0x140911542`, path getter at `0x140911559`, local QFileInfo destructor at `0x1409127ac`, and no identified QFile/QIODevice open/read of the geometry payload in the function body. The native function's named branches store filename values and mutate correspondence records. This is a negative conclusion scoped to the retained reader body `[0x14090ef70,0x140912a10)`; another caller, downstream consumer or virtual receiver path may open the files.

The exact missing edge is a static caller/consumer path from the recorded Var+0x28 Geometry row or its +0x00/+0x08/+0x10 path fields to the first payload-file open/read, together with a concrete receiver/owner binding. Do not invent a file read at the QFileInfo constructor, or infer that the file is consumed merely because paths and correspondence pairs are stored.

## Smallest source-closed next slice

There is no additional source-closed public Geometry admission/payload slice in this evidence set. CP113 path projection is conditional on a bounded named absolute filename and normal native QFileInfo construction; CP114 row-prefix mutation and CP115 pair append are isolated already-converted receiver effects. Widening the public guard would now compose those helpers while skipping (a) constructor/handler/ref effects, (b) `GeoOperation` conversion order/value as part of the real reader entry, (c) original default QSystemLocale numeric result, and (d) the later `.GEO` payload consumer.

The next implementable work is therefore evidence acquisition, not another parser helper: bind one concrete call chain that supplies the reader's source filename and receiver, then statically trace a consumer of the stored geometry-path fields to its first QFile/QIODevice open/read. If no complete static path binds that consumer, the remaining smallest decisive action is a permitted fresh-original observation of that one admitted Geometry case, capturing the selected locale/provider result and first payload open, while retaining the current public refusal until that evidence is available.
