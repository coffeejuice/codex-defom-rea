# CP209: one-run producer-zero branch observation plan

The next observation should identify which return becomes zero inside the same faulting `1d510` occurrence. Select an owned Windows debug-event observer with four hardware execution-breakpoint slots and one staged slot. This avoids adding an inline hook to the shared runtime cast helper and reads the actual consumed `C`, `D`, and final result. It is a proposed successor, not an implemented or released runner. No original process, GUI control, converter code, shared state, or external fixture was changed for this report.

## Evidence and decision

The original is `DEF_GUI_MO_64.exe` from the v11.0.2 installation, SHA-256 `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`; the installation version is not a PE version-resource reading. CP207's successful `analysis/resume207-original-function-owner-2026-10-26T11-51-11-398Z/summary.json` records `CAPTURE_COMPLETE`, qualified hook/core evidence, CP205 fault parity, a unique exact-caller same-creation/thread/invocation pair, natural-exit cleanup, process absence, and unchanged fixture digest. Invocation 2 returned producer zero before the QtCore fault. Its earlier invocation 1 also returned zero; occurrence order alone therefore cannot select the faulting occurrence.

`resume209-zero-branch-static.md` and the retained `1d510`, `45780`, and `44a90` assembly establish three outcomes: current getter `C=0`; current `C!=0` but model cast `D=0`; or `C,D!=0` with Project accessor result zero. The third is a downstream-accessor route, not automatically proof of allocator failure. A failed manager downcast does not itself cleanly explain a normally returning producer because the current getter dereferences that manager.

| Method | Evidence and perturbation cost | Decision |
|---|---|---|
| Extend successful Frida function hooks | Keep `eaf60`/`1d510`; add current-getter and Project-accessor entry/leave hooks and a direct second-cast observation. Direct cast-result capture would normally add an entry/leave hook to the shared CRT cast entry/thunk, with caller filtering after instrumentation. This expands relocation and callback surface into shared code; prefix/target/patch-width review is still absent. | Viable alternative, but CP207 parity applies only to its two sites. Do not treat that success as approval for five sites. |
| Infer cast zero from `C!=0`, producer zero, and no selected accessor callback | Can use two additional function hooks if complete delivery and exact nesting are established. It relies on a negative observation rather than retaining actual `D`; unrelated/missing/ambiguous callbacks weaken the conclusion. | Smaller implementation than a debugger, but weaker direct discriminator. Do not call a missing event a witnessed cast return. |
| Owned debug-event hardware execution breakpoints | No inline relocation or broad cast-function hook. Four per-thread slots suffice by changing only one stage slot. Requires a correct new debug-event state machine, exact x64 contexts, resume semantics and cleanup review. Stops perturb scheduling and may change the fault. | Preferred direct-evidence plan for one original run, after harmless fixture and independent release review. |

CP207's fallback recommendation favored Frida for the earlier two-value question. That run has now succeeded; this new question needs internal branch returns, so its earlier implementation-cost comparison does not settle the choice. No measured speed or token advantage is claimed here. A one-run design means one owned-original trial after preparation, not repeated automatic variants until one agrees.

## Four slots and exact observations

All sites are app RVAs relative to the newly verified module base. Initial per-thread layout: slot 0 `eaf60`; slot 1 `1d510`; slot 2 `eb000`; slot 3 `45793`. No software breakpoint, instruction patch, data watchpoint, target-side injected API, ordinary-instruction single stepping, or target data write is needed. Debug-register changes and any required processor resume-flag handling are instrumentation writes and must be explicit in the implementation review.

| Site | Required raw capture and filter | Next stage |
|---|---|---|
| `eaf60` before prologue | `RCX=O`, entry `RSP=S`, `[S]=base+eaa7a`, identity and owner occurrence ID. Reject other callers. | Retain frame record, without assuming an unobserved owner return. |
| `1d510` before prologue | `RCX=input`, `RSP=E`, `[E]=base+eb000`; require exactly one owner record with `E=S-170h`, matching live stack return and same thread. Assign nested producer occurrence ID. | Save prior slot-3 state for nesting; arm selected occurrence's `45793`. |
| `45793` before `mov [rsp+30h],rax` | Actual `RAX=C`; require `RSP=E-78h`, `[RSP+48h]=base+1d52b`. Guard-read `[RSP+50h]=M` as manager identity. | `C=0`: arm `457e1`. `C!=0`: arm `457c6`. |
| `457c6` before `mov [rsp+38h],rax` | Actual `RAX=D`, same `RSP` and outer return; compare guarded `[RSP+30h]` with retained `C`. | Arm `457e1` in either case. |
| `457e1` before epilogue | `RAX=P45780`, same frame and outer return. If retained `C,D` are nonzero, guard-read `[RSP+38h]=D`; this is the actual continuation after `44a90`. | Mark branch occurrence complete; disable its stage slot until producer return, or restore enclosing stage as appropriate. |
| `eb000` before `mov r11,rax` | Actual `RAX=Pproducer`; require `RSP=E+8`, matching owner frame and selected producer. Guard-read `[O+30h]=H` and `[H+38h]` as pre-store diagnostics. | Pair complete branch and producer records; restore saved enclosing slot-3 state or initial stage state. |

The stack offsets follow the retained prologues: `1d510` subtracts `28h`, then calls `45780`, whose entry subtracts `48h`. `45780` entry RSP is `E-30h`; its body RSP is `E-78h`. These constants must be independently checked in fixture tests against the exact byte spans before release. Do not apply them to exception frames or another caller.

**`457e1` is a shared merge, not an exclusive accessor-return witness.** Both early zero arms jump there. Only a preceding same-frame `C!=0,D!=0` establishes that its `RAX` came from `44a90`. For `C=0`, the local for `D` is uninitialized on this route; do not report its stale contents. Do not read freed callee locals in Frida `onLeave` as a substitute for these stopped instruction coordinates.

The three accepted classifications are: `C=0,P45780=Pproducer=0`; `C!=0,D=0,P45780=Pproducer=0`; and `C!=0,D!=0,P45780=Pproducer=0`. Require all reached stages and a final same-occurrence producer return. A nonzero producer, missing stage, inconsistent locals/results, unrecognized entry, or lost event is an explicit other/inconclusive result. Getter-null does not distinguish absent selection from membership rejection. Accessor-null does not distinguish allocation-null, constructor result, or mutation. Those subcauses are outside this minimum capture; `44acd` allocator return would be a separately reviewed extension, not a fifth simultaneous breakpoint quietly added here.

## Correlation and bounded control

Use `(creation FILETIME text, PID, TID generation, owner occurrence ID, nested producer occurrence ID, S, E)` plus global sequence and per-thread stage. Preserve exact incoming callers, raw registers, memory-read success/failure, rejected-hit counters, overflow, thread create/exit and module-load coverage. Pointer values alone, the second occurrence, or process-global event order are insufficient. Bound owner history and invalidate on unproved stack/frame reuse; no stale owner frame counts as active solely because no return was observed. At the AV, use qualified x64 unwind evidence to bind the live owner frame and selected producer history.

Each created thread gets the initial four-slot layout before its create-thread event is continued. Only that event thread's staged slot changes. Maintain a per-thread nested state stack; a nested selected producer saves/restores its enclosing stage. Other `45780` calls or `eb000` hits must satisfy frame and caller checks before advancing state. If recursion, stack reuse, exceptions escaping a pending producer, or a slot restoration cannot be resolved exactly, invalidate that occurrence rather than guessing. Do not replace another debugger's nonzero debug-register ownership; the child must be fresh and exclusively owned. No process-wide assumption that hardware registers automatically cover later threads is permitted.

Before original release, fixture-test the actual observer state machine using a harmless owned x64 child and synthetic event tests: all three paths, common-merge semantics, earlier nonfaulting zero, unrelated callers, nested producers, cross-thread events and TID reuse, failing reads/contexts, unexpected single-step, debug-register readback failure, overflow, first-AV-before-completion, and cleanup with an outstanding event. Demonstrate execution-breakpoint restart without looping and without changing ordinary flags/results. Handling DR6/status, DR7 local execution encodings, and any RF preservation/restoration must be independently reviewed; merely receiving `EXCEPTION_SINGLE_STEP` is not sufficient to claim an owned observation breakpoint.

Proposed finite limits are 16 owner/producer occurrences per thread, nesting depth 4, 128 accepted scalar branch records, 4,096 total debug events, and a 30-second original observation deadline. Keep aggregate rejection counts even when samples are capped. These are release-review inputs, not pre-existing validated limits; hitting any limit invalidates completeness. Do not loosen limits or retry the original automatically during the trial.

## Release, parity, stop and cleanup gates

Keep an explicit original-run guard false until an independent review binds the observer/helper hashes, harmless fixture receipt, command/cwd, original/module hashes and byte spans, x64 context layout, finite limits and cleanup policy. Use one fresh `CreateProcessW` child with `DEBUG_ONLY_THIS_PROCESS`, not attachment to a user process or descendant-debugging mode. Reuse CP207's verified command and copied fixture identity: cwd `C:\PROBLEM\p202a`, project `Gear_blank.moproj`, fixture digest `55e2a58cf8155995f942f89ac0ebb91454308b521ae76a228edec0ffdc4cedbd`. Verify these again before launching; historical agreement is not a current preflight. Abort held-child setup on any identity, byte, coverage, handle or context mismatch. No GUI-control session is acquired.

The creating debugger thread owns the finite event loop. Microsoft documents that a debug event suspends target threads and continuation resumes execution; context mutation must occur while stopped. Record/read back only owned hardware state changes, preserve ordinary integer/control state, and explicitly distinguish loader breakpoint, owned execution-breakpoint event and unrelated exceptions. [Debugger loop](https://learn.microsoft.com/en-us/windows/win32/debug/writing-the-debugger-s-main-loop), [SetThreadContext](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setthreadcontext).

At the first application AV, persist compact core before enrichment: first-chance flag, exception code, RIP/module/RVA, read/write/execute and address, RCX, thread/creation identity, stage/counter snapshot and selected frame IDs. Preserve an independently qualified stack through `a7510 -> eb1ec -> eaa7a`. CP205 parity requires QtCore4_64.dll RVA `32c0`, read `58`, `RCX=58`, and that app chain. Any divergent first AV ends causal interpretation, even with seemingly useful branch records. Unknown ordinary exceptions follow normal delivery; only verified owned observation events are handled. Pass the original AV with `DBG_EXCEPTION_NOT_HANDLED`; never suppress or repair it. [ContinueDebugEvent](https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-continuedebugevent).

After recording the first AV, stop branch collection, clear owned breakpoints at the stopped event, and continue natural exception delivery/exit while preserving the event loop. Continue every delivered event, including exit events; close load-event file handles and owned handles according to their ownership, with no double close. Make debugger kill-on-exit policy explicit and tested. An error/deadline must resolve the pending event and record whether exact-child termination was required; such termination cannot count as natural capture completion. Retain pre-resume abort versus post-resume failure separately. Independently verify process creation identity/absence, no owned debugger session left attached, unchanged fixture manifest, and retained raw event receipts. Debugger detach is debugger cleanup; it is not a GUI-control-release claim.

This plan supports preparation and review. It does not establish the original branch, prove instrumentation neutrality, or justify a converter behavioral change before a qualified one-run receipt exists.
