# CP116: ordered two-row Spring page/list and writer

Extended the internal Extra3DIo page projection from its existing exact one-row profile to the agreed exact two-row profile. Row0 stays selected; only its visible values undergo the Save-time display parse/writeback, while row1 remains an ordered item-payload copy. Public full Session mode300/palette gates are unchanged. This is source-backed candidate implementation, not an observed original same-run result.

## Exact admitted records and changes

The two rows are consistently:

- row0 `{10,0.5,1.5,20,[0,1,0],flag0}`;
- row1 `{30,2.5,3.5,40,[1,0,1],flag0}`.

`src/engine/simcontrol300_io.cpp` retains the old exact-row0 predicate and adds an ordered vector profile: either that one row, or that row followed by the exact row1 above. Fill requires every row's first/second IDs in the corresponding explicitly qualified combo spans. It preserves the deferred scalar-read/combo callback placement and selects row0/its numbers only. Missing combo IDs, other values/order/count/flags, edits and row reselection remain refused.

Apply retains the existing no-edit/currentRow0 preflight. It copies the admitted item vector, writes the selected row0's IDs and parsed visible numbers into its local payload, and leaves all later payloads unchanged before serialization. The native list writer now derives the count from the bounded vector and emits every row in order. A literal LF follows count and each row's first object, direction0 and direction2; TAB follows every non-LF element, then finalCRLF. Thus two rows produce seven literal LFs plus finalCRLF. All-zero flags still trigger readable-open/delete SPRING2 after the primary attempt, even if that write returns false. The one-row list/order/bytes and ignored-failure behavior are preserved.

The unchanged shared SpringSelectionState vector already carries this state, so no header was edited. Root owns any explanatory header update. Allocation failure, native widget construction, row-change events, user edits, arbitrary multirow data and original combo-population occurrence are outside this slice.

1. Native read/page Fill with first IDs `{0,10,30}`, second IDs `{0,20,40}`; verify ordered records, selected row0/visible first-row numbers, exact bytes, unchanged page row1, absent companion; reread both normalized records in order and require idempotent second Save.
2. Open with absent companion, then create a late readable companion and hold the primary for read with read-only sharing. A forwarding IO spy records actual primary write attempt/openedfalse before SPRING2 deletion. Apply still completes, the exact pre-truncation primary input survives and the companion is removed.
