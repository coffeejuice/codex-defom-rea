## Highest-impact remaining fidelity gap

CP111's candidate terminal path still substitutes a fixed worker endpoint for the original runtime's invalid-parameter prelude. `src/cli/isolated_save_worker.cpp:68-90` selects `FreshDefault` under the explicitly documented static assumption, publishes Boundary after validating the leaf request, and calls `TerminateProcess` directly. The terminal receipt labels `StaticFreshDefaultAssumption`, `CaptureContextUnimplemented`, and `native_execution_observed:false` (`src/cli/isolated_save_job.cpp:259-275`). CP109 static evidence establishes the original executable's startup encoded-null assignment and predicts the null-FILE dispatch / default-handler termination only if the same module slot remains unreplaced. It also establishes the native context-capture, function-table/unwind, debugger/filter and termination sequence. It does not show that a fresh original process with the constructed B133 overlay actually reaches that occurrence. The accepted CP111 raw manifests and process status are candidate evidence, not that missing original witness.

This is the largest remaining terminal-fidelity uncertainty because it is the condition that separates matching an OS exit code from reproducing the original handler path. Adding more candidate assertions or copying the `0xC0000417` value cannot close it. The normal `Returned` receipt remains intentionally deferred (CP111 test expects no receipt for normal return); that is an auditability/product-contract omission, but lower priority than establishing whether the original path occurs at all.
