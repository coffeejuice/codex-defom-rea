# CP284 source-stable integration and successor

CP284 adds one native fixed-harmless failure case: after the first CREATE_PROCESS image gate and successful DR0 write/readback, it raises a fixed error before attempting continuation. The raw injection snapshot retains sequence 1/code 3, owned PID/TID, original `0x10002` disposition and `continuationAttempted=false`. Worker cleanup then terminates the owned child, continues that held event once, drains `[3,6,5]`, closes logical handle generations, and records no cleanup errors. The independent supervisor verifies child and worker exits. This does not simulate a ContinueDebugEvent API failure.

Native no-ack remains a separate failure case. Its child identity is independently duplicated and both exits are verified; acknowledgement is false and no ResumeThread is issued. There is no completed worker result, so worker-local cleanup is not claimed. Silence before an event-held IPC record does not prove no pending event. The full retained normal, pre-arm refusal, held-entry, post-arm refusal and no-ack receipts are bound by `analysis/cp284-create-event-validation.json` to final source hashes and sizes.

Root final-source tests passed 10/10 probe in 7.164 seconds, 6/6 supervisor in 12.295 seconds and 12/12 observer in 2.325 seconds. Independent source and final receipt review passed for this benign scope. CP283 frozen raw receipts were not overwritten. The converter C++ source and m2m ABI were unchanged; CP274 remains the last full C++ candidate with 369 registered tests (362 clean, six logged gaps, one diagnostic difference; historical 93 SAME/five DIFF). An admin-only failure injection does not justify a full C++ rebuild or lifecycle acceptance claim.

Independent read-only PE parsing of the copied original bound the selected direct CALL, helper RVA/full 31-byte prologue and `.pdata` unwind range; see `analysis/resume284-original-color-entry-pe-binding.md`. Retained Boolean evidence still lacks a same-invocation constructor E to first-Open Apply/add witness. No original application, GUI control, Frida or mutable REA analysis ran. The literal original refusal and GUI release/status gate remain in force.

CP285's selected successor is a separately reviewed **disabled** original-image binding using the immutable PE identity and RVA/call/prologue checks, without launching the original. It must keep fixture export/object-prefix predicates separate and maintain the unconditional original refusal. Further harmless failure/neutrality gates remain queued. All 15 converter workstreams and eight acceptance gates remain open, so CP284 is a checkpoint rather than completion.
