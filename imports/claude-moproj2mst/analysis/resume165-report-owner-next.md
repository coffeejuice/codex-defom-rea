# CP165 Report Open owner and SessionRoot lifetime boundary

## Decision

There is no new source-ready **actual Report document owner** or Close/SessionRoot continuation. The original has a concrete lazy `SubProject S + 0x30` producer, and one Report Open invocation passes its returned document `D` through reset, `.DS` read, and traversal. The converter still has only a diagnostic slot observation, not the main-window-parented `SfSessionManager` or its current payload and lifetime. Keep public Report Open, Save, and Close continuation guarded. The already implemented pure `.DS` path helper is the only source-ready prefix; adding another detached slot or a `SessionRoot` XML node would not bind the native owner.

This is a read-only static finding for original `DEF_GUI_MO_64.exe` **v11.0.2**, SHA-256 `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`. The VA base is `0x140000000`; RVAs below subtract that base. No reconstructed executable version, fresh original occurrence, Qt result, or new REA Evidence ID is claimed. No source, tests, shared plan/state, build, GUI/app control, original execution, live REA, or deployment was changed or run.

## Bounded Open chain and the precise owner relation

The path-before-lookup order corrects the older CP52 statement that first-use document ownership precedes path calculation. It does precede the document reset/read, but the path's Qt string work has already run. The earlier Report `0x1412add20` check, `0x1412ae070` Project read, and `0x1412b0f70` active-S lookup are separate current reads. Even with one stable receiver, callback-sensitive operations can change their values. The static chain does establish that **if** the fresh lazy accessor returns a live object, the constructor return was stored into that selected `S+0x30` before the Open caller's first reset call. It does not prove that the QObject parent accepted the proposed main window, that all intervening calls returned normally, or that Save later selected the same S/D.

## SessionRoot and Close require this same D

The retained `0x140645320` (`0x00645320`) null-slot path constructs `SfInteractivePost` from current `D+0x48`, stores it at `D+0x30`, calls `0x1406453c0`, and rereads the slot. The latter asks `0x14065b470` to create a `SessionRoot` element and invokes QtXml `appendChild` on a copy of current `D+0x58`. Publication precedes the append attempt. Neither the append return nor successful XML mutation is established by the selected PE path. `0x140646370` is a separate possible `D+0x30` replacement. Report Save's default fresh `D+0x68=1` routes `0x14064a830` to `0x14064ab80`; its alternative `D+0x68!=1` path can call the lazy accessor. The later direct Save lazy call requires current `D+0x2a!=0`, while the Report constructor receives zero. Intervening writers, indirect callbacks, and actual branch values remain open.

The accepted Close chain already reaches `0x1400b5bb0(S)` (`0x000b5bb0`), which reads `S+0x30` twice, conditionally dispatches the second current document's deleting virtual `+0x18`, then clears the guard. For a still-live D retaining its constructor table, that virtual is `0x14064f060` (`0x0064f060`) and its ordinary destructor visits current `D+0x20` model, `D+0x30` interactive payload, `D+0x40` parts, `D+0x48` DOM owner, and QObject base destruction. A preceding QObject-parent child deletion could instead invalidate `S+0x30`. The static Open producer and Close deletion chain cannot select the actual first or second Close guard value, or prove which owner destroys D first.

## Smallest missing occurrence and implementation guard

The next evidence needed for **actual** ownership is one original Report Open→Save→accepted-Close occurrence with generation-specific identities, after the parent repository's supported GUI-control release gate permits it. At Open, bind receiver, current `P`, fresh active `S`, `S+0x30` before/after the lazy accessor, allocation and constructor return `D`, proposed main `M`, accepted QObject parent `H`, child-list delta, connection registrations, and both accessor slot reads. Retain reset/read/traversal returns, current `D+0x20/+0x30/+0x40/+0x48/+0x58/+0x68/+0x2a`, and any rebind or death. At Save, bind its **fresh** S/D lookup, `0x14064a830` branch and callback returns, and any `0x140645320`/`0x140646370` call including `SessionRoot` create/append result. At Close, bind actual admission, manager/Project/S again, both `S+0x30` reads at `0x1400b5bc2` and `0x1400b5bd5`, D's current table/payload, and parent child-deletion order. If the first Close read is null, identify the earlier destruction/invalidation rather than assigning a synthetic null default.

For another immutable-only pass, inspect the **complete** `0x14064ab80..0x14064b14f` default Save branch and any Report-specific intervening `D+0x68` writers, then the exact indirect callback receivers. A direct-call scan cannot certify absence. Static closure may narrow which calls can create `D+0x30`; it cannot supply the current P/S/D/H values or Qt append outcome. Source work should begin only with a root-owned parented QObject/document producer and the per-SUB live slot, then preserve fresh rereads and release ordering. Tests should cover same-S publication/reuse, changed active S or guard between Open and Save, failed allocation/parent acceptance, reset/read failure with D still published, actual DOM/SessionRoot append result, and null versus nonnull Close double-read. Diagnostic `KnownNull`/`KnownNonNull` token tests and DOE `SessionRoot` fixtures are separate contracts, not public Report acceptance.
