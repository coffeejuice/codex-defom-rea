# CP167 connector independent source and test review

## Decision

**Block acceptance.** The production source represents the selected `[0x1311b5, 0x1311bb)` write faithfully, but the checked-in tests assume a first call stops at `0x1311b5`. `initializeNativePrefix()` proceeds directly from CP166 to CP167 in that same call and stops at `0x1311bb`. The focused tests and predecessor tests therefore assert an unreachable first-call boundary. This is a source-flow finding; this review did not run a build or tests.

## Source assessment

The retained disassembly at `analysis/resume163-connector-qobject-67131160.asm:32-34` shows `xor edi,edi`, the qword store to `[rbx+40h]`, and then the separate `[rbx+48h]` store. The inspected source places `std::optional<std::uint64_t> private40` in `PendingTaskPrototype::SparseQObjectPrivate`, initially disengaged (`doe_task_runtime.hpp:26-36`). The pending Report retains this private object. `task_factory.cpp:201-225` admits only `BeforePrivateZeroFields`, checks the associated live root by exact pointee through `ownsWidgetRuntime`, the retained Report/private identity, allocation sizes/address points, committed QList and QString markers, exact qualified root bindings, absent `private40`, and incomplete QObject/backlinks. It then sets only `private40 = 0` and advances to `BeforePrivateZero48`. The final guard at lines 227-232 refuses before the `+0x48` instruction. There is no model observation for `+0x48`, `+0x50`, or `+0x58`, and no new container, TaskInfo, task, backlink, counter, or cache effect. The prior symbolic deltas are not recommitted on CP167 entry or reentry.

`TaskAllocationStore::ownsWidgetRuntime` compares both shared ownership and `.get()` (`task_runtime.cpp:30-37`), so an aliasing `shared_ptr` with a foreign pointee cannot satisfy the associated-root check. The two retained bindings are compared with the two symbol objects from that same root. Marker validation is the per-frame record of the already committed increments; root deltas may be shared with other frames, so their absolute value is not a per-frame admission criterion.

## Acceptance blockers

1. **First-call checkpoint mismatch.** The CP166 block at `task_factory.cpp:166-199` changes the phase to `BeforePrivateZeroFields`, then the next `if` at lines 201-225 immediately writes `private40` and changes phase to `BeforePrivateZero48`; the throw mentions `RVA 0x1311bb`. In `test_doe_task_factory.cpp`, first-call expectations of `RVA 0x1311b5` remain at lines 307, 349, 368, 404, 429, 461, 490, 532, 554, and 655-656, with corresponding expected `BeforePrivateZeroFields` states. The new positive CP167 case at lines 368-378 cannot observe its claimed initially unknown field after that first call. Its second call is already a reentry at `0x1311bb`, not the one-time write under test. The alias case at lines 404-415 likewise mutates the binding only after the write and cannot exercise the CP167 root guard. Update the checkpoint/test seam consistently, then run the focused tests.
2. **CP167 refusal matrix is incomplete.** The plan requires pre-write refusals for missing/expired/foreign or mismatched roots, an uncommitted CP166 marker, wrong address point, and a prematurely observed `+0x40`, with phase, binding, delta, and field invariance after each refusal. The new CP167 tests at lines 362-419 cover only a positive/reentry sequence and one QList alias injection, and that injection currently occurs after CP167. Existing CP165/CP166 corruption tests exercise earlier guards, not this CP167 guard. Add direct CP167 pre-write cases after the checkpoint seam is repaired, including the QString side and an actual `ConversionSession` pairing that observes the one-time transition.
3. **Required gates have no receipt.** `analysis/resume167-connector-next.md` requires focused factory/root-owner tests, the source-stable checkpoint build/regression, and original comparison gates. `analysis/resume167-connector-implementation.md` explicitly says no test/build command was run. Acceptance remains open until those gates pass on a frozen source snapshot.
