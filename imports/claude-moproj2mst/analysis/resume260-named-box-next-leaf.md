# CP260 named scene-box successor (read-only design)

A bounded named-holder union leaf is justified for the existing non-refreshing `sceneBox(Display&)` specialization. It can add the native named contributions after the CP259 fixed slots without solving the independent radius query or introducing an owner/API. This establishes the box/window contribution only; it does not establish complete fit parity or named refresh parity.

## Current ownership and safe traversal

`source/apps/moproj2mst/include/m2m/engine_scene.hpp:58` defines DisplayModels. Its Named record contains name, unique_ptr<GuiModel>, flag. The vector is declared in QMap key order. `src/engine/scene.cpp:25` finds an existing key first, otherwise creates the model and inserts before the first greater name; flag starts false. Models have stable heap addresses while vector insertion moves their unique_ptr owners. Existing native holder lifetime differs: the port header records a QPointer holder and native display not deleting the model; this leaf must not claim ownership-lifecycle parity or change ownership.

The box-only query path does not insert/erase named entries or call a refresh callback. A direct ordered const reference loop over `d.models.named`, checking flag first then `model.get()`, is therefore sufficient for this bounded specialization. Do not retain Named references/iterators beyond a visit, copy unique_ptrs, snapshot raw holder addresses, or call displayNamedModel while iterating. A model raw pointer confined to the immediate query is stable under current single-threaded non-mutating path. No new borrowed-pointer collection is needed. A future refreshing/reentrant named traversal needs its own lifetime and snapshot argument; this design does not authorize it.

Canonical names are unique because displayNamedModel reuses existing keys. The exposed vector allows synthetic unsorted/duplicate records; tests should use canonical creation and verify insertion order, not repair or sort user-mutated fixtures in sceneBox. Models can alias the fixed guarded slots without ownership duplication; native independent visits must remain independent. Never put the same raw model into two unique_ptrs to create an alias test.

## Implementation and actual caller regression

Only production file required is `source/apps/moproj2mst/src/engine/viewer_camera.cpp`, replacing the named-tail omission around line 274. For each shown non-null Named in stored key order, call viewerSceneBox, boxOf and existing boxUnion exactly as CP259 does. No new refresh or preflight, no dimension/step check here, and no geometry admission broadening. Invalid boxes preserve valid accumulated boxes using existing helper behavior. A thrown later query retains earlier caller refresh effects.

Actual entry is `displayRefreshScene(Project&,GuiModel*)` at viewer_camera.cpp:443, through displayShow then fit. displayShow recognizes named membership without replacing main. `fit` refreshes shown fixed slots only, then calls the private sceneBox. Named geometry is therefore consumed from its current cache; this leaf must not imply that later named geometry edits become current on this caller. `viewerSceneBox` at viewer.cpp:2100 reads viewer caches and retains the established unsupported geometry-list mesh rectangle boundary.
