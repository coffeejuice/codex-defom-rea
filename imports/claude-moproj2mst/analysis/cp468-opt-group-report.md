# CP468 Type3 .OPT preliminary group lists are temporary copies

CP465 established the writer's three `+0x98` group calls and conditional `+0x60` calls. CP467 first inferred that matching row values populated the collections tested by the writer. That inference was wrong. CP468 follows the identities of the writer's list objects, copied arguments, append target and Qt detach operation. The writer tests separate original lists that remain empty in the stable normally returning profile. The preliminary `+0x60` branches are therefore skipped, regardless of matching NUM_CON rows. The later per-row `+0x60` loop is a separate path and remains reachable.

Let `W` be the writer's post-prologue RSP. The tested originals and by-value temporaries are `W+0x98`/`W+0xd8`, `W+0x50`/`W+0xe8`, and `W+0x78`/`W+0xf8` for groups 0, 1 and 2. Each original starts as an empty list. `0x14003f680` copy-constructs the temporary, shares and refs the backing, and returns the **destination** address. The caller passes that temporary as R8 to `+0x98`, then tests its original list. In `0x14091eff0`, clear, matching-row append, size and destruction all target the saved R8 temporary. A matching append copies the row's `+4` field1 value, not its loop index. The returned count is ignored by the writer.

Copy-on-write closes the possible shared-backing route to the writer's original. Append observes backing refcount other than one and calls `0x1400253c0` followed by original Qt `QListData::detach_grow` at `0x67048880`. That Qt function allocates replacement storage and publishes it only into the supplied temporary list object. The writer original retains empty backing. The writer's three conditional preliminary result locals also have no later reads in the complete CP465 function; do not claim group values are emitted. This conclusion assumes valid shared-null backing, normally returning original Qt/EXE functions and no concurrent mutation or hooks. It says nothing about allocator failure, faults, unwind or a loaded runtime module identity.

The reproducible verifier `analysis/cp468-opt-group-verify.py` binds five EXE functions and Qt detach_grow to complete PE exception ranges. It compares 1,022 addressed bytes and 251 instructions to immutable original files, with zero mismatches; the six bounded exports and `analysis/cp468-opt-group-byte-verification.json` retain hashes and ranges. Original EXE SHA-256 is `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`; QtCore SHA-256 is `bcf0074c7e9fba3bcafdaa38742931f309889cbdbacffbca32af83db237fc160`. CP465 binds the writer caller windows, CP467 binds the `+0x98` callee plus four scalar row getters, and CP461's byte-bound Qt/EXE helper evidence qualifies shared_null, ref/deref and the selected list clear/assignment/destructor calls. Allocator/CRT effects and hooks remain outside the stable model. No original process, GUI control or mutable REA session was used.

The CP467 report's first draft described a writer-visible matching list; this report supersedes that interpretation. A private projection may implement the four row getters independently. It must not expose a populated group list to the writer from these calls or treat a preliminary `+0x60` branch as normally taken. Public Type3 Save and physical `.OPT` bytes remain guarded.
