# CP222: ownership closure before R300 cache1 publication

## Engineering outcome and current boundary

Make the converter's native step reachable only through model-owned operations, so a Stopping or geometry continuation can park the model without a previously returned step, simulation-control, object, material, or geometry pointer bypassing admission. This requires a coordinated migration across ownership, loaders, editor operations, viewer state, property helpers, serialization, and tests. A private `step` member or another callback wrapper alone does not establish that property.

This is an implementation design, not an implemented or tested closure. CP163's Stopping size-query/fresh-A prefix and immediate `CoordinateSync` return must remain throughout every migration commit below. Selected-length/cache1 publication and subsequent normal continuation remain closed. Source closure can be implemented now; the separate original same-occurrence witness remains required before admitting the continuation.

CP203 establishes the public-storage/earlier-alias problem and the native zero-length/cache1 instruction order. CP214 correctly refuses an independently safe cache1 increment. CP218 inventories 25 direct-step production files plus 43 test files; that locator differs from CP203's broader 41-file audit and is not an exhaustive semantic inventory. A current scoped search still finds the same 25 production files. This design adds concrete contracts, migration commits, and work ownership; it does not reinterpret those reports as proof of closure.

## Concrete ownership/API contract

### 1. Private aggregate and finite operations

Keep `DB_STEP_DATA` and its layout unchanged in the recovered native port. Preserve native interior backlinks such as `sim_ctrl.owner` and `LLOBJ_DATA::owner` inside that aggregate. Those are native implementation relationships, not public borrows. `GuiModel` owns one private `std::unique_ptr<DB_STEP_DATA> step_`, declared where destruction ordering preserves existing lifetime guards. Do not deep-copy the native graph, change its allocators, or substitute serialization snapshots for state mutations.

The supported converter C++ surface exposes only named operations and owning value results. Examples of proposed API shapes (names are new, not existing declarations):

```cpp
StepIdentity stepIdentity() const noexcept;       // observation only, grants no access
bool hasStep() const;                            // nullable semantics, admitted read
int objectCount() const;                         // admitted scalar read
std::optional<ObjectKey> findObject(int number) const;
ObjectSummary objectSummary(ObjectKey) const;   // strings/vectors own their data
ApplyResult applyAdvanced(const AdvancedPage&, Operation&);
bool writeObjectKey(ObjectKey, const String&, FileEffects&);
```

Do not return native pointers/references, spans/string_views into native storage, pointer-bearing native structs, or callbacks that receive the native graph. A noncopyable `StepBorrow` with `get()`/`operator->` would still let callers save its pointee; it is not the public solution. A `const DB_STEP_DATA*` is also an alias, not an owning snapshot. Avoid copying whole `SimControl` structures because their nested owners/tables remain pointers.

Implementation may use a private, noncopyable, nonmovable RAII native-call scope with a reference to the aggregate, but only inside a finite set of reviewed implementation adapters. The scope never crosses a named operation's return, an application callback boundary, a queued job, or a stored lambda. No unrestricted friend template or public `GuiModelAccess::withNative(F)` survives the closure. Friend domain adapter classes may be declared in the model header with their definitions/method declarations in private implementation headers; their externally callable methods accept values/keys, not raw pointers. Any raw references among their local helpers remain confined to the synchronous operation stack. C++ does not provide a general borrow checker: confinement of these finite trusted bodies and their native callees is part of the proof, not something `requires` clauses establish.

Native writers that synchronously consume a step retain their original call ordering and output behavior. If a native callback currently receives a raw object, move that callback invocation inside its owner command and audit both dispatch and callback implementation. If a callee really retains an alias, migrate the retention to an identity or keep that route refused; declaring the adapter trusted cannot discharge an unknown lifetime.

### 2. Identities that do not become pointers

Add `StepIdentity`, `ObjectKey`, and, where consumed, material/geometry/frame identities. Their constructors are private to the owning model/access implementation. A step identity binds the existing lifetime-control-block identity and a monotonic storage generation; an object key additionally binds object incarnation and native number/ordinal. Equality must distinguish a new model allocated at a reused address and a replacement/recreated object with the same number. No token exposes a conversion back to `uintptr_t`/pointer or a resolver returning a reference.

Every consuming operation validates the key against its actual owner and admitted current storage before resolving a native pointer locally. `reset()` clears the same aggregate rather than necessarily replacing its address: advance the generation before `step_clear`, and retain the advanced generation even if a later native call fails. Whole-model KEY/DB reload and object removal/recreation need equivalent invalidation at their first destructive effect. Merely changing a step's numeric simulation step or read-only query must not silently rebind a stale key. A per-object incarnation permits existing unrelated object bindings to remain valid when fidelity requires that; define the invalidation matrix before migrating viewer bindings. Use explicit rebinds at the original bind sites. Overflow must not wrap and revive an old key; fail admission before a destructive effect if generation space is exhausted.

Diagnostic address values may remain inert historical observations where the research receipts require them, but they cannot authorize access, equality acceptance, or dereference after a call. Preserve qualified original pointer-equality behavior by issuing/reusing an identity for the actual live binding; do not replace an equality test with just an object number. Reader identity additionally binds the current `DbHandle` owner, reader incarnation and existing directory receipt/version. Do not erase directory-receipt checks in favor of a model generation.

### 3. One model-owned admission state, separate native continuation proofs

Use private access state in `GuiModel` (or private owned state): storage generation, active native-call depth, current operation epoch, and a parked reason/frame identity. Normal entry performs existing nullable/geometry/ownership checks at the same reached point, then admits its operation. R300 Stopping and geometry use this common exclusion mechanism; retain their distinct payloads, stage transitions and existing proof predicates. Combining admission is not permission to clear one continuation using the other's token.

The converter already serializes conversion entry; do not add a new concurrency guarantee. Enforce the same owning execution context for internal operations. For synchronous nested calls, pass private admission authority down the stack rather than reacquiring through a public getter. Installation of a parked frame is permitted by the current owning operation, after its required native prefix effects. It immediately closes normal admission, including reentrant Save/display/reset calls. The current native operation may finish only its explicitly allowed prefix using a private operation-epoch token; unrelated nested calls cannot inherit that authority. On return, no native scope/pointer remains outstanding; the model stays parked. A mutex held across native/user callbacks or a wait for the current scope to drain would deadlock reentrant paths and must not be introduced.

Before a parking transition, assert that no unrelated native-call scope is outstanding. If a callback can introduce another active operation at that point, reject or defer admission before its first effect; never publish cache1 while an unrelated earlier borrow remains. Preserve currently supported callback order and error prefixes; do not add rollback, replace ignored native returns, or restart partially executed loaders. RAII bookkeeping must unwind on exceptions without silently clearing the parked frame. An original continuation may only retire the exact installed frame at its already-qualified terminal stage; model/viewer replacement and lower query versions cannot retire it.

### 4. Shared `Operation::engineModel`

Shared ownership itself is compatible with closure; interior mutable access is the problem. Retain the same shared control block and lazy `opModel` creation timing. Move the field behind an operation cache owner/access class and provide separate noncreating observation and creating lookup. Cleanup (`operation_info_cleanup.cpp`) must still inspect the actual nullable cache without lazy creation. `conversion_session`, Boolean and R300 owner checks must compare both pointee and shared-owner identity exactly as today.

A retained model handle may keep the model alive and call admitted value/command methods, but cannot retrieve `step_` or an interior pointer. Weak guards remain nonowning. Cache clearing/rebinding cannot cancel a parked old model; the old owner state follows that retained model until its legitimate destruction. Do not turn every shared owner into a weak pointer or alter accepted Close ownership as part of this migration. Existing `opModel` raw model pointers can remain compatibility lookups during staging; final application callers should receive an opaque model handle/guard with the same lazy/null behavior, never a native-step alias.

## Dependency-ordered compiling commits

These are proposed commits, not claims that the source currently contains the APIs. Each must compile and pass its focused tests before the next dependent seam is integrated. The cache1 guard remains in all of them.

1. **`model: add opaque step identity and invalidation observations` — smallest first batch.** Own only `include/m2m/engine.hpp`, `src/engine/gui_model.cpp`, a new private identity/access-state header, a new focused Testkit test, and root-owned registration. Add nonforgeable model/generation identity and equality/currentness observations. Instrument constructor/destructor/reset identity transitions without changing native effect order or adding new public admission failures. Existing public `step` remains explicitly legacy, so this commit makes no closure claim. Initially test constructor/reset/destruction and model-address reuse; other destructive operations are not yet represented as covered. In particular, direct legacy `step.reset()`/assignment can still evade metadata invalidation: identity currentness in this commit covers only instrumented owner operations and cannot authorize access or publication. Do not expose a general token-to-pointer resolver. This is useful groundwork and is buildable without migrating 68 files at once.

2. **`model: introduce named commands and private native admission scaffolding`.** Add value/key APIs and owner-operation scopes alongside the legacy surface. Preserve existing geometry checks on migrated methods. Define private adapter declarations and the full invalidation/admission table, but do not claim the scaffolding can park safely while public aliases remain. New code uses the safe surface; legacy fallback is explicitly migration-only. Add nested-call/exception/park-state unit tests against the new seam. Root integrates common headers once before parallel consumer work.

3. **`loader: move storage mutation behind owner commands`.** Migrate `GuiModel` native methods, KEY/DB reads, all loader families and destructive invalidation points. Change pointer-returning object-creation helpers to return `ObjectKey`/status and let the subsequent owner command resolve it. Preserve create/init/import/viewer/update order and missing-step behavior. Keep legacy readers available for the still-unmigrated families, and keep cache1 closed. This stage cannot privatize storage yet. Multi-file loader helper declaration/definition/caller changes land together so the commit compiles.

4. **`engine: migrate editor and property mutation families`.** R300/Boolean and property entry points resolve their native control internally; replace public raw-control inputs and `opSimCtl`/`slotObject` forwarding. Preserve owner identity, nullable lookup, recovery-list admission and repeated native tail calls. Each family can land separately after stage 3. Save code temporarily retains its legacy access until its own family commit; do not remove a shared helper before its last caller migrates.

5. **`viewer: replace retained native aliases with current-owner bindings`.** In one dependency-closed family migrate `View::obj`, geometry frame/evidence/temporary records, recipient arrays, DOE slice `boundObject`, and stored lambdas. Store owned scalar/byte observations plus keys; recompute native pointers only in the correct current operation. Preserve existing allocation retention and lower-layer heap ownership. A parked frame must be inspectable for diagnostics without dereferencing old graph addresses. Tests cover reset/reload/rebind, same-number object recreation, dead models, stale receipts and frame reuse. Stage 4 and this stage can be developed concurrently after the common API freezes, but integrate separately.

6. **`save: consume models through synchronous owned commands`; `model: confine operation cache ownership`.** Migrate serialization/Save and remaining readers, preserving file/write order, formatter bytes, failure prefix and ignored-return behavior. Writers may use a private synchronous native scope for the whole dependent write stage; do not deep-copy or make Save transactional. Independently migrate operation-cache observers/creators, preserving existing shared identity and no-lazy-cleanup behavior. Integrate callback signature changes with all callers. Complete the remaining source/test migration before final removal.

7. **`model: remove legacy storage and alias APIs; enforce common parked admission`.** In one integration commit rename/private `step_`, remove all public/native raw getters and generic pointer callback seams, and delete transition-only privileges. Every production and test caller must now compile against the closed surface. Ensure reset/load/reload/editor/viewer/display/Save and forwarding hooks enter the common state before consuming native data. A retained model owner or a formerly issued key cannot bypass a parked state. This is the first possible source-closure candidate; cache1 remains refused pending independent audit and original witness.

8. **Only after both gates: `editor300: admit witnessed selected-length/cache1 continuation`.** Separate behavior change and tests from access migration. Bind exact original occurrence, current owner/reader/receipt/frame and length/cache predicates. Do not infer reader normal return from the cache store. Failure to obtain the original witness does not block commits 1–7; it blocks this publication/continuation commit.

Temporary public storage in commits 1–6 is intentional compile staging and disqualifies their barriers as complete. Do not label those checkpoints cache1-safe. No intermediate commit may activate the new store just because its own changed tests pass.

## Proof and test requirements

Before final storage privatization, produce a per-symbol/call-site ledger classifying read, mutation, replacement, synchronous borrow, callback, retained field and native backlink. Search production, tests, installed C++ headers, sample/binding callers and relevant port callees, including `.get()/reset/release`, `at<>`/casts, `sc.owner`, object owners, `DB_STEP_DATA`/`LLOBJ_DATA`/`Material` references, raw-return wrappers, `std::function`, stored lambdas and pointer-bearing snapshots. Independent native-port fixtures may still construct their own raw `DB_STEP_DATA`; the forbidden escape is from the actual model-owned aggregate. Do not replace those native layout tests with model mocks or treat every raw pointer in the port as an ownership violation. Bound each search output and inspect the actual callees. Retain the source qualifications from CP203/214; no source search proves an original public execution.

Required evidence for the source-closure commit:

- Compile-negative checks prove ordinary consumers cannot name public `step`, call legacy getters/callback seams, construct valid keys, obtain native references, or derive a bypass through a shared operation cache. Positive public C/C++ binding smoke checks preserve all `m2m_*` exports, signatures, API version 1, flags, structure layout and error mapping in `include/moproj2mst.h`. Source-visible C++ `GuiModel`/`Operation` layout is intentionally migrated; do not claim binary C++ ABI compatibility that the inspected sources do not promise.
- API tests exercise null/missing steps, same model address reuse, step clear at unchanged address, reload, object remove/recreate with unchanged number, replacement, expired guards and stale reader receipts. Owning snapshots remain valid values after invalidation; stale keys fail before dereference/effect. Internal replacement/invalidation rejects unrelated active scopes; exception unwinding preserves already-committed native effects and parked state.
- Reentrancy tests attempt Save, display/viewer, reset, reload and another editor entry from native/file callbacks before and after park installation. No entry observes cache1 or performs prohibited effects while parked; the current authorized prefix can finish and leave no active borrow. Do not replace real native functions with mocks for existing fidelity tests; use explicit test observation hooks where necessary.
- Existing `tests/mdt/test_simcontrol300_stopping_cached.cpp` remains a regression for cache index 11 staying zero on covered refusal/retry paths. Add coverage using pre-obtained keys/shared owners and every named entry above, including `objectCount()`. Include both geometry and Stopping reasons and demonstrate that one continuation cannot clear the other's state. Candidate tests do not supply the missing original occurrence.
- Load/reset/viewer/geometry/slice/property/Save tests preserve output bytes, null behavior, allocation ownership, per-stage return/error prefix and call order. Existing low/high geometry continuation tests must continue to distinguish their qualified stages. Do not blanket-close geometry behavior that is already supported merely to simplify admission.
- Testkit preflight uses the actual `check.hpp` macros (`CHECK_EQ`, `REQUIRE`; no `REQUIRE_EQ` or Release-disabled `assert`), resolvable include paths, and missing-file probes beneath `M2M_TEST_SCRATCH`. Root runs changed targets as one focused group, then the complete source-stable launcher and freeze with source/executable hashes bound before and after. CP221's counts are historical baseline expectations, not fabricated results for this design.

The independent original witness still must correlate live Project/DB reader, actual step and selected Stopping node, query/version outcome, A publication, selected zero length, cache1 store, loader normal return, arrays timer checkpoint, recipient assignments and reader/outer return within one source-produced occurrence. Retained instruction windows establish order, not that execution. GUI-control release remains governed by the existing lifecycle gate; this design neither acquires nor authorizes another GUI session.
