# CP170 connector independent source and test review

## Decision

**Accept the CP170 source cut for integration; block the focused test and checkpoint acceptance.** The source models the fourth private zero field as unknown until the selected store, validates the CP169 predecessor and owner before mutation, writes only private `+0x58 = 0`, and stops at QtCore RVA `0x1311c7` before the QVector shared-null load. The current factory tests contain stale phase assertions and restored predecessor frames that retain the CP170 observation. The CP170 refusal matrix also omits several required owner and binding faults. This is a static review; no test, build, original comparison, GUI, or live REA operation was run here.

## Source assessment

- `doe_task_runtime.hpp:39-50` declares `private58` as a default-disengaged `std::optional<std::uint64_t>` in the same retained `SparseQObjectPrivate`, and declares distinct `BeforePrivateZero58` and `BeforeQVectorSharedNull` phases. `task_factory.cpp:129-130` saves the allocation-time private pointer independently.
- The earlier zero-store guards at `task_factory.cpp:223-225`, `:250-252`, and `:277-280` reject an already observed `private58` before private `+0x40`, `+0x48`, or `+0x50` can be written. Each guard runs before its field/phase mutations.
- `task_factory.cpp:286-311` checks the retained Report in the allocation store, its independent private pointer, `0xc0`/`0x88` native sizes, written task/private address points at `0x23cac8`/`0x1a9d10`, store-owned live root, pointer-identical qualified QList and QString bindings, both committed markers, zero `private40`/`private48`/`private50`, absent `private58`, and incomplete/unbacklinked state. `TaskAllocationStore::ownsWidgetRuntime` at `task_runtime.cpp:30-37` compares shared control-block and pointee identity. A malformed CP169 frame is refused before `task_factory.cpp:312-313` writes the one zero and advances the cursor.
- The only CP170 admission writes are `private58 = 0` and `phase = BeforeQVectorSharedNull`. The unconditional stop at `task_factory.cpp:315-326` reports RVA `0x1311c7`; no QVector binding, reference increment, private `+0x68` write, backlink, completion, or cache update occurs in this cut. Native-profile initialization precedes key lookup at `task_factory.cpp:332-339`, so reentry reaches the same stop without replaying the store or prior reference deltas.

## Test blockers

1. **Stale first-call phases.** Every searched first-call stop string in `test_doe_task_factory.cpp` has been updated to `RVA 0x1311c7`, but assertions at lines `313`, `331`, `339`, `363`, `368`, `409`, and `1001` still expect `BeforePrivateZero58`. The successful call has already advanced to `BeforeQVectorSharedNull`. The real `ConversionSession` positive case at lines `344-369` therefore also has two wrong assertions, although its owner pairing and root deltas are tested.
2. **Restored predecessor frames retain `private58`.** The CP168 transition test at lines `387-409` restores `BeforePrivateZero50` and clears `private50`, but leaves `private58 == 0` from its first call. The CP169 guard rejects that frame before the expected CP169/CP170 continuation, so the test cannot prove its claimed transition. The CP168 refusal matrix at lines `428-463` and the three-case CP169 loop at lines `529-543` also leave `private58` observed when reconstructing earlier prewrite seams. Their refusals can be caused by this common premature field instead of the injected independent fault. Clear `private58` at each restored seam, assert it is absent, and include it in the post-refusal snapshot.
3. **Incorrect CP170 wrong-phase diagnostic.** The CP170 matrix sets `BeforePrivateZero50` while `private50 == 0` at lines `714-723`. That invokes the CP169 guard and throws the `CP168 state` diagnostic at `task_factory.cpp:281-282`; line `733` instead expects `RVA 0x1311bf`. This case will fail even though the source refuses without mutation. The assertion should name the actual guard, and its snapshot should remain intact.
4. **CP170 prewrite coverage is incomplete.** The CP170 matrix at lines `710-741` exercises missing `private40`, bad `private48`, missing/bad `private50`, premature `private58`, wrong phase, completion, and two backlinks. It does not inject absent/expired/foreign/aliasing-foreign roots, wrong QList/QString binding or qualification, uncommitted markers, wrong address points, replaced private identity, wrong native sizes, or completed QObject base at the `BeforePrivateZero58` seam. Its refusal snapshot checks fields, phase, bindings, deltas, two counts, and completion/backlinks, but not allocation-time identity, task/private address points and sizes, binding markers, root identities, absolute-count observations, or all factory maps. Earlier-phase matrices cannot substitute for these CP170 admission cases. The ordinary CP170 test at lines `677-709` establishes the one-time observed value, cursor, reentry, prior deltas, and lack of completion, but does not itself establish the complete no-mutation contract.
5. **Initial unknown state lacks an explicit test.** `SparseQObjectPrivate` correctly defaults `private58` to disengaged, but the fresh-state checks at lines `374-377` stop at `private50`. Add a `private58` absence check so the test directly protects the sparse-field contract.

After these repairs, run focused `doe_task_factory` and root-owner tests and the established source-stable checkpoint/original-comparison gates. The inspected implementation note records no CP170 build or test result, so this review does not claim runtime acceptance.
