# CP77: remesh tail, project status, and the DOE refresh boundary

## Reconciled ordering and status

For ordinary supported Type-0 Save, the original static sequence is current-operation Save `0x140052ec0`, project writer `0x1400983c0`, operation properties `0x1400982e0`, MST writer `0x1400a20d0`, then remesh write/remove. `analysis/save-semantics.md` and `analysis/wave3-remesh-save-lifecycle-contract.json` show no branch on project or MST file booleans before the remesh tail. The original top Save combines the project/MST booleans locally, but returns its earlier check/status local; this is not the DLL adapter's `M2M_E_WRITE`.

Current native adapter ordering matches those effects on the tested Type-0 profile: project writer returns; properties/Boolean sidefiles run; MST attempts; remesh tail runs; then adapter status is chosen. It deliberately maps remesh refusal first (`M2M_E_UNSUPPORTED`), MST failure next (`M2M_E_WRITE`), and project failure last (`M2M_E_WRITE`). CP73's injected post-close project error verifies successful MST/remesh continuation and the project-only final `M2M_E_WRITE`. CP74 targets a remesh-open refusal, but the original failed-open case is a distinct CRT invalid-parameter path and cannot be represented as that ordinary status without qualification. Existing tests exercise MST-only failure and project-only failure, not both returned failures together; the adapter's MST-over-project tie-break is therefore an acceptance choice beyond the original top-level return, whose earlier status is unchanged.

## DOE refresh is inside the project-writer call

For Type-2 sub-project serialization, original effects occur inside `0x1400983c0` before that writer returns. `analysis/resume64-doe-save-effects.md` source-qualifies the Type-2 order: study DOM node; InputTable XML open/write/close/error; unconditional `2signalDoeTableRefresh()` even when the XML writer Boolean is false; current `DEF_DOE.PAR`; `Samples_LHS.par`; `Samples_FF.par`; `Samples_USR.par`; `Subproject_DbName`; then parent DOM replacement and final `.moproj` stream/close/error. The outer Save only reaches properties, MST, and remesh after the project writer returns normally; if it returns false, it still continues those stages as for Type 0.

The current candidate writer reaches the XML writer and journals its normal return, then `DoeTableOwnerState::requireRefreshDelivery` is noreturn. `analysis/resume72-doe-manager-after-refresh.md` qualifies the missing actual table/timer/Qt receiver effects and explains why catching that guard and continuing would invent them. Consequently, for a Type-2 project the current flow throws before `projectWriteReturned`, before Type-2 PAR outputs and parent project close, and before outer properties/MST/remesh. The CP73 `ProjectOutputFactory` post-close injection cannot cover this path: its post-close query is not reached while the serializer throws at DoeTableRefresh. This is a deliberate unsupported boundary, not evidence that the original returns a failed project writer or skips its later effects.

## Next concrete test and prerequisite

The next meaningful integration acceptance is a paired Type-2 Save after the actual `DoeTableRefresh` receiver/timer/UI path is bound. Use a bounded profile with empty Type-2 variables and supported constraints, and maintain real Session/SUB/Study manager identity. In control and injected runs, record ordered effects: XML normal writer return (including a separate ordinary-false case), refresh receiver delivery and timer/widget/cache effects, current and fixed-mode PAR calls, DBName/DOM replacement, final project Close/error query, then properties, MST, and remesh. For the injected project writer result, reuse the declared post-close error service only after the serializer reaches and returns from its final `.moproj` writer. Assert downstream continuation and the adapter's project-error mapping only in that returned-writer case. Do not predict partial XML/project bytes from the original static evidence.

This depends on closing the real `DoeTableRefresh` notification owner/population, QTimer stop, and slot delivery for the converter's live Session; existing owner-state tests intentionally refuse at that boundary. Until then, do not weaken the guard or label CP73's Type-0 case as DOE Save coverage. A smaller non-DOE follow-up can add an adapter test for simultaneous normal MST failure and project post-close false, asserting remesh still runs and MST `M2M_E_WRITE` wins only at the adapter boundary; this does not resolve or substitute for DOE refresh.
