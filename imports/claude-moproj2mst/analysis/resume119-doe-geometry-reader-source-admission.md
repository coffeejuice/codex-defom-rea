## Source-ready shape versus missing admission

After the missing constructor/conversion context is closed, the smallest private wiring would carry the existing per-invocation source through `parseInputTable -> appendBoundedHeaderVariable -> encountered Geometry`. It would operate on the already-selected concrete record, obtain the parent at the native phase, convert/read attributes in order, call the row prefix, then call indexed pair append immediately for each completed pair. It would never call `0x140032800`, `0x1400d4560` or the GUI editor loader. The source-less bytes API must retain its own guard.

The obvious shared write set for that future lane is `doe_study.cpp`, `doe_variable_record.hpp` / `variable_record.cpp`, private `input_table_reader.hpp`, and a focused named-source integration test. Root must assign these before editing. Passing a filename or an enum/Boolean called “FileInfo succeeded” is insufficient: admission needs an owner/decision path connected to this same invocation and the reached handler/conversion state. Existing resource QString helpers and QFileInfo private ref0 helper are isolated and resource-scoped; using their profiles on this parser would invent that binding.

A profile with **no PointPair elements** avoids the toDouble/token-list dependency. It still constructs QFileInfo, performs three integer conversions, mutates the keyed row, applies tail flags and MorphMethod, and cleans up the local QFileInfo. Missing all three numeric attributes gives qualified zero values but still does not close QFileInfo or process-locale side effects. Therefore this smaller profile is a useful next integration target after those prerequisites, not a currently admitted public case. There is no benefit in adding a parser helper that computes conditional paths and immediately throws at the unchanged earlier guard.

CP118 removes an over-broad prerequisite: the separate GUI GEO loader does not have to be implemented merely to reproduce this in-memory reader branch. It does not remove the earlier concrete QFileInfo/Qt conversion dependencies. Likewise the public nonempty-variable Save reconciliation and live refresh callback guards are independent of a successful Geometry read and must remain.
