# CP416 first-versus-retried wait discriminator

CP415 established that CP333 submitted the terminal `ReadFile` and CP328 then hit the absolute deadline at a `wait_budget` boundary. That phase did not say whether `GetOverlappedResultEx` had been called. CP416 adds one local `first_wait` flag in CP328 `_finish()`: the original `wait_budget` now labels the first budget check before a result call; `wait_retry_budget` labels a later budget check only after a result call returned nonterminal. The existing result call, budget arithmetic, Win32 arguments, ownership, cleanup and acceptance remain unchanged. A retry phase does not measure how long a wait took or prove the contained runner wrote a terminal frame.

CP333 emits the new fixed phase on the same exact deadline failure; CP349's allowlist accepts it under the unchanged 40-record/2048-byte bounds. Injected tests cover expiry before the first result call, a nonterminal result followed by retry-budget expiry and retained-operation cleanup, and a successful transfer without a retry phase. The CP3xx suite passed 644 tests from each supported module root with `-B`; raw output is `cp416-wait-discriminator-tests.log`. `git diff --check` passed. Independent current-source review found no change to native calls, deadline, ownership or success decisions, while noting that the reviewer could not inspect Git diff from its restricted checkout. Root inspected that exact diff.

The static protocol review also established that CP316 WORKER writes RESULT and reads ACK, whereas CP335's contained runner writes the CP339 terminal frame only after CP330 reports exact WORKER completion. No later CP333 parent action is needed before that write. CP417 is the successor: freeze CP416, independently gate at most one new inert occurrence, and use its first/retry phase to decide whether runner-side evidence is needed. Do not rerun CP415 or infer public C++ parity from the inert harness.
