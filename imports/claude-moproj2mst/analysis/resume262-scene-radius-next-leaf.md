# CP262: independent fit radius and the next implementation leaf

The independent fit radius is the radius of a second union of boxes. It is neither the maximum per-model radius nor necessarily the radius of `sceneBox`. The difference is already meaningful for the converter's supported rectangular fallback: the native radius query reads every settings-bearing view's cached 3D box, whereas `viewerSceneBox` may return the model's 2D rectangle instead. The smallest useful successor is to recover that owner-level all-view query and wire its union/radius into fit before the existing scene-box queries. Do not fold it into `sceneBox` or silently retain the substituted radius for one dimension.

## Arithmetic and camera gate

Use existing `boxOf`/`boxUnion` arithmetic at the display layer and existing Box3/Rect2 operations at the viewer owner. `14121a9f0` returns the other operand when the accumulator is invalid and preserves the accumulator when the incoming operand is invalid. Two valid operands use componentwise extrema; ties take the incoming operand. Derived centre sums widen input floats, then narrow the sum to float, divide by two and narrow again; max-minus-centre narrows to float. Squared components/additions remain float before widening for double sqrt. This is union radius, not a sphere merge or max of individual radii. `cfe0f0` reads the resulting stored radius without another arithmetic operation. Shared-helper arithmetic here is retained qualified evidence, not a fresh independent byte audit of every float helper.

The independently decoded camera store `d69e70` first calculates window width (Box right minus left), then height (top minus bottom), then loads the double constant at `1421b5050`, verified directly as `0.001`. It calls `1412197d0` for invalidity, rejects invalid, rejects when `0.001 > independentRadius`, rejects when `0.001 > width`, then rejects when `0.001 > height`. On acceptance it copies the scene Box3 to camera `+298` (`d69f6f`) and stores the independent radius at `+380` (`d69f82`). On rejection both previous stored values survive. Width and height come from the **scene box's** derived view volume, not the independent union's volume.

The disassembly uses `COMISD` plus `JA` for early rejection (`d69f19/d69f22`, `d69f2a/d69f30`) and `JBE` for final acceptance (`d69f38/d69f3e`). Consequently unordered comparisons do not reject. The exact C++ predicate is `valid && !(threshold > radius) && !(threshold > width) && !(threshold > height)`, with width/height computed before the validity test. Current `threshold <= ...` rejects NaNs and is different. This establishes static comparison behavior, not an admitted production NaN fixture or signaling-NaN/FPU exception parity.

Native fit's order is: shown fixed refreshes; global scene-present guard; independent radius query; first `cfd750(...,false)`; camera store using that box plus independent radius; destruction; second `cfd750(...,false)`; camera window setter; destruction; reset; origin from the stored box. Current `viewer_camera.cpp::fit` substitutes `sceneBox.radius`, calls `sceneBox` once, and uses ordered `<=` checks. All three are concrete differences. Keep independent radius before either scene-box query, and keep both queries even where today's supported reads happen to be pure.
