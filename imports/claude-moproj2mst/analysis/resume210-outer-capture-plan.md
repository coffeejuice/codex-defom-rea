# CP210 outer-loader capture design

The smallest direct discriminator is one owned Windows debug-event trial with three simultaneous hardware execution breakpoints: outer-loader entry, its selected caller continuation, and one staged post-call observation. Five conditional return sites do not require five simultaneous debug slots. Prefer this over expanding Frida to six function-entry hooks, but keep original execution disabled until the new observer passes harmless fixtures and independent release review. This report is a design, not an original-ready runner or an execution authorization receipt.

## Method comparison

| Method | Minimum layout for direct values | Principal cost and qualification |
|---|---|---|
| Caller-qualified Frida entry/onLeave | `1ca30` plus `c78c10`, `c79390`, `146f8fc`, `44a90`, `8a9b0`: six entry Interceptors. Qualify helper callers at entry as `1cf11`, `1d08a`, `1d0bd`, `1d0d8`, `1d0fb`. Capture raw retval on normal leave, low byte for acceptance. | Reuses CP207 host/cleanup structure, but patches six prologues, including shared RTTI code; caller filtering happens after instrumentation. All prefixes, actual entry/thunk identity, relocation windows and mock semantics need new review. A helper fault/throw has no normal leave. Missing leave cannot be treated as a zero result. |
| Debug-event hardware execution | Three per-thread slots: `1ca30`, `1c94`, staged post-call site. Fourth slot remains disabled. | Captures actual caller-side RAX/AL before subsequent instructions without inline patching or shared-helper interception. Requires a new bounded state machine, owned debug-register handling, stack unwinding and stronger failure cleanup than CP209 prototype. Stops perturb scheduling and may change the path. |

Inferring a failed cast from an absent Project-accessor hook is weaker than observing the actual RTTI return. Hooking the five interior return instructions with Frida would reintroduce CP206-style instruction relocation risk and is outside this proposal. Do not combine Frida with the debugger merely to reuse CP207 stack capture; combined instrumentation would need separate justification and review.

Select the hardware method for direct discrimination. This is an evidence/perturbation-surface judgment, not a measured speed advantage. CP209's self-fixture demonstrated one primary-thread hardware hit and native AV delivery; its independent review explicitly HOLDs direct original adaptation, identifying loader-breakpoint classification, multithread coverage, raw receipt and failure-cleanup gaps. Those are release blockers, not inherited passes.

## Three-slot state machine

Arm each created thread before continuing its creation event. Slot 0 observes `1ca30` entry; slot 1 observes `1c94`; slot 2 is disabled until a selected entry, then stages the table below. Slot 3 stays disabled. Initial and every changed DR0–DR3/DR6/DR7 state must be recorded/read back while stopped. Never overwrite unexplained nonzero debug-register ownership. Other threads require explicit coverage; hardware registers do not propagate automatically.

At `1ca30`, read raw RCX main, RDX selected QString address, entry RSP E and guarded `[E]`. Select only `[E] == base+1c94` with a successfully decoded, bounded exact B98 path. Assign a per-thread occurrence ID and save identity, E, main, path, and sequence. Require entry/continuation stack relation `RSP=E+8` at `1c94`. Derive and independently verify the outer body stack offset from exact prologue bytes before using it; this design deliberately does not invent that offset from decompiler local names.

| Current stage / stopped instruction | Raw value | Expected continuation |
|---|---|---|
| `1cf11`, immediately after `c78c10` | RAX duplicate lookup | Nonzero: first failed prerequisite is duplicate identity; disable stage slot and await selected outer return zero. Zero: stage `1d08a`. |
| `1d08a`, after `c79390` | RAX child | Zero: factory-return-null route; disable stage slot and await outer zero. Nonzero: stage `1d0bd`. |
| `1d0bd`, after RTTI helper | RAX cast child | Zero: failed cast route; disable stage slot and await outer zero. Nonzero: stage `1d0d8`. |
| `1d0d8`, after `44a90` | RAX Project | Zero: Project-accessor-null route; disable stage slot and await outer zero. Nonzero: stage `1d0fb`. |
| `1d0fb`, after `8a9b0` | raw RAX and `RAX & 255` | AL zero: acceptance-false route; otherwise acceptance succeeded. Disable stage slot; await outer result. |
| `1c94`, selected main continuation | RAX outer result | Require matching entry frame and all expected preceding stages; close occurrence and bind the result to its recorded path. |

Every stage hit must match the selected thread generation, expected body RSP and guarded entry return marker at E; record registers and relevant reads before changing slots. An address hit alone cannot advance the state. Use `(creation FILETIME text, PID, thread generation/TID, occurrence, E, main)` plus ordered sequence, not pointer equality or process-global event order alone. Null/read-error are distinct states. A selected normal return with nonzero RAX is a valid divergent outer outcome, not a capture failure by itself; it cannot support the proposed null classification.

For the smallest first trial, reject/invalidate overlapping or recursive selected outer entries rather than implementing untested nested slot restoration. Entry slot catches those before their stages; record the ambiguity and stop causal collection. Retain unrelated-entry and stage-rejection counts. If an unrelated outer invocation overlaps the selected one and frame attribution cannot exclude interference, mark the occurrence incomplete. Do not leave an old selected frame active merely because no return was seen. Exceptions escaping the selected frame, frame reuse, context/readback failure, missed stage, unknown owned-breakpoint state, or cap reach invalidate completeness. No automatic rerun with more hooks or relaxed filters.

Only scalar results are necessary for the first route discrimination. Manager/DB QString, child vtable, child+19c0, allocator return and reader filename can explain a subcause, but adding call-entry stages or bounded object readers broadens this minimum and requires separate review. Factory zero is only a syntactic route: CP210 notes unguarded factory accesses may fault first. Project accessor zero does not prove allocation failure. Accepted `.moproj` XML-read failure is separate from the reader's acceptance return. Do not classify these subcauses from the five results alone.

## Same-run parity and receipts

At the first application AV persist a compact core before stack enrichment: exception code/chance, fault RIP, module/path/base/RVA, operation/address, RCX, process/thread creation identity, selected/closed outer occurrence IDs and stage/counter snapshots. Persist a correctly qualified native x64 stack; raw stack-word scanning is not an accurate unwind. Strict CP205 parity requires QtCore4_64.dll RVA `32c0`, read `0x58`, RCX `0x58`, app returns `a7510 -> eb1ec -> eaa7a`, and outer callback context `2a725 -> 1cae` binding this selected main Open. A first AV on another path ends CP205 causal interpretation, even if useful branch values preceded it. Preserve those values as observations with a divergence label.

Require one complete same-frame outer entry/stage-prefix/normal-return-zero sequence before attributing its first failed prerequisite. At the fault the outer frame has already returned; bind the retained closed occurrence to the main/postOpen path, rather than demanding it remain active. Multiple eligible closed occurrences or unqualified stack association stay indeterminate. Missing later-stage events after a witnessed failing predicate are expected; missing a required stage before a subsequent hit or return is not. Registration/readiness and zero hit counts never establish a branch result.

Record both AV chances and dispositions. Pass application AVs through with `DBG_EXCEPTION_NOT_HANDLED`; do not change registers, results, target memory or exception fate. After first AV stop causal collection, clear only owned breakpoints while stopped with checked readback, continue natural delivery and drain exit. Do not stop the debugger loop while the process is suspended on an outstanding event.

Raw directory must contain observer/helper source/hash, runtime/tool versions, target/module identities, fixture-before/after manifests, every debug event and successful/failed continuation, thread/module/handle generations, bounded raw scalar snapshots, debug-register before/after/readback records, compact AV core, qualified stack/enrichment, both AV chances, natural exit code, cleanup API results, and a derived summary with explicit failures. Persist events incrementally; a summary cannot reconstruct a lost exception. A final complete receipt requires count/sequence parity and no serialization errors, cap reaches or unreported drops.

## Exact cleanup

The creating debugger thread owns the event loop and every continuation. Track CreateProcess caller handles, event process/thread handles and duplicates by acquisition/generation; numeric handle reuse must not alias ownership. Close create/load image file handles even during failure drain. Check every ContinueDebugEvent, termination, wait, context and close outcome. Account for Windows automatic event-handle closure after continued exit events; avoid double close. Preserve an independent exact creation handle through verified signaled termination and exit code; independently inspect process enumeration/identity without using PID alone to choose termination. A still-openable signaled PID is not proof of live execution or PID absence.

On held-child setup failure, terminate only the exact created child handle and drain/check events. On post-resume deadline/error, retain the pending-event state, resolve it under a tested failure path, use exact-child termination only when required, and record it. Forced cleanup cannot count as a natural complete capture. Make kill-on-debugger-exit policy explicit and test failure handling; never leave an attached debugger or suspended child while doing unrelated analysis. If detach is used on any error path, first restore owned debug state and verify detach/child state; a detach call alone is not a cleanup receipt.

Do not close user applications or restore installed originals. No GUI control is acquired, so debugger detach/process exit is not described as GUI-control release. Finish with fixture digest equality, exact-child terminated/absence qualification, all handle dispositions, and no remaining owned debug session. Preserve uncertainty if verification fails.

This one-run design can identify the first observed outer null predicate while preserving the CP205 comparison boundary. It cannot establish observation neutrality, successful original Save/Close, allocation subcauses, or authority for a converter behavior change without its qualified result.
