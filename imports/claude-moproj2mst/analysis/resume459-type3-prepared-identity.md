# CP459 private ShapeOptim prepared identity graph

CP458 bound concrete linked-property construction, factory publication and ordinary operation disposal to 6,005 matching original-PE bytes. It did not establish the selected current operation or intervening link history at an imported Open. CP459 therefore adds a private prepared identity graph and resolver, not a public Type3 lifecycle route.

The graph keeps class, operation, property and data identities separate. A prepared construction records a new property with its creator class and an independently allocated data identity initialized to int 200 and double 0.001. Other explicit prepared postconditions select an operation, publish the supplied factory-return property to OPI+10, or replace/reset a class's linked OB+b0 property independently. The resolver obtains current P through class.currentOperation→operation.property and linked B through class.linkedProperty. It passes P's ordered tree and data to the CP455 property-tail helper, and obtains B's refresh source from B.creator and sink from B.data. Equal property or data identities preserve aliasing; neither is inferred from matching dynamic type. Invalid prepared references are refused before effects. A missing data identity passes through to CP455's delayed write-boundary refusal.

Independent source review found no blocking issue. Its optional combined cast-failure/null-P-data case was not needed for this checkpoint because the existing tests separately cover cast failure with refresh and delayed null-data refusal, and the code selects the cast branch before dereferencing P data. The eleven focused cases cover defaults, matching and diverging P/B histories, reset, independent creators, shared and distinct data, cast failure, missing references/data, invalid IDs and rejected prepared publication. The earlier `mirror_plane_owner.hpp` introductory comment was also corrected to describe CP457's exact-capacity path; no behavior changed there.
