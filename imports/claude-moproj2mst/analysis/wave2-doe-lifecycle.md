## Constructor and activation order

1. Subproject constructor `0x1400b5470` allocates a manager for Type2/3. Derived constructor `0x1400d1180` uses `0x140919b80`, owns its SP, sets initial `DoeStudy<id>` name and invokes directory creation before XML study-name parsing. Initial sample mode0/count100 and three invalid flags are recovered; mode1/2 count fields are not explicitly initialized.
2. Lazy subproject parser `0x14008f530`, Type2/SfDoeStudy branch, calls `0x1400d2aa0` for name, `0x1400d3970`→`0x14090e080` for InputTable, then `0x1400d7a80` in mode order0/1/2 for Samples_LHS/FF/USR, then `0x1400d7820` for DEF_DOE.PAR. Those callee return values do not abort the parent parser; it eventually returns true. Preserve effects and partial state rather than making all reads transactional.
3. InputTable reader opens ReadOnly|Text, sets a global error string on open failure and returns false; malformed XML closes/returns false. It does not itself show a dialog in that body. Child readers overwrite the accumulated return status, and header values may already have changed. The current header-only helper is not a complete reproduction of those failure/status details.
4. The load-like Samples routine actually calls the writer on an empty local table. Successful opens truncate/create the Samples files to mode-header-only text. If the requested stored table was nonempty, it clears the current table but validates the requested flag. Open failure must skip that memory change. An effect list planned for later cannot substitute its eventual result here.
5. DEF_DOE.PAR reads into a local table and directly into manager mode. Id-only rows are dropped; after success its current table becomes valid and count becomes the number of parsed rows. Thus historical120's100 empty vectors reload as an empty valid design; its initial requested100 is overwritten to0. The invalid flag prevents the ordinary ensure-design routine from resampling it. This is a static prediction, not a measured original resave.
6. Selected DoeOutput load `0x140e2e320` resets/sets the model dimension from the preceding operation (or reverse operation search), shows it in the viewer and calls `0x140e2ec40`. The latter obtains the SP session document, resets it with `0x140644fd0`, reads Control/<base>.DS via `0x140645dc0`, then processes it through `0x140644440(doc,1,0,0)`.

The .DS reader updates its remembered filename before open. Failed open or zero-length file returns void with prior/default DOM; nonempty input resets DOM before QDomDocument::setContent. Parse failure therefore does not restore the old DOM. Type2 constructor flags make its document root PartRoot; successful processing finds SessionRoot descendants, creates part records, selects entity0 and resets current session index to-1. `0x140659d90` reads SessionRoot operation range/entity/display fields and optional export flags, then `0x140650e60` parses Sessions. Task factories and selected viewer/task application are still required for a complete headless lifecycle; retaining XML alone does not establish that those state transitions occurred.

## Current-operation Save effects precede project/control Save

`0x140e2e730`, DoeOutput vt+0x68, does the following before calling its vt+0x80 `.DS` writer:

1. `0x140e33210` requests mkpath of Control/Regions through `0x14081afb0(...,true)`.
2. With a model, `0x14081b400` clears entries under Control/Regions. It skips dot entries; directory children go through recursive helper `0x14081b2b0`, regular-file removal results are ignored. The top Regions directory is retained. Do not replace this with deleting an arbitrary computed root.
3. It independently removes existing Regions/Common_Mesh.Key and Regions/Common_Mesh_User.Key, ignoring removal failure.
4. ROI0 chooses the former filename, ROI1 the latter. A nonempty selected name and nonnull cached common-mesh object gate geometry output `0x140895f30`. The no-region/ROI0 case requires proving that object is null; it must not simply invent a mesh.
5. It invokes current-operation helper `0x1400543a0`, then vt+0x80 `0x140e2fcd0`.

`0x14081afb0` **returns true unconditionally**, even when QDir::mkpath fails. On failure with warn=true it shows an Information box with a single button and text containing “Can not make the directory %1.” The caller continues after dismissal. The apparent checks in later `0x1400ba800` therefore do not abort on those mkdir failures. Full dialog/default behavior for other warning paths is not inferred from this one-button branch.

## .DS Save can preserve ordinary DOE payloads

`0x140e2fcd0` gets Control/<base>.DS and the active SP's lazy session document. It locates SfTaskDoe, synchronizes manager object/operation selections, regions and constraints from current model/task state, then invokes `0x140645030(doc,path,0)` even when task lookup did not produce a task. The document must be nonnull; earlier project/SP absence branches do no write.

The document constructor initializes flag+0x68=1. `0x14064a830` therefore takes refresh `0x14064ab80`. It records current viewer image in memory and updates part range/display metadata. For task names **Custom** or **SfTaskDeformMetalFlow**, it invokes full Session serializer `0x14064fc30`; ordinary **SfTaskDoe** instead takes `0x14064aa80`→`0x1406530f0`. That routine finds the nth existing Session child, updates Title/Type/Subtype/DB_ID/Steps/StepNumber/Objects/TaskType/EntityNo attributes, and only delegates task vt+0x228 for an existing child named SfTask. Consequently Image/StepData/camera and other children are not indiscriminately regenerated on this branch. A preserved **input DOM** is a viable starting representation; copying historical expected .DS bytes is not.

SfTaskDoe vt+0x228 is `0x14140d2e0`. It only processes existing SfTask children: OprList and ObjList are replaced through vt+0x250/0x258 when their corresponding task lists are nonempty, OutputList invokes vt+0x270 when nonempty. Missing lists are not appended by this routine. Direct fixture inspection corrects an earlier report: historical120 **does contain** Session/SfTask, with OprList operation5, ObjList object1 and empty OutputList. Its StepData contains StateVar only. This updater is therefore relevant for that input. Loading, selecting and potentially replacing its task/model still need faithful treatment; preserving all task children unchanged is not justified.

Part metadata update `0x14065a9b0` finds a SessionRoot by PartEntityNo (QString::toShort), then sets OprStartNo/OprEndNo/PartEntityNo/DisplayName. Session update finds children by ordinal, not Title/TaskType. Preserve those different addressing rules.

Final writer `0x140645030` sets the path, refreshes DOM, conditionally saves linked documents, then opens QFile WriteOnly without Text, selects UTF-8 and writes QDomDocument::toString(1). It closes/checks QFile error but returns void on all branches. Open failure skips target write; preceding state/linked effects are not rolled back. LF output is source-derived here, not a newline normalization exception.
