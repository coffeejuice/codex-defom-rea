The host qualification requires one outer entry/normal return on the owned primary TID, one invocation, contiguous sequence/counts, correct caller/frame/RSP and main/path delta, ordered normal helper returns, raw pointer/AL predicate agreement, and stable exact 34-unit QString witnesses at outer entry/return and acceptance entry/return. Missing leaves, snapshot failures, extra/reordered events and observer errors fail completion. Rejected unrelated callers are counted but do not by themselves invalidate this selected occurrence. An early prerequisite failure may yield `openObservationComplete=true` while `encodedPathQualified=false`; the final capture predicate requires both. The monotonic five-second endpoint starts immediately before the single resume command. An outer-return message, first AV, observer error or deadline ends observation; a late outer return cannot satisfy the endpoint. The owner then receives `{"command":"terminate"}` and stdin closes. The independent 20-second helper watchdog includes setup and cannot count as successful completion. Helper cleanup requires signaled exit, closed handles and helper exit zero; the host also requires drained complete JSONL, settled unload/detach, retained raw receipts, and successful Windows plus same-device Frida absence checks. PID reuse is reported without killing the new PID. The native receipt has two normal-return then idle cases with `0xe201` cleanup, natural early exit 42, a deadline cleanup and a pre-resume rejection cleanup; all five report closed handles, helper exit zero and dual absence. The idle fixture is a Sleep loop, not a Qt event loop.

## Release conditions and limits

1. Keep this PASS bound to the exact frozen runner/includes/helper and the reviewed five-byte patch mode. Any changed callback, gate, fixture, lifecycle logic or installed runtime identity requires focused rereview. The literal review guards must be enabled only for this one recorded command and disabled again immediately afterward; record the released runner and generated-agent hashes.
2. Immediately before launch, confirm installed v11.0.2 EXE/Qt hashes, runtime identities, and fresh clone/source manifest equality; confirm `p213a` has no hard links or escaped entries and paths stay below 100 characters. Stop on any difference without repairing or overwriting the fixture.
3. Admit resume only after the exact held child identity, loaded-module checks, all six prefix/patch receipts and independent host patch gate pass. If setup exhausts the helper watchdog, if the actual redirect is not the reviewed five-byte shape, or if any read/identity check fails, retain incomplete receipts and terminate the owned child without a second attempt under this release.
4. Preserve the exact endpoint, intentional held-handle cleanup, bounded drains, raw messages, before/after manifests and both independent absence results. A qualified observation with failed cleanup is not capture complete; successful cleanup with no qualified outer return is not an Open observation. Review the original capture independently before making a behavioral claim.

This PASS authorizes only the narrow trial's technical readiness. The strongest supported result would be a fresh instrumented owned original CLI occurrence receiving the exact B98 path, recording its prerequisite/acceptance returns and outer result, followed by verified intentional cleanup. It cannot establish full project initialization, XML/read success, Save, accepted Close or scientific parity. The GUI-control release gate is separate: this runner acquires no app-control session, and Frida detach or child termination is not a GUI-control release receipt.
