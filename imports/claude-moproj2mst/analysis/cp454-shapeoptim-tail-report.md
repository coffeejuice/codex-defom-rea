# CP454 ShapeOptim tail: ordered prepared-value successor is source-closed

The tail after CP452 can be implemented as a private normal-path value projection over prepared, ordered property display names, with an ordered diagnostic event and an explicit optional final refresh. It cannot establish Type3 owner publication or permit public Type3 Open/Save. Keep the owner, GEO and Save guards listed in CP452.

## Exact normal control flow

The outer project/SUB gates and optimizer-null branch remain the CP452 contract. Once project and SUB exist, the following tail runs even when the optimizer is null; in that case the retained incoming `OB+cc/+e0` values are available to it.

1. `0x14013de34..de68` obtains the current operation's properties through `1405ef2b0` then `140051230` and dynamic-casts from type descriptor `143579b60` to `1435b4c20`. A null result branches directly to the final +b0 handling at `0x14013e48d`; it does not return from the consumer.
2. For a successful cast P, `140353770(P+10,out)` copies the list at `P+18`. The iterator constructor `1401408e0 -> 140140a10` copies that list, initializes control int +8 to zero and obtains begin/end through the verified QListData imports. `140dfc080` increments the control int and permits an iteration only if its prior value was zero and iterator != end. Each body's trailing decrement allows the next iteration. `140de9800` advances the iterator pointer by eight bytes. `140dd75b0 -> 140619750` obtains the pointer stored in the current list slot. Thus the normal domain is list storage order, including duplicates, without sorting or deduplication.
3. For every top-level pointer, `14036fcc0` obtains a QString display name. The consumer constructs QDebug at `0x14013e088`, inserts that name at `0x14013e0b6`, and destroys QDebug at `0x14013e0c5`, **before** testing the name against the PE-bound ASCII `StopCritGroup` string at `0x14013e0da`. Every visited top-level display name is passed to QDebug, including nonmatching names and duplicates. This binds the calls and order; exact emitted bytes, quoting, sink, handler and newline policy belong to Qt and were not observed.
4. Only a top-level display name equal to `StopCritGroup` causes `140370f60(top,out)` to copy the child list at `top->payload(+8)+58`. Children use the same iterator pattern in storage order. There is no recursive descent into grandchildren and no child-name qDebug call in this tail.
5. The child's `14036fcc0` display name is compared first against `MaxSims`, and only if unequal against `MinObjFuncVal`. A match to MaxSims reads the current `OB+cc` into EDX at `0x14013e333`, calls `QVariant(int)` IAT `141e05998`, and passes the temporary in R8 to `1401424e0(P,child,temp)` at `0x14013e37d`. That helper ignores child, calls `QVariant::toInt(nullptr)`, stores its int result at `P->data(+38)+8` at `0x140142515`, then destroys the QVariant.
6. A match to MinObjFuncVal reads **double** `OB+e0` into XMM1 at `0x14013e3bb`, calls `QVariant(double)` IAT `141e05808`, and passes its temporary to `140142580(P,child,temp)` at `0x14013e407`. That helper ignores child, calls `QVariant::toDouble(nullptr)`, stores XMM0 at `P->data(+38)+10` at `0x1401425b2`, then destroys the QVariant. The decompile's `_N` label is a type-recovery artifact: PE import `??0QVariant@@QEAA@N@Z` and XMM1 establish double, not bool.
7. Other children have no destination write. Every matching child is visited, including duplicates and children of repeated StopCritGroup entries. Values go into the same P data object, not into each child's own value field. Child QString/list/reference cleanup finishes, then top-level QString/list/reference cleanup finishes before +b0 handling.
8. At `0x14013e49c`, `140c1aef0(OB+b0)` returns the first qword at that address. If null, the consumer returns. Otherwise the getter is called a second time at `0x14013e4b5`, and its result is immediately dereferenced and dispatched through vt+58 at `0x14013e4d5`, with no second null check. This getter does not promote a weak reference or retain ownership.

`14036fcc0` is a display-name getter, not an unconditional raw-name accessor. The verified body checks signed payload+48 against -1. For values <= -1 it copies the backing QString; for nonnegative values it builds a `%1` decimal representation of index+1 and passes backing name plus that representation to `1400048f0`. The latter combination helper and exact Qt formatting behavior were not expanded here. Therefore a source-closed private helper should take already prepared display names. Matching a raw base name without this qualification could admit an indexed/decorated property the native comparison does not admit.

## Final refresh and distinct owners

The consumer's only guaranteed target is nonnull +b0's dynamic vt+58. Retained `vtables.tsv` identifies `SfOprShapeOptimProperties` slot +58 as `140142ca0`; this concrete helper is newly PE-byte-bound. If its object B has null class pointer `B+40`, it writes nothing and returns true. Otherwise it writes, in order:

- int `B->class(+40)+cc` to `B->data(+38)+8`;
- double `B->class(+40)+e0` to `B->data(+38)+10`.

The cast property object P, the +b0 object B, their data pointers and B's class pointer are not proven identical by this consumer. For the concrete selected helper, final refresh can overwrite earlier P-data writes when their data aliases, and its source can differ from current OB. Do not silently force B's class to OB or merge both property sinks in a private model. The exact +b0 dynamic target/lifetime remains an integration dependency; arbitrary vt+58 behavior is outside a selected concrete helper.

## Native failure/partial-order contract

This void consumer has no success result or transactional rollback branch. Dynamic-cast failure and first +b0-get null are explicit benign branches. All visible native dereferences assume valid inputs: no check occurs for a null top/child property pointer, backing payload/name pointer, P data pointer, second +b0 result, B data pointer or nonnull-but-invalid B class pointer.

In particular, P+38 is **not checked before traversal**. An empty tree, no StopCritGroup, or only unmatched children can reach final +b0 handling without touching P data. The first recognized child triggers the selected setter's QVariant conversion, then its data dereference/store, then temporary destruction. An unconditional candidate refusal for missing P data changes the observed action prefix by moving refusal before top-name qDebug and before determining whether any setter is needed. Current `report.cpp` contains that conservative early guard and omits an actual qDebug emission; this report does not edit it or demand native invalid-pointer behavior from safe private code.

Earlier successful optimizer-prefix writes/appends, top-name debug calls and completed setter stores precede any later fault/throw. A failure in a later child does not imply rollback of an earlier setter. If failure prevents normal completion, the final +b0 call is not reached through the visible normal path. B's first int store precedes its second double source read/store, so even its refresh is two ordered effects. This evidence resolves explicit normal branches and store/call order; it does not determine Qt allocation/detach failure, QDebug handler reentrancy, OS fault handling, or C++ exception unwinding/cleanup. Those require the called dependency or unwind/runtime evidence and are not reproduced by std::vector exceptions or invented safe native return values.

## Smallest useful successor

A private prepared-value helper may accept ordered top-level display names plus ordered child display names, seeded maxSims/minObjective destination state, current OB scalar inputs, and an explicit optional concrete linked refresh with its own source and destination identity. It can emit an ordered value event trace: `debug(topDisplayName)`, `setMaxSims(value)`, `setMinObjective(value)`, then optional linked refresh int and double writes. Keep repeated writes/events; read values at their native effect points if callbacks or aliasing are supported. A smaller stable-value profile may prohibit callbacks/reentrant mutation and document that restriction. It must not claim to reproduce Qt log serialization or invalid-native-pointer failures.

Meaningful tests include no cast props but linked refresh; empty/nonmatching trees; top-name debug before all child writes; no child logging; duplicate groups/children in input order; names differing only by case or prepared suffix; a MaxSims match and a double MinObjFuncVal value that distinguishes bool conversion; missing P data with no matches versus first match (a modeled refusal must occur at the effect boundary); distinct P and B destinations; shared destination overwritten by B from a different class source; B class null; and the final refresh's two-write order. A failure-injection event test can preserve completed preceding effects without claiming native Qt exception parity.

Native property acquisition/list sharing, display formatting, dynamic +b0 publication/target/lifetime and failure recovery remain the smallest dependencies for broader native parity. They do not block the private normal-path prepared-value contract. Type3 SUB+28 owner construction/publication/teardown and .OPT streaming remain CP452 integration gates. Study-folder/GEO read/write and Save optimizer update guards remain unchanged. No conclusion here enables public Type3 Open/Save.

Only new `analysis/cp454-shapeoptim-tail*` files were written. No source/test/build/deployment/plan/state edits, original execution, GUI/app-control acquisition, or mutable shared REA/Ghidra project operation occurred.
