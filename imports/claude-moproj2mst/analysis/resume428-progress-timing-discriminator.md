# CP428 progress I/O timing discriminator

CP427 observed exact WORKER exit code zero after CP333's terminal-read timeout, with runner progress ending at `worker_ack:4657`. CP330 samples that remaining time before calling CP420's synchronous `write_progress`; the latter flushes and fsyncs the stage before CP330 checks the original deadline and enters CP329 `complete_success()`. This ordering creates a source-level liveness path independent of the WORKER protocol: diagnostic I/O can consume the remaining budget. CP427 does not prove that its fsync took that time.

Two injected-clock tests bind the boundary without launching a process. A writer that advances the fake clock to the unchanged deadline only at `worker_ack` causes CP330 to hold at its next `_budget()` before calling CP329 success completion. It retains one resume, INIT and one ACK frame, the original ACK-unconfirmed receipt and no `worker_closed` marker or accepted success. A writer that advances only to one millisecond before the same deadline still reaches exact worker completion and `closed-success` in the injected harness. These tests show the timing sensitivity and preserve the original deadline; they do not measure filesystem latency in CP427.

Dual-root injected validation passed 657 CP3xx tests and eight CP4xx tests from each root. The next narrow repair is to reduce synchronous durability work on post-ACK diagnostic stages, version the sidecar identity, and explicitly retain the limitation that ordinary file open/write/flush may still block. It must not relax protocol, owner, deadline or success gates. No original app or GUI was controlled.
