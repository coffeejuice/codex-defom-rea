# CP225: object-storage mutation routes and the next identity batch

The useful next identity increment is a private, pure incarnation-transition helper with focused tests. A small patch confined to `GuiModel` cannot yet make an `ObjectKey` a certificate of live object storage: native imports and KEY hooks can destroy whole lists below the wrapper, while public `step` and raw getters still permit unobserved mutation. Keep live-key issuance/admission and R300 cache1 continuation closed.

This is a read-only source/evidence audit. It recommends work; it implements and compiles nothing. Root confirmed the CP221–224 snapshot as `38c82884` before this report was written. Paths below are relative to this converter subtree unless a shorter application-relative prefix is explicitly stated.

## Evidence and meaning of currentness

Reviewed `AGENTS.md`, `TAKEOVER.md`, the current takeover cursor, `resume223-object-key-contract.md`, CP222's editor-closure architecture, StepIdentity implementation/review, loader/editor/viewer alias ledgers, and CP224's two leaf recommendations. Inspected current application mutation callers and their concrete native-port callees, rather than inferring mutation from getter names alone.

The existing `StepIdentity` in `source/apps/moproj2mst/include/m2m/engine.hpp` and `src/engine/gui_model.cpp` observes a weak model control block and an instrumented generation. Reset advances that generation before `viewerClear`; destructor retirement precedes cleanup. `tests/mdt/test_step_identity.cpp` deliberately demonstrates that public `model.step.reset()` leaves the observation current and that `GuiModel::reset()` on the resulting null step is a no-op. That is the supported staging qualification, not a defect silently repaired by this audit. No existing consumer may promote this observation into native access authority.

The final CP223 contract needs three independent facts: the actual model owner, the current storage generation, and the current object incarnation. Number, sparse position and address are lookup observations, not substitutes for those facts. A future consuming named command must validate all three immediately before resolving a local native pointer. A successful earlier `isCurrent()` query must never grant later access.

## Why the apparent small live batch is unsafe

Adding issue/retire calls only to `objectWrap`, `appendObject`, `reset`, `deleteObject`, and the outer `readKey`/`readDbEntry` functions misses placeholder creation, post-parse dimension replacement, sim-control/inter-object imports, companion keyword targets, and additional trailing deletion. A registry reconciled by scanning after return cannot distinguish removed/recreated nodes at reused addresses; it also cannot revoke a key before a native virtual callback during destruction. Entry invalidation of every import instead changes non-destructive failure/equal-dimension semantics and unrelated-key stability. Neither is the CP223 live contract.

The exact blocking dependency is owner-aware notification at each native destructive boundary **plus** eventual removal of raw owner-storage bypasses. No static search can turn a retained raw object pointer into an admitted operation. Before enabling live-key consumers, freeze the logical binding policy for empty-node reuse and full-copy payload replacement, map KEY companion/target models to their actual owners, and preserve native preflight/failure/effect order at the lower boundaries. Do not add a process-global pointer-to-GuiModel registry or change native object layouts simply to make a small patch appear closed.

## Smallest useful compiling batch: private metadata transitions

This safe batch is the narrower fallback explicitly allowed by CP223. It exercises the state machine needed later, without presenting synthetic observations as live-model currentness.

Exclusive implementation owner: new `source/apps/moproj2mst/src/engine/object_identity_metadata.hpp`. Define a private implementation helper containing an inert value identity, weak owner-control-block identity, storage epoch, monotonic incarnation allocation, and an explicit binding discriminator. Binding discriminator must distinguish numbered lookup from list/position observations; a position is a hint, never identity. The helper accepts explicit transition requests on metadata only: observe an established binding, retire a binding, retire all/advance epoch, and retire owner. Repeated observation reuses an active incarnation; reestablishing a retired discriminator allocates a fresh one. It must contain no native model/object pointer, resolver, callback, list traversal, native effect or model lifetime extension.

Keep this helper unused by production in the first batch. Do not add public `ObjectKey::isCurrent`, model lookup/issuance, or fields to `GuiModelLifetime` yet. Name the tested predicate `matchesMetadata` (or equivalently explicit wording), not a claim of native liveness. This deliberately smaller deliverable provides tested retirement/allocation/equality/overflow semantics without changing native effect order or creating a misleading API contract. The later model-owned ObjectKey can use the reviewed helper after event wiring is source-qualified.

Exclusive test owner: new `source/apps/moproj2mst/tests/mdt/test_object_identity_metadata.cpp`. Use the source-relative quoted include `../../src/engine/object_identity_metadata.hpp`: `m2m_core`'s `src` include directory is PRIVATE and is not inherited by ordinary tests. This exact relative include resolves from the proposed test location. Use Testkit, `int main() { return testkit::run_all(); }`, `CHECK`, `CHECK_EQ`, and `REQUIRE`; no C `assert` or nonexistent `REQUIRE_EQ`.

Test the helper's actual semantics: inert/foreign owner refusal; weak-owner expiry and reused model-address surrogate with fresh control block; repeated metadata observation; retire/reestablish same number with distinct incarnation; distinct sparse discriminators; retire-all invalidates every old entry; independent bindings survive a single retirement; copied identities do not extend owner lifetime; max-minus-one/max exhaustion rejects before changing metadata and never wraps. Make bounded counter state injectable only in this private helper or parameterize its arithmetic for tests; add no production-visible mutation hook to `GuiModel`.

Root owns CMake/registration and integration. Current `source/apps/moproj2mst/CMakeLists.txt:129-153` uses `CONFIGURE_DEPENDS` globs and derives `m2m_mdt_object_identity_metadata` / `m2m.mdt.object_identity_metadata` from the filename; no registration edit should be necessary. Root must confirm actual configured registration, compile the new focused target and run it with `m2m.mdt.step_identity` as one focused group. Hold all source owners through the full launcher and `admin/freeze_checkpoint.py` hash-bound candidate freeze. This report neither schedules nor runs those checks. No changes to public C ABI, native layout, R300, loaders, viewer, shared recovery cursor or installed artifacts belong to this batch.

The batch is useful only as tested transition machinery, not as proof that a model-owned object's incarnation is observed. If root prefers a production consumer migration immediately, the ready alternative below removes an actual raw alias site while the native-boundary policy is resolved.

## Alternative ready migration: explicit dimension owner command

Add a named `GuiModel` dimension-setting command in `app/include/m2m/engine.hpp` / `src/engine/gui_model.cpp`; migrate the `g_loaderSlots.setDimension` lambda in `src/engine/class_slots.cpp` and the raw setter in `src/engine/l6_slots.cpp` in the same batch. Preserve the current geometry guard, null-step qualification, equal-dimension no-op, and native virtual setter order. Do not replace the base-before-free native sequence with a reset-first implementation. This is a staged owner command, not full key invalidation coverage: KEY hooks/imports continue to invoke native setters below it. If it advances CP222 observation metadata, document exactly these two covered routes and preserve exhaustion-before-effect ordering; do not update the public comment to claim all dimension routes are covered.

Root should assign one owner for the shared model files and both callers, with tests in an explicitly assigned focused Testkit file. `tests/mdt/test_l6_slots.cpp`, `test_l5_loader.cpp` and `test_step_identity.cpp` provide surrounding regression targets; add focused equal/changed dimension, preserved defaults, guarded refusal, and existing null behavior checks only where they verify meaningful mutation/admission behavior. Reinspect call sites and the native setter before choosing exact test placement. No caller-removal patch should precede the owner API declaration/definition.
