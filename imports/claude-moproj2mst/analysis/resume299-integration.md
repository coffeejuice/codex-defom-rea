# CP299 original palette initialization

CP299's immutable-original PE audit traced the palette constructor wrapper through the startup constructor table and the indexed initialization loop. The wrapper pointer at `0x141e0c938` is slot 28 of the entrypoint-traversed table; normal successful traversal calls `0x141ca0b20`, which initializes the palette through `0x1402d5010`. This is conditional static control-flow evidence, not a witnessed original Open occurrence. No original process, GUI control, mutable REA or converter source was used.

The loop's false settings-lookup arm uses a 92-case jump table. Slot 12 points to `0x1402d3318`, which fills a temporary with three binary32 RGB words `0x3f05e354` (0.5230000019073486f) and a fourth word `0x3f733333` (0.949999988079071f); `0x1402d5141` copies that 16-byte temporary to the actual slot. A distinct settings-result arm converts runtime QColor redF/greenF/blueF/alphaF to binary32 and stores all four fields instead. The loop can also skip a slot when its constructed key is empty. An independent immutable-PE check confirmed the jump-table target, constants, conditional copy and alternative getter arm. Later audited mutator callers target slots 14, 15, 20 and 21, which does not prove absence of all slot-12 mutations. See `analysis/resume299-palette-initialization-static.md` for exact addresses and byte-span receipts.

The fallback tuple is source-ready as a **conditional** private value. It is not an unconditional initialized color or a callback-time value: runtime settings, constructor completion and same-occurrence ordering remain unknown. Public initial rendering remains guarded.
