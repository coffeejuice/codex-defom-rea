# CP173 independent R300 barrier review

## Decision

A staged source migration can preserve the converter's documented C ABI and the currently observed CP163 behavior while closing the two named C++ raw-borrow surfaces. It cannot do so by making `GuiModel::step` private as the first isolated patch: direct uses across the engine and ops tree would fail to compile. It also cannot publish zero-length cache1 until a model-wide parked-state gate protects every supported route that could consume the partial step. Keep CP163's refusal immediately after A publication during the access migration.

The smallest **first compileable cut** is to remove the internal `opStep(Project&, Operation&) -> DB_STEP_DATA*` escape and migrate all of its current callers to one synchronous, void/bool-return callback helper. This cut closes only the `opStep` return surface; it does not install the Stopping barrier, privatize `GuiModel::step`, or advance the native reader. Retain `opModel` lookup timing, nullable-step behavior, call order, return values, diagnostics, and file effects. In particular, the two `loadMaterials` writer paths must not move their step acquisition earlier across item mutation, and `syncFromModel` must retain its current ordered nested calls. A callback may still capture its argument, so every migrated lambda needs an explicit no-escape review. Do not silently route this first cut through `GuiModelAccess::withStep`: that helper currently adds a geometry refusal which `opStep` does not, changing existing behavior.

The second stage migrates all direct `GuiModel::step` reads/writes to a narrow synchronous access seam. Only after every owner compiles without direct access should the declaration be made private *without moving its declaration relative to other data members*. A new fixed-size barrier can be appended within `GuiModel` for internal state; adding a member changes C++ object size and must not be described as preserving binary layout. `Operation::engineModel` can retain its shared ownership/identity semantics. A later stage composes geometry and Stopping availability, gates top-level load, editor, display, reset and Save routes before effects, and only then permits the zero-length cache1 cut. The public `simCtl()`, `object()` and `objectAt()` methods also return mutable raw pointers, so private `step` plus scoped `opStep` is not a proof against previously obtained aliases. The supported serialized model-thread contract and alias lifetime must be established, or the whole operation and outstanding borrow period needs a real gate. A flag around barrier metadata alone is insufficient.

## Exclusive first-cut ownership and acceptance

Reserve exactly these four source files to one owner for the first cut: `source/apps/moproj2mst/src/engine/engine_internal.hpp` (callback declaration/template and constrained return), `source/apps/moproj2mst/src/engine/loader.cpp` (helper removal and its callers), `source/apps/moproj2mst/src/engine/loader_l2.cpp`, and `source/apps/moproj2mst/src/engine/db_load.cpp`. No other source or test owner should edit them until their patch is integrated and source-stable. The helper may pass a nullable pointer inside the callback to preserve each caller's current behavior; it must never return that pointer or a reference to it. Prefer a callback result limited to `void` or `bool`, as the existing `GuiModelAccess` concept does, and inspect captures/returned closures for escapes. `loadMaterials` currently performs two conditional acquisitions; preserve the reached branch's timing, using one scoped borrow for its selected writer call.

Acceptance for this first cut is: (1) a scoped search over all `source/apps/moproj2mst` finds no `opStep(` declaration, implementation, or call; (2) each migrated callback is synchronous, returns only void/bool, stores no step pointer, and preserves null paths, including the current unchecked `slotMaterialsFromMesh` path; (3) the focused CTest targets `m2m.mdt.loader_l2`, `m2m.mdt.db_load`, `m2m.mdt.simcontrol300_stopping_cached`, `m2m.s.save_current`, and `m2m.g0.abi` pass against a source-bound build, with the existing loader/material/DB fixture outputs compared where they cover the changed paths; (4) the C export names and `M2M_API_VERSION` remain unchanged; and (5) a source-stable full suite/freeze is run by root after integration under the project's checkpoint rule. Tests that do not actually enter a changed writer or missing-model path cannot establish their parity; add one focused fixture only if the existing tests lack that coverage. No tests or build were run for this review.

Rollback for the first cut is to revert only that owner's four-file patch to the recorded pre-cut hashes, restore the `opStep` declaration/definition and its callers together, and rerun the affected focused tests. Cache0, the existing A allocation and CP163 refusal must remain unchanged, so rollback requires no step/fixture cleanup or new original capture. Do not use a test failure as reason to publish cache1 or to restore any installed program.

## Closure gate before cache1

The CP173 inventory is a useful search map, not a proof of all aliases. Its `opModel` note needs one exact qualification: `loader.cpp` can return `c->classModel(p, op)` *before* the `op.engineModel` lazy-cache path, so the later availability gate must check both return branches. `GuiModel::objectCount()` currently reads `step` without the geometry guard, confirming that guard coverage is not yet uniform. `saveCurrentOperation` and `saveProject` also have effects around model lookup; a gate at a late step borrow is insufficient for pre-effect refusal. The first cut must not claim these routes closed.

Before the zero-length store, require a clean direct-step audit after privatization, a separate audit of `engineModel` and raw object/SimControl aliases, an entrypoint/effect-order map for Save and DB replacement, and a no-throw barrier install/publication path. The pending bit must be visible before cache1 under the established serialization contract. The frame must be nonowning, tied to the actual model/step and receipt, retired only on model destruction in this parked cut, and never used to dereference stale project/reader/node tokens during retry. Focused barrier tests must prove one query/A production, zero-only cache1, no arrays timer/recipient/Stop effect, sequential retry refusal before cached success, reset/reload/display/Save refusal before effects, safe changed owner/receipt rejection, and single step-owned A cleanup at model destruction. Positive/negative selected lengths remain cache0 and refused. Retain CP161/163 negative and existing-A cases. Then run focused Stopping and lifecycle/snapshot regressions, followed by root's source-stable full suite/freeze.

Unsupported today: concurrent or nested reentry safety; complete raw-alias closure; exact original allocator failure parity; original same-occurrence public Open/Save reachability; normal reader-tail completion or resumability; and C++ binary/source compatibility for external consumers. The static zero branch supports the conservative parked candidate only. The GUI-control release restriction still prevents a new original-runtime witness. No GUI, live REA, mutable evidence, build, source, fixture, or deployed program was touched in this review.
