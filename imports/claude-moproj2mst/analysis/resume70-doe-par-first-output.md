# CP70: Type2 PAR output gates through first design sample write

## Scope and result

This is a static trace of the original Type2 continuation after `signalDoeTableRefresh()` returns normally. It does not establish that the current candidate can return from that refresh: public `subProjectElement` still throws at the guard, and no GUI receiver is fabricated here.

The order is current selection file `Control/DEF_DOE.PAR` (`0x1400d75a0`), then LHS mode 0 (`0x1400d7790`, `Samples_LHS.par`), followed by FF mode 1 and USR mode 2. `DEF_DOE.PAR` is the first post-refresh write; `Samples_LHS.par` is the first design-table write. Native call windows and bounded wrappers are in `resume63-doe-public-save-call.asm`, `resume63-doe-public-sample-calls.asm`, `resume64-doe-current-samples.asm`, `resume64-doe-mode-samples.asm`, and `resume64-doe-sample-writer.asm`. Original PE SHA-256: `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`.

## Gates and exact continuation

1. The caller is the public `0x140099040` Type2 arm selected by exact SUB type 2 and its sixth argument 0. It obtains the active SUB's manager at `SUB+0x20`. A null manager skips the study node and DOE file sequence and reaches common DB-name output; a non-null manager is cached for the arm.
2. It appends the pending `<SfDoeStudy>` node, calls `0x1400d3200` for InputTable output, and that wrapper calls `signalDoeTableRefresh()` unconditionally after the XML writer, regardless of the XML Boolean. **Normal callback return** is required to continue. An exception/refusal/fault retains already reached cleanup/XML/file/error effects and leaves all subsequent sample writes unreached.
3. After normal return, `0x1400997b2` calls `0x1400d75a0` for the cached manager's selected current table and path `DoeStudies/<name>/Control/DEF_DOE.PAR`. At `0x1400d75c8..5d9`, native reads selected mode from manager `+0x40` and directly indexes the invalid byte at `manager + mode + 0x70`; true skips serialization, false continues to path construction and the `0x1400915290` writer. The bounded body shows **no mode-range guard before that indexed read**. Treat malformed mode as an unqualified native memory case; candidate code's safer out-of-range refusal is a reconstruction boundary, not an observed native branch. A valid empty table is still written.
4. The public arm next calls `0x1400d7790` three times in fixed order: mode 0 at `0x140099a77`, mode 1 at `0x140099d7c`, mode 2 at `0x14009a081`. The first call targets `Samples_LHS.par`. For each, `0x1400d7790` first checks explicit mode `<0` or `>=3`; invalid mode returns false before file I/O. Otherwise it reads that mode's invalid flag at `manager + mode + 0x70`; invalid returns false. If valid, it passes that mode's table and path to `0x1400915360` through `0x1400915290`.
5. The common sample serializer opens the target with QFile WriteOnly|Text. Open failure returns false. Successful open truncates/writes in place, emits mode header plus CRLF even for an empty table, emits one-based row numbers and tab-delimited values for rows, closes, and returns true without converting a later close/write error into false. There is no rollback or atomic replacement. These ordinary Boolean results—including the XML result, current `.PAR` result, and mode-0 sample result—are not used by `0x140099040` to cancel the next phase. A true invalid flag skips only its one file; a failed open similarly does not stop later mode calls. A thrown unsupported callback/fault is distinct from an ordinary false result and does stop execution at that point.
6. After mode 2, the helper appends common `Subproject_DbName` and returns the pending child element. Only then does the parent replace/append the old `Sub_Project` DOM node and stream/close the `.moproj`. Thus a later refusal preserves previous file effects and the already-open/truncated project-file prefix, while DB-name, child replacement and final project bytes remain unreached.

## Minimal helper admission

The candidate's `doe::saveSampleTable` is admissible only as an isolated **serialization/validity helper**: it matches the 0..2 validity test, per-mode invalid skip, and valid-empty header behavior. It currently appends complete bytes to `FileEffects`; there is no production call site, and that bucket is discarded by the native Save body's local `unused` effects object. It does not implement the immediate QFile open/truncate/close contract or a public ordered attempt receipt. Therefore the smallest useful admission is to retain/test this helper at unit scope and, when orchestration is later authorized, wrap one mode at its native sequence point in the existing StudyIo output path with an explicit open-failure result and ordered effect record. Do not wire it into public Save before actual refresh return is qualified; do not treat the diagnostic FileEffects payload as proof of a written file.

The already-existing `saveCurrentSamples`/`saveSampleTable` candidate also has a range check for the selected current mode, unlike the bounded original `0x1400d75a0` prefix. Preserve that safe refusal while native out-of-range semantics remain unqualified; do not claim byte-for-byte behavioral equivalence for malformed state. The active valid-mode sample output branch and the public receiver lifecycle are separate closure requirements.

## Evidence limits

The call-site windows establish fixed order and mode arguments; the bounded wrappers establish the ordinary mode/invalid gates and writer call; retained sample I/O contract records the file-open/empty-table behavior. Static captures do not establish fresh original runtime execution, actual active-manager contents, current filesystem outcomes, or a normal DoeTableRefresh return. No source, test, build, GUI, original application, or mutable REA state changed.
