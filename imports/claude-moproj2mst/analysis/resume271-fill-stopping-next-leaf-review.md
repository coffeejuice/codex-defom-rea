**PASS — the one-expression substitution preserves the Fill entry's admission and effects in supported synchronous execution.** No required design correction found. Keep the test/provenance qualifications below explicit.

Reviewed CP271 against current `fillStopping3DInto`, its optional wrappers, `applyStopping3D`, current model dimension/numbered-object implementations, snapshot partial-fill cases, lifecycle retaining call site, and CP270's distinct Apply review.

The old prefix `!model.step || model.step->dimension != 3` refuses absent storage or every live dimension other than three. Existing unguarded `dimension() const noexcept` returns zero without storage and the actual live integer otherwise, so `model.dimension() != 3` has the same refusal set. Do not substitute dimensionOr(3), normalize dimension, create a step or add another geometry check. Equivalence does not claim safety under concurrent storage replacement or undefined lifetime states.

Keep `model.object(0)` as the next `||` operand. For absent/non-3 storage it remains uncalled. For live three, its geometry guard is reached before the native numbered lookup; parked three therefore throws before locale/profile/page effects, even if locale or retained widget state would later refuse. A present object numbered zero still returns InvalidModel. Do not remove that query based on its usual null result or move locale/profile checks before it.

For parked absent/non-3 cases the dimension query does not throw and InvalidModel remains the result. Do not interpret this early scalar refusal as bypass permission for Stopping/cache1 continuation. For ordinary live three with no object zero, keep locale admission next, retained-widget profile next, then report stage Scalars and the existing SC scalar reads/page writes. The proposal's “no scalar read” should be understood as no **supplied control scalar** read; the initial dimension is itself an intentional model scalar read.

An early initial InvalidModel refusal is mutation-free for the supplied page/control.
