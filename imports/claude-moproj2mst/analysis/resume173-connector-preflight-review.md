# CP173 QVector increment preflight against frozen CP172

## Decision

**The proposed `[0x1311d2, 0x1311da)` cut is source-ready against the accepted CP172 frame.** The shipped QtCore instruction performs one locked 32-bit add at the exported `QVectorData::shared_null` RVA `0x2f0bb8`. CP172 already binds that root-owned symbol at private `+0x68` and stops before the add, with `qvectorSharedNullReferenceCommitted == false` and no QVector delta change. CP173 must add exactly one symbolic `uint32_t` reference delta, mark that private frame committed, and stop at `BeforeSecondQListBinding` / `0x1311da`. It cannot infer a live absolute count from the PE-initialized DWORD.

This preflight uses the frozen CP172 source receipts from `analysis/resume172-finalfix-build.json` and `analysis/resume172-connector-source-review.md`: factory `92245bc591766eb68b748cc636dcc2bba96672a3bd93b183d3ee3aff9f70086a`, runtime header `31a1c9c52418a6ea775b2d5822feb13be170c3e54e98a632698b72c80a0b28b1`, root header `db71dd022911a4214768a93f742a17cf4bda1237c87401b3d999df8e57354a3e`, and factory test `025bfd98911a7b2b9f662d46805c5c02de54ee8574e2df3113d4dce4b1d49df8`. The worktree had already moved beyond those hashes when this note was written; this is a contract review, not acceptance of the newer implementation. The CP172 focused build and tests passed on a stable source tree. `analysis/wave3-checkpoint172-validation.json` records the later checkpoint with explicit historical-oracle and test-permissiveness qualifications.

## Exact admission and effect

The continuation must start on the same retained pending Report and allocation-time private pointee at `BeforeQVectorSharedNullIncrement`, with task/private sizes `0xc0`/`0x88`, written address-point RVAs `0x23cac8`/`0x1a9d10`, and private `+0x40`, `+0x48`, `+0x50`, `+0x58` each observed zero. QObject and base remain incomplete, and both backlinks unavailable. The factory's live `WidgetRuntimeState` must be the allocation store's associated root by pointee and control block. Its committed, pointer-identical QList `+0x18` and QString `+0x30` bindings must remain qualified. The private `+0x68` weak binding must lock to the same root-owned QVector record by pointee and control block, qualified by QtCore SHA-256 `bcf0074c7e9fba3bcafdaa38742931f309889cbdbacffbca32af83db237fc160` and symbol RVA `0x2f0bb8`, while its marker is false. All of these checks precede any write.

On admission, only the root QVector `referenceDelta` advances by one modulo `2^32`, the private marker becomes true, and the phase advances to `BeforeSecondQListBinding`. A preexisting root delta is valid; a seeded `0xffffffff` must become zero. Keep the binding and root/private identities, four zeros, QList/QString deltas, optional observations, maps/counts, completion, and backlinks fixed. The next `mov [rbx+0x70],rcx` and the later second QList add are outside the cut. The current model has no `private70` observation, so the cursor plus unchanged QList delta is the available boundary assertion.

## Focused acceptance matrix and fixture hazards

1. Use an actual `ConversionSession` root pairing and a retained CP172 frame. Snapshot identities, all three symbols and deltas, any observation fields, four zeros, flags, bindings, phase, and task/prototype/cache state. Verify one continuation has only the three permitted changes; then same-key and different-key reentry refuse with no second add. Add a near-wrap case without requiring a zero starting delta.
2. At the exact CP172 increment seam, inject one defect per case: absent, expired, foreign, aliasing-foreign, or wrong-control-block QVector binding; malformed symbol qualification; expired root; prior QList/QString marker or binding defect; missing/nonzero predecessor zero; bad address-point value or written flag, size, retained Report/private identity or kind; already true vector marker; wrong phase; and premature completion/backlink. Snapshot before each refusal and compare all three root deltas, private bindings/markers/fields, phase, allocation and map counts, and completion/backlinks afterward. A foreign **factory root** cannot reach this retained seam through the public API because a different factory creates a different Report and is stopped earlier; do not claim that test exercises this guard. A wrong or missing root-owned QVector record is likewise not injectible through the current immutable root API; the supported malformed qualifier and private-binding faults provide reachable coverage.
3. Migrate every ordinary first-call/reentry assertion from `RVA 0x1311d2` / `BeforeQVectorSharedNullIncrement` to `RVA 0x1311da` / `BeforeSecondQListBinding`. Keep `0x1311d2` only for an intentionally reconstructed CP172 pre-increment state or for the increment guard diagnostic. Older tests that rewind a post-call frame to CP169–CP172 must restore a coherent predecessor: clear the committed vector marker and `+0x68` binding where appropriate, and account for the already increased root QVector delta in expected snapshots. Use a fresh root/fixture when a zero-delta premise matters; do not silently relabel a post-increment root as an untouched CP172 root. Hold any original private pointee through clone-identity refusal snapshots, and ensure expired-root tests release all root strong owners while symbol references alone remain live.

The two plan documents agree on the native instruction, owner, symbolic arithmetic, and stop. The earlier plan-review caution about a tautological CP171 pointer expression was repaired in the accepted CP172 source; CP173 still needs an actual bound-versus-root comparison at its own seam. No source, test, build, GUI-control, original-process, live REA, or shared-state operation was performed for this note.
