# CP80 independent review: QString path-owner source

## Assessment

The new owner is a carefully scoped **diagnostic reference-profile ledger**. It correctly distinguishes unknown counts from known counts, does not substitute C++ observer copies for reference increments, rejects a missing shared-null profile, and reproduces the selected alias arithmetic for explicitly supplied counts. Its API comments and test title correctly avoid claiming original live counts.

It does **not** yet satisfy the actual owner integration prerequisite in `resume80-doe-qstring-path-ownership.md`: `observeInput` accepts a copied `qt::String` plus caller-supplied optional count and free-form qualification; `bindSharedNull` validates the QtCore hash/RVA then creates a new per-`QStringPathOwner` record from a caller-supplied count/profile. There is no handle to the actual resource QString slot/data ref, no Session/process owner, and no shared-null identity across scopes. Two owner instances can each bind the same module/RVA and produce distinct identity/counters. This is coherent for separate isolated arithmetic fixtures, but it cannot be used to cross the first native QString mutation or claim the process-global `QString::shared_null` object.

## Specific contracts checked

- **Alias/reference arithmetic:** `adoptExistingInput` installs an active lease without increment; `acquirePathAlias` accepts only an Input with no backslash and adds one; `copyAlias` adds one from an active lease; shared-null acquisition uses a distinct record; release subtracts once and guards when decrement reaches zero. The B121-relevant no-backslash branch is explicit. Observer `QStringPathData` copies do not alter reference words.
- **Unknown versus zero:** an unknown count remains `std::nullopt`, and acquire/adopt/release paths refuse before destination/lease mutation when a native count is unavailable. A known zero is not accepted as a live input/shared-null observation, but release-to-zero remains a known optional value and sets `dataDeallocationPending` before raising the unsupported-free guard. It does not silently turn unknown into zero or an invented initial 1.
- **Shared-null profile:** exact module SHA `bcf0074c7e9fba3bcafdaa38742931f309889cbdbacffbca32af83db237fc160` and RVA `0x2f0b30` are checked; the test rejects the QByteArray RVA `0x2f0900`, a different image, unknown-count acquisition, and a second bind within one owner. Equality is actual record identity only inside the owner scope, not a cross-scope/process singleton.
- **Cleanup order:** the test constructs input temporary, filename alias and native-path shared-null lease separately and explicitly calls `release(temporary)`, then `release(nativePath)`, then `release(filename)` while checking counts. The static native destructor order for file entry is native-path slot then filename. This primitive owner does not label file-entry slots, journal release events, or enforce that order; correctness of this sequence is caller-driven. A later composite file-entry object must encode and test that ordering before claiming destructor parity.
- **Zero/free boundary:** the zero test consumes the lease/decrements to zero, sets pending and refuses actual data free, with no repeated decrement. `text()` remains available from the diagnostic record after that guard; treat it only as retained historical diagnostic text, not access to live native QString data.
- **Admission/integration:** source references show only the new owner header/source/test use these types. No reference to the private QFileInfo prefix, `QFileInfo`, resource icon path, public converter, `Study`, `StudyIo`, or constructor admission was added. This isolation is required. It remains before the private-file-entry/engine boundary.

## Recommendation

Accept the arithmetic as an isolated mechanics/profile seam, with the integration boundary explicit in the implementation report: it is not an actual QString owner and cannot advance `DoeFileInfoPrivateArena` beyond `QStringPathOwnership`. Before native-prefix progression, replace or bind the input record to the actual source QString data/slot owner and provide a single Session/process-owned shared-null identity for this QtCore image. Preserve explicit unknown counts until a real observation supplies them. For cleanup parity, add a typed file-entry slot aggregate or an ordered destructor-action recorder that enforces native-path-before-filename rather than relying on test call order.

No source edits, builds, tests, GUI actions, or mutable REA access were performed. This review file is the only written artifact.
