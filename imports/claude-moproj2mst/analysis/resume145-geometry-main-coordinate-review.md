No concrete blocker found in `resume145-geometry-equal-width.md`. The proposed cut produces a real, owned fresh destination after the native reset, then stops before BC allocation, variable sizing and equal-width copy. It does not complete the node allocator/helper/first reader. This accepts the design for source work; released implementation and root validation remain required.

The native order is correctly identified. Null object+8a8 reaches140837080, which calls the real free/reset wrapper140837300 ->140853350 before entering allocation140854200. Reset nulls coordinates and **all seven** BC pointers at node+f0..120, writes node-class n/+12c and+13c=0 and clears the registered variables. The current port has those seven fields and clears them all. Only six are allocated by the later BC loop; this distinction does not affect the proposed stop.

At14085424d the native fixed admission computes1*3,140854250 calls the diagnostic double allocator,14085425d publishes node+8, and140854261 begins the next key/BC phase. Node-class n is not set to1 until140854342; variable sizing is14085435b. Calling whole `bc::alloc_node_arrays` or `obj_read_node_arrays` would cross real unimplemented effects. The proposed direct `bc::calloc_doubles(3)` after real `bc::free_node_arrays` preserves the selected bounded allocation/publication while leaving n0, BC/variable slots empty and no copy.

Admission must remain confined to the current initial high frame after actual source A/cache1 and arrays checkpoint, with the actual installed frame/control block/current step/DB/receipt and internal source-A pointer/count still matching. Fixed object count1, first1 and actual D[0]=stored width3 make prospective copy offset0/length3; requiring produced extent>=3 excludes a short source without inferring capacity from nominal header fields. The exact live selectors exclude every other region block. Actual same-step owner and caller state/flag/MAR/null/type7/byte3610 order remain before the new branch. No low/null caller or later cache1 refresh may acquire this producer admission.

The empty-storage guard is sufficient for the planned existing clear when implemented exactly: real same-owner node collection, coordinates null, n0, seven BC pointers null,28 data slots null, canonical collection count/types/ids and each variable's u30 bound to its correct actual node slot. Collection and each empty values body must have unique ownership before clearing. `Cls_140329c70::reset_all` uses mutating COW element access, and `StateVarBase::clear` detaches its vector and republishes null through u30; these uniqueness/binding checks prevent unknown COW allocation or foreign-slot writes in this admitted profile. Type/id checks alone would not suffice, but the plan explicitly includes the needed checks. Read-only count/element APIs are available for qualification.

After real reset, revalidate frame/source/object/owner/count/D identities before calloc; a dispatcher test mutation must retain reset effects and park before publication. The actual main node class owns the new buffer. Frame pointer/count are observation only; they must not become a second owner or a generic destination-ready capability. On allocation-null retain diagnostic/null publication and stop. On success retain the installed model barrier and stop immediately: no BC array allocation, class-count publication, sizing, copy, node Stop, high-frame retirement or builder getter. The existing barrier already prevents reentrant/parked refresh or mutator calls from replaying the consumed reset/allocation. Post-reset stage reporting must not claim a reset completed if the call did not return.

The test plan distinguishes the new prefix from old refusal and full completion: real same-step secondary object without another view; actual source extents3/6; real destination extent3; one coordinate COW/arrays checkpoint; n0 and seven BC/28 variable slots still empty; timer2/unknown scene; stable pointers on retries and raw-field repair; and a real clear-dispatch callback that invalidates a guarded fact before allocation. The negative owned/preexisting sentinel destination, short source, wrong count/first/width, shared/nonempty/foreign-bound registry and foreign-owner cases exercise the admission boundary after earlier source effects. Mutated owning pointers must be restored with RAII before actual object/step destruction.

Both fresh buffers start zero, so zero-content assertions alone cannot detect an accidentally inserted early zero-to-zero memcpy. The distinct count/sizing/timer/continuation checks plus direct implementation inspection for no copy remain necessary; this is an observability limit, not a concrete design blocker. No production-array seeding or fake allocator receipt is needed. Existing CP144 zero-main completion/cached behavior and CP141 null-DB mismatch must stay unchanged; a main presence change after cached reader return must not synthesize delayed assignment.
