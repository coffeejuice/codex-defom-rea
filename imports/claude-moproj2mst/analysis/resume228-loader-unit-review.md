# CP228 loader unit owner independent review

## Verdict: PASS

The implementation preserves the specified construction and mutation order. `newModel` evaluates `projectDb(p)` and constructs one `std::shared_ptr<GuiModel>` with `dim`; `GuiModel` constructs its step and runs `guiSimCtrlInit(step->sim_ctrl)` before construction returns. The loader then calls `m->setModelUnit(p.unit, true)` and returns that same shared pointer. The method delegates directly to `def::key::set_model_unit(*step, unit, reset)`. There is no move into construction, factory, pre-equality check, reset-flag change, or catch. Constructor failure precedes the setter; any setter exception propagates through this function and C++ unwinding releases its local shared owner. The latter is a source-derived consequence, not a runtime-tested failure case.

The native setter source makes the behavior explicit: if the unit differs, it stores the new unit and, with reset true, calls `reset_unit_defaults`; if equal, it performs no mutation. The owner test compares changed-unit fields with an independently initialized model passed through the native setter, and compares equal-unit behavior while checking a seeded reset-sensitive value remains unchanged. The loader test calls the installed `g_loaderSlots.newModel` function pointer, which is the narrow seam to the production `newModel` callback; it checks changed and equal `Project.unit` results. The changed path's reset defaults and equal path's constructor defaults are consistent with the GUI initialization followed by the setter. The test uses Testkit macros and no C `assert`.

No finding: C ABI headers/exports and cache1 storage/publication are not changed by this CP228 patch; the implementation remains an internal C++ owner method. Review is source-level and does not establish original-runtime equivalence or injected exception behavior. The shared working tree contains unrelated edits in `engine.hpp` and `gui_model.cpp` for adjacent increments, plus other files; those are outside this CP228 verdict and must remain separately owned during integration.
