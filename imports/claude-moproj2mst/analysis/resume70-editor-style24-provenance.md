# Style24 null-image provenance and the public editor boundary

No new public style24-null admission is justified by the retained evidence.
The native conditional path and same-owner helper integration are recovered, but
original editor probes003/004 selected style1. They supply no style24 embedded
image, active-painting word or QPaintDevice cleanup-global value. The next safe
public implementation depends first on the actual post-Open private palette/font
producer and lifecycle-state join; substituting startup observations would bypass
that missing edge.

Only this report was written. No source, build, CTest, GUI, original execution,
mutable REA or new raw captures. Token usage is unavailable. Source remains
frozen. This audit complements resume70-editor-font-tail-inputs.md rather than
relabelling its captured style1 values as a texture observation.

This covers the specific active-source/null-data cut integrated in CP65/66.
Source painting word0 is another null copy route with fewer inner temporaries;
it must not be called active merely because the returned image is null. A null
image with a present pixmap cache first enters conversion and cannot use the
no-cache cut. Likewise B+90 nonzero selects pixmap regardless of a convenient null
image field. Unknown fields cannot be normalized to these branch values.

Both inner J and outer I1 QPaintDevice destruction use the module's canonical
RVA9cb858 counter owner, not any brush/image reference count. The admitted existing
nonnull counter==0 cleanup path needs its actual live module and value. Null
imageData does not imply counter0, nor does it skip destruction. Nonzero/warning,
lazy allocation and unknown owner/value branches retain their guards. An active
word with null data is a native conditional branch, but valid public UI production
of that combination has not been established or disproved by this audit.

A bounded scan of normalized messages in editor probes001..004 found selected
integer brush-style values only in003/004, and only value1. The first two capture
profiles do not supply the style24 field family. Probe004 explicitly captured:

- Records23..25: same QWidget bit17 change and raw120-false native helper return.
- Records27..36 and state3/state1: actual font/thread/DC/metric and pre-count

Probe003 corroborates the same path with its own native identities: selected

it is not evidence for any style24 source word/cache/data or cleanup-global value.
No actual capture associates B+78 or the canonical cleanup counter with the
selected public editor. The existing CP48 report explicitly preserves this limit.

## Exact post-opacity transitions and their scope

The selected-null conditional suffix joins6506e75b, the same caller point as the
captured solid-brush suffix. It no longer reads the selected brush. The exact
sequence is:

1. On a changed opaque bit, complete65097940. Actual window/raw120false returns;
   the bounded bit11-clear path also returns without platform handle/style calls.
   This return does not create a QThread, DC, font or widget counter value.
2. Pass SAME QWidget+10 and private+180 font into651f2e30. Its virtual metric8
   obtains application QThread through QObject::thread and current QThread through
   QThread::currentThread;65099181 compares the actual objects. Equal chooses
   cached displayDC6507f9d0; unequal reaches the separately guarded foreign DC path.
3. DC cache lookup precedes metric override/parent logic. With known positive
   cached DC, no GetDC allocation is performed. For this base QWidget, absent or
   zero DPI-Y override and null parent select GetDeviceCaps(DC,90).
4. Compare returned metric with actual FontData+38 and require +3c0. Match shares
   the same FontData and mask. Caller assigns then destroys the temporary before
   any widget-count increment; mismatch needs unrepresented font-data copy.
5. Set raw34/35, then6506e7ab..6506e7c9 increments shared current count with native
   uint32 wrap and compares signed32 against maximum. Compatibility follows,
   then actual Create dispatch and raw0x4a posting dependencies.

Captured editor004 values are QThread objects both0x3490b90 (record30), cached DC
0x11011293 before/returned (31/32), metric168 (33), FontData0x4748690 with mask0,
field38=168/3c0 before and after (27/34), extra absent/parent null (state3), current

compileVersion0x40804/attributes0. Probe003 supplies its own matching identities
and the same numeric values. GetDeviceCaps itself was not hooked: its DPI168

The admitted active-null/zero-cleanup prefix makes no direct font, display-cache,
QThread or QWidget-count write. Its private opacity/destruction and source/module
reads do not authorize invented values in those other owners. If actual current
inputs were separately supplied for a selected-null call, the same tail consumes
them without another brush read. That compositional statement does not transfer
historical values between captures or prove the unobserved public producer.

## Existing runtime seam and smallest next public boundary

Current source has definitions of observeTextureImageInputs and
observePaintDeviceCleanupInputs, but no production caller that supplies those
observations for the public Session. The editor hook correctly calls the runtime
source interner after selecting the actual brush; that interner establishes
identity and ownership, not missing native payload fields or current counter0.
Isolated test profiles deliberately provide those inputs.

Public beginEditor300Factory binds the actual Project/Operation/GuiModel editor
to the same Session WidgetRuntime, then still requires PrivatePaletteUnavailable.
Its earliest missing input is the actual current default palette owner for that
receiver, followed by font/locale/application context. Existing startup Values
are a FIRST SplitView profile, not a post-Open editor profile. The private observer
also rejects a different current shared default owner; passing an editor fixture
alias is not a permissible replacement for it.

There is therefore no evidence-closed public-session style24 branch to enable in
this lane. The smallest responsible public successor is the producer/lifecycle
join BEFORE PrivatePalette: recover how the actual post-Open application palette
and font become the private constructor's current owners, preserve their mutation/
replacement ordering and qualify the selected slot. Only if that slot actually
has style24 should the existing texture observers bind its payload and module
state; otherwise the captured style1 branch is the faithful selected branch.
An unconditional default style24/null state would contradict the captured input.

The tail mechanism already supports the actual editor through
observeConstructorTailValues(actualEditorWidget,o), validating its same interned
font and receiver/runtime. It does not need a surrogate SplitView/MainView.
However, public startup current173 becomes174 after its recovered tail; observed
editor current760 cannot replace it through equal/unknown-only mergeObserved.
Recover intervening QWidget construction/destruction effects or explicitly admit
a current-stage state through a source-qualified producer; do not reset counters
at SharedTail. QObject count, image refs and cleanup count are separate owners.

A bounded follow-up investigation should trace the actual palette/font producer
across Open and current shared-owner replacement, then enumerate the intervening
QWidget current/max transitions. Until that join exists, preserve the public
private-palette refusal and all later queue/wrapper gates. A local style24/helper
pass is not a public Open-Save-Close acceptance result.
