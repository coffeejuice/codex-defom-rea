# CP164 editor300: next Stopping reader cut

## Decision

The next native operation after CP163's A publication is an **actual-step selected-length read** at `140828248`: `S.u2b28[id]`, where this Stopping path has already bounded `id=11` inside the 280-entry step array. The read alone changes no state and cannot advance the reconstructed getter. On length zero, the first new effect is `S.u26c4[11]=1` at `140828265`. That cache write is **not a standalone source-ready stop**: a fresh invocation could see cache1 and return from the already implemented cached path without the original call's arrays checkpoint, main-object assignments, node-timer Stop or outer return. CP163 has no Stopping-owned pending-call guard. The smallest meaningful next implementation is therefore a Stopping-owned durable barrier **installed before the zero-length cache write**, then the zero-length cache1 commit and immediate guarded refusal. Until that barrier's lifecycle and all entry checks are implemented, retain the CP163 after-A refusal.

## Minimal owner-bound barrier contract before cache1

The missing prerequisite is an implemented, reviewed **Stopping-owned model/step/node/DB/receipt pending-call state**. It must identify the actual `GuiModel`, its current `step`, selected main object and canonical node set, the leased Project.dataDb/reader, signed directory index and current allocation receipt, selected region 11, queried/post-query version, published A pointer and observed allocation count. Install it with a no-throw or failure-before-effect transition while cache11 is still zero; failure to allocate/install the barrier retains CP163's refusal and does not mutate cache. Do not use a page-local flag, a raw step pointer alone, or the viewer's geometry frame as the owner.

Every entry that can consume or expose the pending step, including a fresh Stopping getter and relevant model/session paths, must reject or retain the pending state **before** the cache1 shortcut, low-version shortcut, reset/reload or public Save path can act on it. Its stage must distinguish A published, zero-cache committed, arrays timer committed, per-main-recipient progress and completed reader/outer return. No later call may replay a committed query, allocation, cache write or timer checkpoint as though it were a resumed native stack. Keep the frame parked on unresolved continuation and uncertain exceptional outcomes. Release it only after the same owned call's complete required tail is proven, or retire it with the actual model/step lifecycle; retirement must not free A separately from step ownership. A changed Project lease, directory generation, step or node must refuse without dereferencing stale identities.

This barrier is an adapter design obligation, not an observed original data structure. Its implementation needs its own source review and focused owner/lifecycle checks. The existing geometry barrier illustrates the kind of model-wide gate and stage proof but provides no Stopping ownership or recipient authorization. If a complete same-call reader and getter tail is implemented instead, this parked barrier may be unnecessary; the empty-length branch alone does not establish such completion.

## Acceptance for the next bounded cut

With the barrier in place, preserve all CP163 gates and order. After normal A publication, read actual `S.u2b28[11]`. On **zero only**, commit actual `S.u26c4[11]=1`, record the zero-cache stage, and refuse under the installed barrier before the arrays timer. On nonzero, leave cache0, arrays timer, header/MAR/A contents and object coordinates unchanged and retain refusal; the body path remains unopened. A normally returning null allocation publishes null as CP163 already specifies; it is not proof of original allocator-failure parity and must not authorize a cache write without the defined owner contract. A preexisting A from a prior partial invocation remains parked/refused rather than allocated again.

Focused tests should bind a real Project/ProjectScope and current physical directory receipt to the actual S and canonical node, then cover selected lengths 0, positive and negative (native compares to zero, so negative belongs to the nonzero body branch and remains refused). On zero, assert one cache1 write after one query/A producer, arrays timer byte-identical, no Stop or assignment, and pending state retained. A fresh page retry and every relevant public/model entry must refuse before cached success and must not replay query, A allocation or timer work. Exercise model reset/destruction, Project/reader replacement and receipt retirement without a stale dereference or double free. Preserve CP161/163 low-version, owner/index, header, count, cache-hit and existing-A controls. Build the focused Stopping target and source-stable regression only after source review; none ran in this lane.

The nonempty branch cannot use directory sizes as body extents. Before `140b38d57`, bind the actual `140816170` path/part owner and first-step/slot conversion, the real file handle, the actual S header/MAR/A allocations **with producer extents**, and the selected `u1dc0[11]` span. Main-object assignment and node-timer Stop still remain after it.

The present blocker is the **source lifecycle barrier** for the next cache write; it is not uncertainty about the zero-length native instruction order.
