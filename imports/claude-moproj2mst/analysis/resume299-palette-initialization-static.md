# CP299 palette initialization: conditional slot-12 default

The immutable original `DEF_GUI_MO_64.exe` installation v11.0.2 is 67,611,136 bytes, SHA-256 `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`. This is a read-only preferred-VA PE/DUMPBIN 14.44.35228.0 audit. No original execution, GUI control, mutable REA, converter source edit, or build occurred. The report concerns no reconstructed DEF_PRE executable. CP296's strict PE mapping and callback qualification remain controlling.

## Initial image versus initialized palette

Palette base `0x143d77590` plus index 12 times 16 resolves to `0x143d77650`. The `.data` raw-backed RVA ends at `0x03d76400`; slot-12 RVA `0x03d77650` lies `0x1250` bytes into its virtual-only tail. The loader initially zero-fills that image span. These zeroes are not the post-constructor RGB and cannot be substituted for callback inputs. CP287's earlier purported slot bytes belonged to `.pdata`, as CP296 corrected.

The palette static-initializer wrapper at `0x141ca0b20` passes base `0x143d77590` to `0x1402d14f0` at CALL `0x141ca0b2b`. A raw `.rdata` QWORD at preferred VA `0x141e0c938` (file offset `0x1e0b138`) points exactly to `0x141ca0b20`; it is slot 28 (zero-based) in the startup pointer table. The PE entrypoint `0x141470dc0` enters startup `0x141470c28`; its CALL `0x141470d53` reaches `0x14146e780`, whose loop traverses pointer cells `[0x141e0c858,0x141e14d88)`, skips null entries, and invokes each nonnull entry at `0x14146e7ee`. The palette pointer lies within that range, so normal successful CRT traversal calls its wrapper in table order before returning to the caller. This does not establish completion when an earlier constructor or this wrapper fails, or a later runtime snapshot. The wrapper's callee calls `0x1402d1530` at `0x1402d14fe`, which calls `0x1402d5010` at `0x1402d153e` and then `0x1402d2200` at `0x1402d1508`. The separate `0x141df46a0` passes the base to `0x1402d1520`, whose entire six-byte body is `48 89 4c 24 08 c3` (no palette store); this path does not supply an RGB initializer.

`0x1402d5010` loops integer indices 0 through 91 (`cmp [rsp+24h],0x5c` at `0x1402d5064`). At each index `0x1402d53d0` constructs a key from decimal `QString::number(index,10)`, literal `_` at `.rdata` VA `0x1422daeac`, and literal `displayOption/dispEntityColor` at `.rdata` VA `0x1422ddd00`. Under the imported QString concatenation order, index 12's key is `displayOption/dispEntityColor_12`. The loop skips an empty constructed QString at `0x1402d5092..5097`. Otherwise it converts the key to local 8-bit text, calls `0x140809270` at `0x1402d50d6`, and selects the static-default arm when that call returns false (`0x1402d50de..50f9`, `0x1402d510e..5111`). `0x140809270` first calls a virtual receiver method at `+0x58` with the key and, only on a true result, uses imported `QSettings::value` at `0x140809326` and a conversion/assignment into the supplied QColor. Thus the selected color depends on runtime settings, receiver behavior, and Qt conversion. The static RGB literal applies only to the false-return arm.

On the true branch, `CVTSD2SS` results from `QColor::redF`, `greenF`, `blueF`, and `alphaF` are written to `base+index*16` at `0x1402d516b`, `+4` at `0x1402d5190`, `+8` at `0x1402d51b6`, and `+0xc` at `0x1402d51dc`. Index 12 addresses are exactly `0x143d77650`, `0x143d77654`, `0x143d77658`, and `0x143d7765c`.

The false-return arm `0x1402d5113..5146` first calls `0x1402d2ed0(base,index)`. That function uses a 92-entry jump table at RVA `0x02d4b8c`; entry 12 is raw target RVA `0x02d3318` (preferred VA `0x1402d3318`). Its four `MOVSS` stores at `0x1402d3325`, `0x1402d333a`, `0x1402d334f`, and `0x1402d3364` fill shared scratch `base+0x83c/+0x840/+0x844/+0x848`. RGB use `.rdata` VA `0x1421ebc74`, bytes `54 e3 05 3f`, binary32 `0x3f05e354` = `0.5230000019073486`; the fourth component uses VA `0x1421ebc68`, bytes `33 33 73 3f`, binary32 `0x3f733333` = `0.949999988079071`. The common tail at `0x1402d4b7b` returns `base+0x83c`; `0x1402d5141` copies those 16 bytes into index-12 destination `base+0xc0`. Thus **the source-ready default branch** sets slot-12 RGB to `(0x3f05e354, 0x3f05e354, 0x3f05e354)` and fourth component to `0x3f733333`. It is conditional on the settings lookup returning false. The true branch can replace all four components from a runtime QColor. The next `0x1402d2200` stage begins with stores at base+`0x84c`, outside slot 12; this bounded prefix alone is not a complete audit of that stage.

The exact color branch's RGB imports are IAT `0x141e089c0` (`QColor::redF`), `0x141e089b8` (`greenF`), and `0x141e089b0` (`blueF`), as independently qualified by CP296. `0x141e089a8` supplies the fourth component here. This is a conversion of a runtime QColor into four binary32 palette fields; the callback's zero-mode path later reads the palette fields directly and does not invoke QColor getters.

## Other writes and callback order

`0x140ddc160` is a general indexed RGB mutator: `redF`/`greenF`/`blueF` are converted to binary32 and stored at `base+index*16` at `0x140ddc1aa`, `+4` at `0x140ddc1ce`, and `+8` at `0x140ddc1f3`. Its identified callers `0x140ddc0c0` and `0x140ddc210` pass fixed indices `0x15` (21) and `0x14` (20), respectively, after owner and color-validity guards; those calls do not write slot 12. `0x140ddc2b0` has guarded direct RGB writes for fixed slots 15 and 14 at `0x140ddc37a/399/3b9` and `0x140ddc3d8/3f7/417`, plus slot-15 fourth-component store at `0x140ddc455`; it also does not establish slot 12.

The CP296 callback at `0x14126a620` looks up slot 12 twice in zero mode, at CALLs `0x14126a653` and `0x14126a685`, then packs the three binary32 RGB components from each returned address. It does not cache one immutable palette triple across those calls. No static proof excludes mutation between them or establishes a fresh initial-bind occurrence after successful palette construction.

## Result and remaining evidence

A source-ready **conditional default** RGB triple is proven: three binary32 words `0x3f05e354`, copied to slot 12 if the selected settings lookup returns false. No unconditional initial or callback-time RGB triple is proven. A true settings lookup uses the actual QColor conversion, and the branch outcome and resulting values are not in the immutable PE. The later fixed-index mutators above exclude only their own slot-12 writes, not all possible indirect or subsequent mutation. The callback performs two palette rereads. Public color integration must remain guarded until slot-12 values and same-occurrence ordering are qualified.
