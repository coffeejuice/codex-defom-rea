# CP460 Type3 imported Open identity: registry and selection path

The static trace closes how imported operation creation and operation loading resolve the same registry and how a selected OPI is passed into the ShapeOptim consumer. It does not establish that the linked property B equals the selected operation property P in an actual imported Open occurrence. There is no new basis for public Type3 admission.

## Evidence boundary

`cp460-type3-open-identity-byte-verification.json` binds 11 new complete PE exception-function ranges, 1,459 addressed instructions and 8,452 bytes, with zero mismatches, to imported original `evidence/original-binaries/DEF_GUI_MO_64.exe`, SHA-256 `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`. `cp460-type3-open-identity-verify.py` reproduces the bounded dumpbin exports and independently compares every addressed byte using PE section mapping. Each export ends at RET. None repeats a CP458 export. The receipt binds relevant imports, the three concrete ShapeOptim vtable slots, and source/decompile/reference hashes. CP454 and CP458 source qualifications remain in force.

This work read the original only. No original process, GUI/app-control session, native REA/Ghidra project, build or test was run. No source, plan or state was edited. The direct E8/E9 scan is deliberately recorded as byte candidates, not an exhaustive decoded call graph. It found the constructor-to-reset call at `14013aa26`; virtual dispatch, aliased writes, Qt notifications and transitive callees cannot be ruled out by that result.

Static structure alone does not supply that event history for a project.

## Why equality still cannot be promoted

CP458's factory changes OB+b0 independently of OB+20. Nothing in the newly bound selection helper or the specialized wrapper visibly relinks OB+b0 to OPI+10. Under the explicit stable-registry and no-callback profile, two live operations with the same ShapeOptim class key can be created as `(OPI1,B1)` then `(OPI2,B2)`, making OB+b0=B2; selecting OPI1 makes P=B1 while B remains B2. This is a conditional identity countermodel supported by separate native stores, not a witnessed real fixture or a proof that every imported project admits two such operations. It is enough to show that same class type or registry equality does not logically imply P=B.

There are unresolved calls before the consumer, particularly the engine virtual call `14013bfbd`, operation helper `140054820`, engine reset `140c7b720`, and scalar initializer's transitive helpers. Inside the consumer, CP454 also binds a qDebug call per top-level name, followed later by two independent linked getters. An arbitrary diagnostic handler can affect identity after P was acquired. No selected function alone proves no native callback or replacement across these intervals. Absence of direct E8 reset callers outside the constructor cannot close indirect calls, guard invalidation, or raw alias writes.

## Smallest source-closed increment

A private, stable prepared registry/selection adapter may resolve an explicitly supplied class key to an explicitly supplied OB identity and request current selection of an explicitly supplied OPI identity. It must retain linked-property identity independently. CP459 already provides that graph separation and selection postcondition. The new evidence supports attaching native lookup/selection provenance and testing a two-creation/first-selection prepared history, without modelling Qt ownership or granting public input admission. If extending a prepared load prefix, model two ordered scalar-initializer calls around an explicitly external engine effect; do not clear +b0 as part of scalar init. No implementation was changed in this lane.

## Exact minimal same-occurrence witness

The following is an evidence design only; GUI/runtime acquisition remains blocked by the supported release gate.

For a selected copied project and one fresh owned original process, bind original binary SHA-256, PID/process-start identity, input hashes, loaded module base, a monotonic sequence and thread/depth IDs. Use actual runtime addresses derived from the recorded base. Follow one operation occurrence from imported parser return `14008d05e` through consumer return. Pointer addresses alone need lifetime generations so reuse after deletion is distinguishable.

A compact complete witness needs these correlated boundaries:

- Registry/factory publication: capture the relevant `140047c00` return or its `140070650` return with class key and manager/OB identity; the ShapeOptim factory `14013be10` entry/return; and `1400511f0` entry/normal return binding OPI, supplied B, OPI+10, B+38 and B+40. Reuse CP458's factory contract rather than dumping complete objects.
- Relevant mutation history: from the first selected creation until consumer return, log every `14013be10` and `14013ab00` entry for the tracked OB; every `1405ef280` for it; every `1400511f0` or `1400512c0` for the tracked OPI; and relevant `140cbc920`/`140cbc900` calls whose guard-storage address is tracked OB+20, OB+b0, OB+b8 or property+20. Capture normal returns and resulting guard qwords. Also log tracked property/class destructors (CP458 addresses) and retain uncertainty for any thrown/aborted call. A targeted write watch on the actual pointer storage, or an equivalent proven-complete trace, is needed to exclude replacement through paths beyond these named helpers and to see Qt-driven invalidation.
- Selection/consumer: capture OPI and OB at `14005182b`, the effective vt+58 target at `140051843`, OB at `14013bfdf`, and entry/exit of `14013d740`. Capture current C and C+10 at the consumer's actual current-property acquisition (`14013de34..14013de68`, CP454); capture successful RTTI result P with P+38/+40 and dynamic type. Entry-only snapshots are insufficient because the optimizer prefix precedes this acquisition.
- Final refresh: capture both actual getter returns at CP454's `14013e49c` and `14013e4b5`, and the effective target at `14013e4d5`. For nonnull concrete B, capture B+38/+40 and source class scalars at their actual read points. Retain P/B equality or inequality as observed, not as an expected assertion. Record ordered destination values and normal completion of `140142ca0` if dispatched.

For the narrower question of just the consumer's P/B pair, actual P acquisition plus both linked-get returns and concrete refresh/source/destination reads suffice; a complete imported-Open identity-history claim additionally requires the correlated publication and mutation boundaries above. A hook list without storage-write completeness is not proof of every intervening replacement. Full selected lifecycle acceptance still separately needs containing class/operation destruction order and +38 data disposal. Type3 SUB+28 optimizer ownership, OPT streaming, GEO and Save gates are unchanged.
