# CP111 isolated-save CLI acceptance plan

## Purpose and integration boundary

Validate the private opt-in `moproj2mst` CLI Open→Save route end-to-end while showing that the existing CLI and six-export C ABI retain their legacy behavior. The implementation design in `analysis/resume110-cli-terminal-route.md` is authoritative for outcome policy: a `Returned` worker yields its adapter code; only a complete qualified terminal `Boundary` plus natural worker status, durable receipt commit and no supervisor/protocol failure may cause the CLI parent to relay `0xC0000417`. The external test controller separately records the final CLI process status. The receipt must say relay was requested, never that the CLI's future termination was observed.

This validates the candidate isolated route only. The remesh inputs are a constructed overlay on retained B133-before; they do not establish an original enabled-remesh run, original CRT handler context, native Close, or fresh original GUI parity. The terminal path remains qualified `candidate-fixed-endpoint; native-default-handler-prelude-unimplemented`.

## Prerequisite API/job contract reconciliation

Before writing the acceptance source, resolve two current header/design mismatches:

- `src/cli/isolated_save_job.hpp::IsolatedJob` currently carries only `project`, `output`, `deformDir`, `flags`, and `codepage`. CP110's job contract also needs schema/version/nonce, parent ownership and own-image identity, guiUnit, captured `M2M_MO_INPUT_MODE`, initial CWD, and bounded lengths. `IsolatedSaveRequest` likewise has no explicit settings snapshot. Add those fields or document a rigorously equivalent immutable envelope before acceptance asserts snapshot preservation.
- `isolated_save_job.hpp` currently declares leaf-based `writeIsolatedJob/readIsolatedJob` and says the child reads that leaf. CP110 requires a bounded in-memory mapping with a read-only child handle and no file-backed job. Reconcile this deliberately; either implement/test the CP110 mapping as designed or revise and review the product contract. Do not silently treat a filesystem job as the approved mapping. If a private job file remains for diagnostics, keep it separate from the immutable launch payload.

Acceptance source must wait for agreed API signatures and a frozen implementation. The current `main.cpp` has only ordinary argument parsing; there is no implementation found for the two isolated-save APIs yet, so this is a forward test plan, not runnable validation against current code.

Normal, isolated-terminal, default-CLI, and each ABI trial need independent leaves; the normal Save mutates the project and replaces the enabled remesh primary.

Keep project, MST, all seeded/output paths, receipt path, job/diagnostic paths, and any temporary receipt path below 100 UTF-16 code units. Check canonical containment, reparse ancestry and all paths **before** copy/create. Keep receipt storage in a pre-existing separate local regular directory under `C:\PROBLEM`, outside project root and output target. Require an absent new receipt name, then test that alias/collision cases reject before child launch. Pin `M2M_MO_INPUT_MODE` explicitly (unset or exact `0` for the B133 default cases), codepage `1252`, initial CWD, flags (`WRITE_SAVE`, plus explicitly selected strict mode), deformDir setting, candidate CLI/DLL identity and relevant loaded dependency hashes. Before each run, capture all 66 overlay file hashes/bytes (64 source + two seeded files) with canonical slash-relative paths. After stopped/returned outcomes, record every path including missing/read-error markers; retain complete raw bytes for each changed/missing/error file before comparing. No XML path, whitespace, number, or line-ending normalization. Check the two remesh files and the five CP108 raw prefix output files separately. Terminal/default-denied routes must preserve primary/fallback bytes and match the frozen raw prefix only where the qualified all-success project/MST condition applies; also capture the rewritten project XML raw because the retained folder lacks an exact after oracle. Never declare all unlisted files unchanged without full manifest evidence.

## Active cases

1. **Opt-in normal `Returned`/OS 0.** On a fresh unlocked B133 overlay, invoke the built CLI with absolute project/output/receipt paths, `--write-save --isolated-save --isolated-receipt <new-name> --codepage 1252`. Require CLI OS status0, one owned child stopped naturally with v2 Started+Returned and adapter0, durable versioned receipt committed before normal CLI return, no terminal relay request/status, and bounded normal diagnostics. Require raw outputs/full manifest and the normal remesh primary rewrite. This is a candidate control.
2. **Opt-in denied remesh terminal relay.** On another fresh overlay, acquire the noninheritable primary handle before starting the CLI with `GENERIC_READ / FILE_SHARE_READ / OPEN_EXISTING`; retain it through both worker and CLI stop and post-manifest capture. This allows worker Open's GENERIC_READ share-read|write and fallback read, but denies remesh Save's later GENERIC_WRITE/CREATE_ALWAYS. Require child v2 Started+Boundary with exact site/status/error/ordinal/profile/proof and all-success Save snapshot, worker natural terminal code `0xC0000417`, confirmed child stop without supervisor stop/backend/protocol failure, no Returned/backend-failure frame or adapter-return marker, committed durable receipt, and then observe external CLI status `0xC0000417` from the test controller. Receipt fields bind requested relay; external controller writes its own separate observation record for the CLI's actually observed status. The receipt must not claim it observed the CLI kill that follows its own commit. Require unchanged locked primary/fallback and exact qualified raw earlier Save outputs; no native Close assertion.
3. **Legacy default CLI guard.** Repeat the same denial on a fresh overlay but omit `--isolated-save` and receipt options. Require normal CLI status7 and legacy diagnostic, no terminal protocol/receipt and no process-terminal exit; retain raw side effects and project/MST status. `--isolated-receipt` without `--isolated-save`, isolated mode without `--write-save`, duplicate/missing receipt option, unsupported relative paths or other malformed combinations must reject with argument code1 before creating a child or touching project files.
4. **Public ABI guard.** On separate fresh denied overlays, call built DLL `m2m_convert_w` and `m2m_convert_utf8` with `M2M_FLAG_WRITE_SAVE`, explicitly set codepage1252 and mode0, and require legacy returned code7 (never process termination). Verify `m2m_api_version()==M2M_API_VERSION`; inspect the built DLL export directory and require exactly the existing six exports (`m2m_api_version`, `m2m_set_codepage`, `m2m_set_gui_unit`, `m2m_set_deform_dir_w`, `m2m_convert_w`, `m2m_convert_utf8`), with no isolated worker/request symbol. A successful subset of GetProcAddress checks alone does not prove the exact export set. Restore process CWD/settings/environment after each ABI call or isolate each call in a small helper process so the pair cannot inherit unintended global conversion state.

## Receipt/path rejection and failure coverage

Exercise these CLI request rejections with a fresh unmodified fixture and assert no worker PID/Started frame, no output changes, and no overwrite:

- Existing receipt path containing a sentinel: return1, preserve bytes/hash exactly.
- Receipt aliases canonical project file or explicit MST output, lies anywhere inside selected project tree, or is in an ambiguous/reparse/symlink parent: return1.
- Relative receipt, nonexistent/nonlocal/nonregular parent, directory target, existing alias/hardlink, or target equal to another protected path: return1.
- `--isolated-save` without `--write-save`, no receipt, repeated options, invalid settings, nonabsolute project/output, malformed argv/job, wrong role/nonce/schema/size: reject before conversion. Verify ordinary CLI `--version`, usage and default argv behavior remain unchanged.

At the commit boundary, simulate a target appearing after initial validation and before `CREATE_NEW` install. The commit must fail closed (CLI-only65 where control remains), preserve the racing sentinel, avoid relay, and keep the worker observation truthful. Test the no-replace helper directly or through an internal filesystem interface; do not add a CLI fault option. Also cover changed/reparse parent identity and install/flush failure using a private receipt/filesystem seam if available; require no relay and an accurately labeled diagnostic, not a fabricated successful receipt.

Test deadline and worker/protocol failure without relying on an accidental hang: a test-only runner fixture should simulate timeout, child stop success/failure, partial frame, protocol conflict/flood/cap, unexpected status, BackendFailure, PublicationFailed, EndpointReturned, terminal-looking status without Boundary, stale nonce, and failed terminal receipt commit. Product CLI exposes no custom handler, synthetic delay or failure selector. Expected outcomes are timeout CLI code66 or other isolation/backend/protocol/receipt code65, with owned child stop/receipt state where available, no `0xC0000417` relay, no rollback/normal Close, and preserved project outputs up to the real reached boundary. Keep these deterministic runner tests in the named separate runner target if they cannot be exercised without exposing implementation hooks to the integration executable.

## Receipt and terminal acceptance fields

For normal `Returned`, require durable receipt version/schema, candidate and child image binding, requested path/settings/CWD snapshot, worker Started+Returned transcript and adapter code0, OS status0, raw output/manifest references and `relay_requested=false`.

For candidate terminal, require durable commit proof (exclusive final create/no replacement, complete bounded JSON write, FlushFileBuffers, close and write-through rename), verified child image/hash, nonce/profile/proof/site/error/ordinal, complete Save snapshot, worker natural status and stopped state, `relay_requested=0xC0000417`, and explicit native-handler qualification `StaticFreshDefaultAssumption/CaptureContextUnimplemented`. External observer separately records parent CLI status. Reject receipt claims of native handler execution, original runtime parity, native Close, or observed parent relay from within the pre-relay receipt itself.

No source, test, build, GUI, original executable, REA or mutable DB action was performed for this design. CP108 and CP110 are static/worker evidence only.
