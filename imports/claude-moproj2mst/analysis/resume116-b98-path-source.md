# CP116 B98 path divergence: original and candidate source chain

## Finding

The B98 path difference is generated by the original and candidate writers from the project/subproject path in their respective runs. The original-qualified call chain supports the candidate's current project-owned path. It provides no source basis for rewriting the candidate output to the historical checkout root or altering the acceptance oracle. Retain the raw one-file DIFF and the existing separate exact-path qualification.

## Original source-qualified chain

The B98 input identifies the operation as `SfOprDiestress` and its subproject as `Type="0"`, `Active="0"`, with `Subproject_DbName DbName="Gear_blank.DB"` (`evidence/gui_mo/oracle_b/98_B_DS3F_before/Gear_blank.moproj`, operation around line 80 and subproject around line 216; DbName around line 327). The retained S1-05 source contract identifies the Diestress writer as original VA `0x1402b5410` and gives the relevant body at `source/docs/re/moproj2mst/s1-05/spec.md:76-94`:

1. Resolve the operation's current subproject (`0x140055050` → `0x1400a7390`).
2. Call `0x1400b9e80(subproject, ..., true)` for the full DB path.
3. For B98's `Type=0`, that helper takes the non-type-4 branch to `0x1400b9df0` → `0x1400a4f60(project, ..., true)`. The P17 contract at `source/docs/re/moproj2mst/p17/spec.md:38-45` describes `0x1400a4f60` as applying the `.DB` suffix to the full project path (`P+0x18`). The special `Type=4` branch uses DieStress-specific names and `cleanPath`; it does not apply to this B98 subproject.
4. Copy the DB path, replace every case-insensitive `.DB` with `.KEY`, then after the writer's properties check and target selection emit the SIM header, call `0x1401344a0`, and emit GENDB. The helper at `0x1401344a0` writes `KFREAD`, integer `1`, then streams the path QString and line ending. It does not replace the path with a canonical/oracle-root value.

The original `evidence/gui_mo/s1/s1-05/d1s.c` contains the `0x1401344a0` implementation at its bounded `FUN_1401344a0` section: it streams literal `"KFREAD    \t"`, integer `1`, then its QString argument. The writer body and path-helper branch are retained in the S1-05/P17 specifications; the direct decompile excerpt independently establishes the final serialization edge. The original text-format evidence says the MST QTextStream codec is locale-based and this closure does not set one (`source/docs/re/moproj2mst/s1-02/spec.md:59-66` and related closure). B98's paths are ASCII, so codec selection does not explain this path-value difference.

## Candidate correspondence and retained bytes

Candidate `src/ops/diestress.cpp:107-121,169-181` follows the same sequence: `opSubProjectDb` resolves the active operation subproject via `subProjectDbPath`; `writeMst` copies that DB path, applies `replaceAllCi(".DB", ".KEY")`, and passes the result to `emitKfreadOne`; that helper streams the marker and path. Candidate `src/model/paths.cpp:12-18,80-91` uses the full `Project::path` and `.DB` suffix for this non-type-4 branch. There is no B98-specific absolute root, output-MST-path substitution, or historical-path constant.

Retained B98 original `Gear_blank.MST` is 2,756 bytes, SHA-256 `e69980305fc2ad704a1f44c57b723592af7494a5e97ab61826867a193efa27c1`; its KFREAD path records the old `C:/Users/alext/Projects/deform-rea-work/gui_mo/oracle_b/98_B_DS3F/Gear_blank.KEY` root. Candidate receipts preserve different raw values for the copied candidate project. CP95's retained-artifact comparison reports 29 comparable paths on each side, one raw differing file (`Gear_blank.MST`), and no missing/extra files. Its candidate MST is 2,721 bytes (SHA-256 `42a48184d865f1465a5d4a2f23ab935743cada14b9a8a16cf87a5170b416f947`); replacing just the candidate's exact path in a separate comparison buffer produces the retained 2,756-byte vector/hash. The older CP48 build-tree reproduction likewise found one path-line change, with the raw size difference explained by its longer scratch path. These results establish candidate-only byte equality after an explicitly scoped substitution, not raw parity.

The existing `tests/s/test_b98_kfread.cpp` tests the source-backed rule directly: exact copied-project key path, one key occurrence and matching KFREAD count, exact path line, then whole-file equality after only that path substitution. It leaves raw output separate. The full folder comparator does not apply this adjustment, and should continue to report the path-bearing raw difference.

## Whether to change the candidate

No source-backed candidate adjustment is supported. Changing the emitted path to the historical root would violate the original writer's project-path derivation and fail for a moved or copied project. Converting it to a relative path or another canonical form also conflicts with the original writer body. A comparator-wide replacement would erase a raw observation; the existing test already gives a distinct case-specific diagnostic view without modifying either output.

The exact historical Open/Save action, original execution root at save time, and a fresh original Save from the same short B98 project root are not established by these retained candidate-only receipts. Consequently, the evidence cannot upgrade this to fresh-original parity or establish that any hidden GUI/session path normalization occurred before the writer received its project object. That is the evidence boundary, not a reason to guess a normalization rule.

No production source, test, comparator, build, fixture, GUI, original executable, or mutable REA state was changed or run.
