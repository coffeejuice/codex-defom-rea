## Suppressed mode is another independent gate

The shared custom notifier `143d76700` reads byte `+141` at `1402cf3f1` for emissions and `1402cf771` for queries. Nonzero exits without the normal keyed receiver invocation. Unsuppressed emissions clear notifier `+90` at `1402cf408`, then process a copied receiver list. Observe suppression at each relevant call, because earlier synchronous receivers may change it before a later emission. A zero value at constructor completion or timer entry is insufficient.

Setter `1402ce630` reads and returns the old byte, then stores the supplied byte at `1402ce656`; it does not itself enforce balanced or nested restoration. Retained caller candidates and decompilation show explicit1/0 scopes around selection changes (`140265870`, `140266060`) and widget cleanup (`140ccaf50`). These are real mutation paths, not proof the selected Open or Save boundary is suppressed, unsuppressed, or free of other writers. Suppression can allow `modelUpdated`'s fit but stop its click notification, or allow an earlier selection and suppress the later UpdateData. Do not turn skipped notifications into queued work or replay them when suppression clears.

Keep four separate state concepts: notifier `+141`; Qt sender blocked-signals bit; selection/loading/busy gates; and area impl replacement mode `+10`/placeholder flag `+11`. CP70's reached `ShowWidget(QWidget*)` clone supplies false and stores impl `+10=1`; that mode affects old-widget replacement/deletion, not whether the global notifier delivers UpdateData. HWND/serial/postedWake likewise cannot substitute for any of these values.

## Smallest discriminating capture, when the release gate permits it

Use one owned fresh process/input and ordered event ordinals, with native module identity plus process/thread/owner lifetime generation. Record selected Open entry and its actual return to its caller, and Save entry/poll boundaries. “First after Open was clicked” is not “before Open returned.” The following bounded hooks refine the existing passive plan; this report does not execute them or authorize a GUI session:

1. Diagram scheduling at `14017085f` and timer constructor return/store `671348e2`: correlate actual diagram receiver, timer allocation, dispatcher/thread, interval and registration result. Retain every request in this interval; two requests do not imply two deliveries.
2. `67134ca0`, activation gates `6712ed15`, `6712eed3`, `6712ef05`, and actual `140183160` entry: correlate sender/connection/receiver and direct-versus-queued branch. If observing actual callback entry is sufficient for the chosen seam, do not demand invented HWND or serial values. If predicting delivery from the message pump, additionally recover the real native timer-registration/message route and its actual dispatcher/HWND/timer fields; the posted-event serial helper is not that proof.
3. After fit, capture actual current model/item. At relevant `1402cf3c0`/`1402cf740` gates capture key, `+141`, selected receiver order/liveness/method and query result. Keep nested ordinals and rebind/destruction events so an earlier receiver cannot silently invalidate later assumptions.
4. At `1405f4524`/`140dae340`/`1411e2870`, capture actual project/operation/item, property index, impl/current guard, Boolean widget and lifetime. Correlate first factory/adoption separately. An Apply hit proves its occurrence; “first Apply” additionally requires gap-free monitoring from the chosen Open entry, including synchronous and non-timer causes.

A Save-poll callback after Open return proves a later Open-to-Save effect, not an Open-time effect. No Apply hit over a partial/gapped observation proves absence. A modal Save descendant is another dispatch interval, not part of the single zero-wait poll.
