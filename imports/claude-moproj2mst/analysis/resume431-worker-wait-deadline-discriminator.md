# CP431 WORKER wait-return deadline discriminator

CP430 observed exact WORKER exit code zero only in CP333's failure snapshot after the parent terminal-read deadline. CP329's success path checks its unchanged deadline immediately after `WaitForSingleObject`, before checking the returned status or calling `GetExitCodeProcess`. CP431 adds an injected-clock pair around that boundary: if an exact `WAIT_OBJECT_0` returns with one millisecond remaining, CP329 reaches the exit query and closes successfully in the harness; if it returns at the deadline, CP329 holds before the exit query and retains its owner/handles for cleanup. A later failure-only exit-zero snapshot cannot turn that held success path into acceptance.

No timestamp in CP430 locates WORKER signaling relative to CP329's wait return.
