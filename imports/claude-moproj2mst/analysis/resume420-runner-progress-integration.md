# CP420 contained-runner progress sidecar

CP419 found no CP418 terminal-entry marker when the parent terminal read hit its fixed deadline. That absence did not locate the contained runner's earlier state. CP420 uses a new versioned fixed sidecar keyed by the exact BOOTSTRAP nonce and original absolute deadline. `cp420_runner_progress.py` permits only the ordered stages `bootstrap`, `parent_ack`, `worker_resumed`, `result`, `worker_ack`, `worker_closed`, `terminal_entered`, `terminal_returned`. Bootstrap is created exclusively; later stages append only after the complete expected prefix. Each write is best effort and fsynced, and a read is capped at 161 bytes. No caller supplies a path.

CP335 writes `bootstrap` after validating BOOTSTRAP and wraps the original captured `before_resume` bound method to mark `parent_ack` only after its normal return. It marks terminal write entry and exact validated return. CP330 marks the four WORKER stages only in the external occurrence after each existing operation and contract check. All writes are diagnostic-only: a missing or malformed file cannot authorize or prevent protocol success. CP333 reads one fixed latest stage only on the exact absolute pipe deadline failure, before its primary-error marker. CP349 adds the fixed stage names to its existing one-stage allowlist; the 40-record/2048-byte bound remains. A live read is a snapshot, so absence and partial content are inconclusive. Fsync time is part of the unchanged five-second deadline and could perturb the observed timing; it must be qualified in any inference.
