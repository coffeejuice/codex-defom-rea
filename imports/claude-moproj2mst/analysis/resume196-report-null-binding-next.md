# CP196: bind the Session Report caller's null parent argument

## Bounded decision

Select one source increment: qualify the actual ConversionSession-owned first pending Report prototype with the retained TaskBase callsite's known-null QObject argument. Issue that qualification at the Session ownership boundary and consume it only while constructing the fresh `savedEntryRdi` token in `TaskFactoryRuntime::initializeNativePrefix()`. Reuse the existing CP194 TEST and CP195 JE model; the default Session then stops at `BeforeCallerNullParentCall`, QtCore RVA `0x131449`, before the call. This does not add an instruction beyond CP195 or admit the nonnull parent-slot load.

This deliberately replaces the earlier default-unknown Session expectation in `resume195-connector-next.md` and `resume196-connector-next.md` only for the newly qualified source route. Unknown and explicit nonnull synthetic diagnostics retain their existing behavior. Existing retained frames must not be silently upgraded or repaired.

## Issuer and source admission

Current ownership is concrete: `ConversionSession` constructs `taskAllocationStore_`, `widgetRuntime_`, and `taskFactoryRuntime_` in `source/apps/moproj2mst/src/engine/conversion_session.cpp`, then calls `associateWidgetRuntime(widgetRuntime_)`. The factory holds weak roots; the store owns the stable pending Report and its separately owned private state. `TaskFactoryProfile::Native` alone is insufficient: ordinary standalone diagnostic factories also use it. A paired widget root alone is likewise insufficient.

Add a private Session-only factory qualification operation (proposed name `bindSessionReportNullCaller`), accessible to `engine::ConversionSession` by narrowly scoped friendship, immediately after the Session associates its two roots. It accepts no nullness boolean, native pointer, slot value, or caller-authored provenance strings. Internally it requires the receiver's live Native profile, exact stored allocation/widget control blocks and canonical pairing, and no factory initialization, pending allocation, or existing prefix. It creates an immutable privately constructed source-binding capability held by the factory, weakly bound to these actual owners and this factory occurrence. Its fixed source tag denotes exactly the first Report chain and import/export identities above. This is a proposed API, not an existing issuer.

Only the actual Session constructor invokes this private operation. Do not broaden the public constructor, `TaskAllocationStore::allocatePendingReportPrototype()`, `SavedEntryRdi` aggregate defaults, or parsed DOE projection to imply the source qualification. Do not infer the qualifier from a requested task key: native initialization precedes key lookup, so all keys encounter the same first Report prefix. No later prototype or generic QObject caller inherits this capability.

Consume the capability inside the `if (!pending->qobjectPrefix)` fresh-frame block at the existing `frame.savedEntryRdi = ...` construction near `task_factory.cpp:195`, before publishing `pending->qobjectPrefix`. Verify the live capability, receiver, root control blocks, current pending ordinal, owned stable node, Report kind, `0xc0` allocation, freshly owned `0x88` private identity, and incomplete state. Bind its issued frame record to that exact allocation/report/task/private identity and token occurrence. Set only this token's `parentIsNull = true`; preserve the incoming-RDX origin and all existing module/save/call/return provenance. Carry a privately issued source-binding identity with the frame/token and include it in complete snapshots and validation. A free-form source string or public enum plus matching fields is not an admission capability.

Do not retrofit nullness into a retained unknown token after POP or TEST. Freshly initialize from this source, or refuse an incompatible retained frame unchanged. Allocation failure while preparing the frame/qualification must leave no advanced cursor or partially published qualification.

## Validation, invalidation, and terminal behavior

Before each source-qualified resume, validate the live factory and allocation adapter scopes, exact factory capability and Session root pairing (including shared ownership identity), pending ordinal/node/private identity, token occurrence, fixed source identity/module digests, and known-null token. Preserve every existing prefix validator, including saved/restored RDI, `[S-8]` origin and stack lineage, RBX, return boundary, task/private backlinks, shared-null bindings, phase-derived cursor, and completion flags. Once restored, `restoredRdiParentIsNull` must equal the token; after TEST, `parentTestOutcome` must equal recomputation; after JE, require the taken-null path and `0x131449`. Source-qualified unknown or nonnull values are corruption and must refuse, never be repaired into true.

Revoke admission on factory/Session scope release, owner expiry, foreign or changed root/control block, pending allocation replacement, frame/token replacement, private identity change, capability mismatch, or reuse for another factory/report. A coherent diagnostic rewind may retain the same valid capability, but phase, restored token/nullness, TEST flags and branch metadata must be rewound together according to existing validators. Rewind cannot issue a new source capability or conceal corruption. Persisted old frames without it remain unqualified; upgrading them is outside this increment.

For valid newly qualified frames, POP copies known-null with the same token, TEST at `0x131435` yields ZF set, and the existing JE at `[0x131438,0x13143a)` selects `TakenNullParent` / `BeforeCallerNullParentCall` / `0x131449`. The default diagnostic budget remains 17; no eighteenth instruction is added. Reentry, including smaller valid diagnostic budgets, validates and refuses at that same terminal without replay. Keep one retained prototype, zero parsed/native completed tasks, empty factory maps, unchanged reference/allocation counts, `complete == false`, `qobjectBaseCompleted == false`, and native initialization incomplete.

Unqualified standalone diagnostic factories retain `parentIsNull == nullopt` and the guard at `0x131438`. Their explicit test/model refinements still support null at `0x131449` and nonnull at `0x13143a`; those fixtures carry no Session source capability and make no production-parent claim. Preserve their existing corruption/refusal diagnostics and full snapshots. Do not let a synthetic refinement bypass Session capability validation or appoint a production parent owner.

## Hard stop

End at QtCore RVA `0x131449`, before its helper call (retained target RVA `0x2aca0`). Admit no call, TLS/current-thread query, thread-data ownership, refcount, counter, parent `+8` read, `[rcx+0x40]` read, TaskInfo work, registration/cache publication, or completion. Qualifying a statically null argument supplies no thread/helper semantics. The next instruction requires a separate reviewed source/ownership contract.
