## Current harness qualification

`tools/reference_harness` is preparation/receipt/comparison machinery; it launches nothing and does not drive the GUI. Case 003 is the usable training freeze, bound by local successful full-build receipt consistency to source and three binaries. That is not compiler attestation, runtime readiness, full dependency containment, or proof of held-out status. Preflight scans selected XML paths only. Raw comparison covers project and cwd final filesystem states, while missing side channels and intermediate write order remain unobserved. Qualification rules require raw digests, explicit slices, reason and retained evidence; they leave raw output intact. The harness's 39 tests (38 pass, one Windows symlink privilege skip) validate harness mechanics only.

Case 004 supplied a real original attempt but is not an acceptance comparison: the HeatTransfer project rendered Open and the process faulted before Save observation. It was a training deviation, used persisted settings, had an earlier slash-path chooser rejection before corrected native-path Open, and did not trace process-wide I/O. Fault location was QtCore `QObject::metaObject` leaf RVA 0x12a0e4, but registers/stack were not captured; cause and caller are unknown. Candidate exit 0 does not repair missing original evidence. The related passive editor-owned Open harness proposal is merely prepared/syntax-checked; it is explicitly not runtime-tested and may be terminated at a selected constructor/setup point. Its startup observations cannot substitute for full Open–Save–Close acceptance.

## Capture risks and stop conditions

The prior case proves a real crash can occur immediately after Open. Verify runtime identity and no existing process immediately before launch; capture faulting registers/stack/events if supported, avoid repeated probes against the same input, and leave the process untouched if ownership or state is uncertain. Current persisted settings are a confounder that must be observed, not silently cleared. Qt/license/recent-file external writes mean project-only manifests cannot prove absence of side effects. Native CLI Open is not fully equivalent to interactive File>Open timing; if used for a bounded crash-localization probe, label it diagnostic only and do not call it lifecycle acceptance. The proposed editor constructor probe stops before grid allocation and is not a substitute for this comparison.

No original app control, build, source edit or REA database mutation was performed for this audit.
