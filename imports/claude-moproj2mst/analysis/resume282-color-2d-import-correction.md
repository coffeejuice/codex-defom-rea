# CP282 2D color import-cell correction

The previous CP279 descriptions called the three nonzero-branch accesses virtual getters. That was an incorrect dispatch classification. The immutable original `DEF_GUI_MO_64.exe` v11.0.2 SHA-256 is `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`. Bounded DUMPBIN disassembly gives `0x14126A6B3: FF 15 07 E3 B9 00` calling qword cell `0x141E089C0`, `0x14126A6CF: FF 15 E3 E2 B9 00` calling `0x141E089B8`, and `0x14126A6EB: FF 15 BF E2 B9 00` calling `0x141E089B0`. RCX is `this+0x168` at each call; XMM0 double is converted to float afterward.

Independent PE import descriptor parsing binds the QtGui4_64.dll FirstThunk/OriginalFirstThunk pair by the same index, then reads each IMAGE_IMPORT_BY_NAME record: cell `0x141E089C0` (index 1530, on-disk import-name RVA `0x03536e08`) is `?redF@QColor@@QEBANXZ`; cell `0x141E089B8` (index 1529, RVA `0x03536dee`) is `?greenF@QColor@@QEBANXZ`; cell `0x141E089B0` (index 1528, RVA `0x03536dd4`) is `?blueF@QColor@@QEBANXZ`. The three calls therefore read QColor red, green and blue floating components in that order. These are ordinary eager IAT entries; the PE delay-import directory is empty. On-disk qwords are import-name RVAs, not executable function addresses. Actual runtime resolved DLL addresses and the QColor object's live values were not observed.

An earlier agent used DUMPBIN's symbol display ordering as if it were the FirstThunk slot order and falsely assigned `overrideCursor`, `alphaF`, `blueF`. That mapping is retracted. The public `viewerSync` association, selected `this+0x17c` branch, initialized palette slot 12, callback owner, and resulting side effects remain unqualified. This correction does not release the guarded color path. No original execution, GUI control or mutable REA state was used.
