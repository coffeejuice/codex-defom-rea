# CP202 suspended-installation contingency map

## Scope and decision rule

This map covers the five remaining hooks in `admin/frida_original_save_probe.mjs`: `slot_entry`, `busy_return`, `auto_save_call`, `dock_event`, and `show_signal_call`. The revised `prepared_visibility_request` hook is outside this map. Static addresses and instruction claims below come from `analysis/resume202-remaining-hooks-static-audit.md`; the current observer semantics come from `admin/frida_original_save_probe.mjs`.

An installation failure while the original is suspended is a pre-resume stop. Do not resume with partial hook coverage and do not convert a missing observation into a negative result. First preserve the failure receipt and terminate/settle the owned process using the existing held-handle cleanup protocol. Any retry must use a newly created suspended process, after the selected alternate has passed the fixture and identity gates below. Do not retry an uncertain attach or mutate the running observer in place.

The current observer installs all hooks for a module as one unit, reads and validates every 24-byte prefix before attaching any hook, and then emits `module_ready`. A change of site or event semantics therefore requires a reviewed observer/runner revision: its hook table, prefix receipts, callbacks, expected readiness set, `preReady()`, terminal coverage calculation, and any source/hash receipts must agree. Preserve all six observations, module-continuity checks, and the pre-resume readiness gate. The two Qt hooks remain subject to qualified late module loading.

## Global preflight for any alternate

Before another original run:

1. In the harmless owned fixture lane, verify the exact candidate bytes, instruction boundaries, ABI inputs, return-address values, and Frida callback behavior. Exercise both the target caller and at least one unrelated caller where a return-address filter is proposed. Confirm the alternate does not patch or depend on an unqualified RIP-relative instruction.
2. Review the revised probe as a static artifact. Ensure it records the candidate address and incoming-return filter, labels the event at the actual interception point, retains the six semantic coverage slots, and refuses to arm unless all required pre-resume EXE hooks and the observer are ready. Keep the live observer bounded and read-only.
3. Before each new suspended attempt, recheck the original EXE/DLL SHA-256 values, canonical loaded paths, module sizes, candidate prefix bytes, and the qualified QtCore event-type prefix. Capture all bytes for that module before installing any interceptor. Use the module’s live base plus RVA; preferred-image addresses are coordinates only.
4. Confirm the exact helper hash and original held-suspended ownership/readiness protocol. An alternate is not permission to launch unsuspended, relax cleanup, or change the disposable fixture.

If a candidate or required semantic filter cannot be verified, retain the original site and report the hook as unavailable; do not claim complete capture.

## Outcome handling

A safe replacement is a coverage-preserving semantic alternate only for the auto-save and busy-result hooks, and a caller-filtered signal-body entry only for the Show branch. The slot and dock-event hooks have no established fallback in the cited static evidence. Any alternate that changes interception point must be named as such in receipts and reports.

If installation still fails after a preflighted alternate, do not relax the six-point acceptance condition, infer the missing event from other observations, or call the run complete. Preserve the bounded failure evidence and continue only with a newly reviewed candidate or report the concrete blocker to the owning workflow.
