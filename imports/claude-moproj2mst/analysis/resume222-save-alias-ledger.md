## Synchronous trusted-adapter requirements

1. Every adapter accepting a writer/body callback in this scope must call it synchronously, at most once, before the adapter returns; it must not retain/copy it into deferred work. The existing `std::function` type alone does not enforce this.
2. Treat `GuiModel*`, `DB_STEP_DATA*`, sim-control pointers, `FILE*`, and references to stack flags/locals as call-scoped borrows. Use owned values if work must escape.
3. Preserve nullable-borrow behavior: `withOpStep` invokes with null; `withPropsSimCtl` invokes with null when no owner; `captureFx` and `captureKey` may skip invocation on empty target/missing folder/open failure.
4. Preserve each adapter's effects boundary. Scratch adapters record output only when the writer actually produced a file; native adapters may mutate/truncate directly and must not replay a recorded effect afterward.
5. Stored MST slot callbacks are process-lifetime function pointers, not closures. They must not be replaced by lambdas capturing an operation/model pointer during slot installation.

## Output and failure-order assertions to retain

The following existing save tests are the most relevant guardrails; add/keep focused cases when changing adapters rather than treating this review as behavioral closure:

- `tests/s/test_save_io.cpp`: `native_task_writers_match_recorded_bytes_and_leave_no_deferred_replay` (1456), `native_save_continues_after_interobject_properties_or_material_open_denial` (1640), `native_interobject_denial_preserves_contact_updates_before_open` (1658), `sync_equipment_keeps_slot_borrows_and_native_write_order` (1723), `native_equipment_denial_and_failed_flush_are_not_replayed` (1812), `material_lookup_failure_precedes_truncation` (1845), `native_task_key_output_alias_is_rejected_before_target_truncation` (1856).
- Also preserve exact earlier save failure precedence: `save_failed_mst_open_keeps_step4_boolean_files_and_prior_save_effects` (208), `save_bwz_open_failure_still_attempts_ini_and_finishes_mst` (271), `save_ini_open_failure_keeps_bwz_and_finishes_mst` (329), and `native_simctrl_failed_open_skips_model_flag_mutation` (1071).
- Preserve tail sequencing: `native_full_save_writes_same_opened_remesh_state_after_mst` (2059), `native_full_save_remesh_tail_runs_after_project_or_mst_open_failure` (2075), and `native_full_save_disabled_remesh_removes_unmarked_primary_and_ignores_denial` (2092).

For new refactors, the minimum direct checks are: (a) adapter invokes a sentinel callback before return and never later; (b) no callback invocation on empty-path/missing-parent/open-denial branches where qualified; (c) writer bytes and `FileEffects` write/delete order remain byte-for-byte/effect-for-effect equal; (d) callback-thrown errors preserve close/temp cleanup and do not fabricate a recorded write; (e) denied open leaves pre-open model mutations exactly where current tests establish them and does not run post-open mutations; and (f) full save preserves the order `props/model sync → save names → operation files → after-files → heat-treat schedule`, including class-specific early returns.

## Limits

This review establishes the C++ callback shapes and their synchronous call chains from the listed source. It does not independently prove all native call targets' internal behavior, establish GUI-thread affinity, qualify unlisted save paths, or certify all outputs against the original executable. See the source-specific save contracts and existing native/recorded comparisons for those claims.
