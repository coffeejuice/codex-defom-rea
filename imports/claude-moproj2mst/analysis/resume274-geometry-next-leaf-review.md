The finite admission is sound for the existing canonical caller. The unrepresented native model byte at +0x258 does **not** block the conclusion that the retained adaptation helper leaves its Slice collection unchanged for a live 3D owner whose database is null. ## Why the unknown byte is bounded

`evidence/gui_mo/s1/mdt/V/v0.c::FUN_1411f17f0` performs the nonnull-object bind effects, calls `FUN_1411fdd30` only if View+0x338 exists, then continues to `FUN_1411fc900`. `V/v1.c::FUN_1411fdd30` short-circuits in this order: resolved owner nonnull, `FUN_140c7c0a0` true (3D), `FUN_140c911c0` false, and `FUN_140c7ac30` nonnull (database). `V/v3.c` shows `c911c0` as a one-byte read at owner+600 (+0x258); `L5/d1.c` shows `c7ac30` as the pointer read at owner+0xd8. Collection replacement and enumeration are inside the conjunction. For a stable live 3D owner and null database, a true flag exits before the database getter; a false flag reaches the getter and exits on null. Neither path enters collection mutation. The flag read is a scalar read from the same already admitted live owner, with no shown side effect. The larger helper's removed-unreachable warnings limit claims about its adaptation body and exceptional behavior, not this outer short circuit.

`V/spec_V.md` says the native constructor initializes +0x258 to zero and a separate editor model can set it to one. Current `GuiModel` has no corresponding member; `viewer.cpp::patchModeOf` treats operation-model patch mode as true under that earlier qualification. That is useful context but unnecessary to this leaf's Boolean result. The review does **not** claim the test's reconstructed owner has a native byte value, nor that native execution was observed naturally. The null-DB case is supported by the two exhaustive values of the native gate, provided owner and database getter refer to the same stable live owner.

## Exact implementation boundary

Edit only the existing Slice gate in `source/apps/moproj2mst/src/engine/viewer.cpp::bind`, with test changes in `source/apps/moproj2mst/tests/mdt/test_viewer_slice.cpp`, after root confirms file ownership. Retain partial unbind, object assignment, object-dimension binding, and `GeometrySyncAccess::pending(m)` before the gate. On a nonnull collection, resolve `view.ownerModel` and first require `owner == &m`, then a present `owner->step`. Admit dimension exactly 2 as CP272 already does, or dimension exactly 3 with `owner->db == nullptr`. Fall through to the existing later bind/refresh flow; do not return from outer `bind`, reset/replace the collection, or rewrite backlinks or scratch. Keep `viewerSync`'s entry `requireAvailable(m)` and post-bind pending check. Owner equality and present step are conservative converter admission rules, not native conditions.

Preserve the existing `M2M_E_UNSUPPORTED` object-rebind refusal at this boundary for a null/foreign actual owner, missing step, other dimension, and dimension-3 owner with nonnull DB. The foreign-owner check must precede all owner dereferences; caller `m`'s geometry barrier does not qualify a separately parked foreign View owner. A parked canonical owner is stopped by the existing caller barrier or pending return. No step-identity or ObjectKey currentness claim follows from a present public `step` pointer. Do not add a +0x258 field or public getter merely to select an otherwise identical no-collection-mutation result. Do not extend this admission to the native database-backed body.
