# CP74: project post-close failure, remesh tail, and Close cleanup

## Settled behavior

The CP73 paired test injects a declared nonzero QFile error only after the delegated project writer has opened, serialized, closed, and queried its device. It confirms that the candidate then completes Boolean BWZ/INI, MST, and the enabled remesh output before returning `M2M_E_WRITE` for the project writer. The same test's control run delegates the real FileDevice status. This proves candidate orchestration for a scripted post-close status; it is not a physical disk failure or a fresh original execution.

Original static qualification is consistent: `analysis/save-semantics.md` traces native Save through current-operation step 2, project write, property saves, MST, and remaining remesh handling, with no branch after project false before the next calls. `analysis/wave3-project-close-status-contract.json` qualifies that the project writer closes QFile before sampling QFile.error; it does not equate QTextStream.status with the return. Concrete original partial bytes remain unknown.

There are two different meanings of “Close” here. The project writer's QFile Close is exercised and observed in CP73. By contrast, `ConversionSession::~ConversionSession()` explicitly documents that its final cleanup is adapter cleanup, “NOT an original normal-Close replay” (`src/engine/conversion_session.cpp`). It invalidates adapter receipts and releases project/session-owned storage. CP73 must not be described as testing the GUI's later normal Close or proving its cleanup behavior.

## Next uncovered partial-effect branch

The next source-backed branch is a failure in the enabled remesh writer after the project post-close false, with property and MST effects already made. `src/core/convert.cpp` calls `saveRemeshAtProjectSave` after the MST attempt and before it maps either MST or project failure. A remesh outcome other than `Completed` throws `M2M_E_UNSUPPORTED` immediately. Therefore a failed remesh open masks the injected project `M2M_E_WRITE` in the adapter result while preserving earlier BWZ/INI/MST effects; remesh's existing target is retained.

The remesh leaf is qualified by `src/engine/simcontrol300_remesh.cpp`: enabled state opens `LOCAL_REMESH.DAT` via `CoggingFile`; failed `fopen` records `opened=false`, sets `UnsupportedSnapshot` and the invalid-parameter boundary, and returns without writing. `tests/mdt/test_simcontrol300_remesh.cpp::remesh_native_failed_write_open_preserves_file_and_marks_invalid_parameter_boundary` already checks that isolated leaf and its retained `KEEP` bytes. It does not combine the failure with a public full Save or prove the surrounding continuation/error precedence.

Existing public full-Save coverage includes successful remesh after project/MST open failure (`native_full_save_remesh_tail_runs_after_project_or_mst_open_failure`), and disabled-remesh removal denial (`native_full_save_disabled_remesh_removes_unmarked_primary_and_ignores_denial`). CP73 covers successful enabled remesh after scripted project post-close false. None combines post-close project false with enabled remesh-open failure. Thus the useful next acceptance case is a paired control/injected run using the existing project-output factory seam, a seeded enabled remesh state, and a deterministic Windows sharing handle that denies the remesh CRT write-open while preserving pre-existing bytes. Assert that both runs complete step4 and MST; control reaches remesh failure and returns `M2M_E_UNSUPPORTED`; injected also returns `M2M_E_UNSUPPORTED` (not project `M2M_E_WRITE`); the remesh file remains unchanged; and the recorded project writer return differs as injected. Do not claim the original GUI's surfaced status from this adapter result.

## Evidence limit and fixture caution

The unit remesh test demonstrates the intended Windows sharing setup for denied `fopen`: hold the existing primary with `GENERIC_READ` and `FILE_SHARE_READ`, attempt the enabled writer, then close the lock. Before adding the combined case, confirm the public conversion's own file-reader/Open path does not open that same remesh output before Save; otherwise use a direct Save-owned harness or a private boundary after project Open. The fault must occur at remesh write-open, not preempt project loading. This candidate case would test the source-backed adapter ordering and status precedence; original native status propagation beyond the statically observed GUI Save Boolean remains unqualified.
