## What repeats, and what does not change

Each coordinate getter first obtains dimensions and dispatches the actual canonical key0 COW/storage operation (`140854af0..4b19`). The optional node owner then invokes outer which0 sync. For u1b58=0/dimension3/version>=6000/cache0, the reader selects actual tables, starts node timer, records ReadSingleAArrayFromDB, calls the null-companion loader, records arrays checkpoint, performs the admitted main-object skip/zero-node loop, records node Stop, returns true, and completes the outer which0 tail.

The null loader returns before directory query or any version/cache/A mutation. Thus the **second** outer sync sees the same high version and cache0 and executes the same reader. It is not cached merely because the first reader returned. The existing legacy DEF_PRE getter's always-up-to-date gate is still insufficient for that GUI round.

Each fully admitted getter has this mutable order:

```text
one actual optional-node COW dispatch
  -> actual 3D index-table selection
  -> node Start / ReadSingleAArrayFromDB
  -> null loader return (no DB/query/version/cache/A effect)
  -> arrays checkpoint
  -> actual main-object/MAR-input decisions and zero-node returns
  -> node Stop
  -> reader / which0 / existing N+8 return
  -> actual connectivity getter
```

With a shared initial registry lease, first COW may detach that registry body; the second round normally keeps its now-unique body. Both dispatches still occur. Each node Start resets its count before two entry checkpoints and Stop, so final count3 does not by itself prove two executions. In an uncapped arrays profile, two appended checkpoints plus a second COW observed after first Stop discriminate the repeated reader. At capacity>=100 both arrays calls are normal no-ops; do not infer an omitted reader from unchanged count. Initial negative arrays count refuses in the first reader, before any second getter.

There is no A/MAR pointee or optional-coordinate copy on this profile. Actual main owners and +0x87c zero gates, pre-skip MAR selector bounds/load, state/flag and node timer count2 guards remain essential. The dead wrapping32 record address remains unconsumed. Version/cache and optional coordinate/connectivity identities stay current across both rounds.

Reuse the current qualifier rather than duplicate a second COW/timer implementation. One bounded design is:

- Add an explicit private Readiness/Builder getter-round selector and a stack-local output carrying the actual returned coordinate/connectivity values. The default remains Readiness.
- A completed first null reader with populated connectivity yields a `RepeatedGetterRequired` state. It is eligible only to attempt the next recovered round, not to call the old builder with raw data.
- Pass the actual View/item/geometry context into `geometryMeshRect` (its one caller already has them). After its existing count/count/width reads, call the qualifier once for Builder round and capture its returned values. A completed Builder round returns Populated rather than requesting a third getter.
- Consume those values directly in the existing bounded builder. Do not then call the legacy coordinate/connectivity getters again. Coordinate-prefix return can load N+8 only as the proved return of its completed native getter, not as a fallback around missing effects.
- Any second-round refusal leaves first-round effects intact and the item unknown. Do not roll back timers/COW, mark cache1, rerun the first round or reinstate an old low-query frame. The second round must still match the supported current null-companion profile; changed/unqualified inputs cannot create a different frame or body path implicitly.

No shared header/CMake/ABI change is needed. There is no recursion in this call graph: readiness and builder each request one explicitly identified getter round, and neither qualifier invokes the builder.
