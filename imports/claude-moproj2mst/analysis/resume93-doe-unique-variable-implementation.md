## Decision and owner transition

The helper's fresh-empty condition is replaced by exact concrete-owner admission: equal alias/owner vector lengths, count below signed-int32 maximum, every concrete unique_ptr nonnull, and every alias equal to its corresponding owner's Var address in the same order. It compares identities before following a borrowed alias and does not adopt raw/foreign records from matching values. Existing scalar/geometry projection owners, retained scalar prefix and nonzero mode still refuse.

After unchanged header/profile admission, exact QString-value name equality rejects a duplicate before allocation. This deliberately keeps native existing-name behavior outside the cut: native helper returns the matched record, but the reader ignores that pointer and applies its following setters to the last manager record. The implementation neither updates the matched record nor appends a duplicate as fake success.

A unique row constructs its concrete record, secures host ownership, appends the borrowed alias, assigns name, stores selected index=size-1, invalidates all samples, applies ID/dimension and processes ordered nonempty Descriptions. Existing rows, descriptions, indexes and sample table values are not reset at append. The source next-number query scans the existing list plus constructor-number0 even with false assignment flag; its candidate is discarded, so no sequential/lowest-free ID assignment is added. Positive parsed IDs, including repeated numeric IDs or int32 maximum, remain unchanged. Same-name identity, not numeric ID, controls this helper decision.

Only after the complete DoeVariables loop does the existing caller reindex all records; the outer ID finalizer remains unchanged. A later unqualified row preserves earlier records and their still-unfinalized indexes. A top-level guard after successful traversal preserves completed indexes. Host alias-append failure removes only its uncommitted concrete owner; later failures keep the published record and earlier effects. Native Qt COW/refcounts/raw-null allocation/fault timing and manual Close/destructor order are not claimed by that host lifetime protection.
