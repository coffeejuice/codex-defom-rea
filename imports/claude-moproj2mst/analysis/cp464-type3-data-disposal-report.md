# CP464: ShapeOptim property data has no proved destructor release

The selected original normal destruction path deletes property B but does not read, clear or free its separate B+38 allocation D. D is ordinary heap data, and neither its creation nor the shown registration calls install it as a QObject child. This closes the immediate data-disposal question more narrowly than a process-wide leak finding: no direct D release exists in the recovered B/base path, while tree payload cleanup and QObject callbacks still prevent an unconditional claim that D is never freed anywhere.

## Failure prefixes and remaining ownership question

There is no success flag or rollback in the selected destructor chain. A nonreturn during old tree release prevents shared_null publication and every later base/guard/QObject/B-free/OPI-null step. Some tree entries and their data may already have been destroyed. A failure after list publication can leave B+18 empty while later guards remain registered. Failure inside QObject cleanup can follow completed guard invalidation and still prevent B heap release. Do not model a failed disposal as an unchanged object, or assume OPI+10 was already nulled before its deleting call returned. Exception/unwind handlers were not recovered here; these are normal-call ordering and nonreturn-prefix facts, not an SEH/C++ unwind model.

The exact source-ready next step is a **private prepared disposal event model** that separates property identity B, data identity D, tree storage, operation publication and registered guards. It may implement the proved ordinary event order with explicitly supplied stable graph/guard assumptions and injected boundary refusal events. It must not add `delete D`, label B+38 a unique_ptr, or coalesce property deletion and data disposal on the strength of this evidence. Safe host memory cleanup can remain an explicitly host-owned implementation detail, separate from a claimed original D-free event.

For native D lifetime acceptance, obtain one same-instance original witness (only after the independent GUI release gate permits it): capture D from the allocation/store at `140142777`, B and its operation/class identities; trace D aliases/rewrites and all allocator release events for that exact address through successful containing-operation destruction; record relevant Qt tree/guard/callback state, loaded module hashes, and the order of guard invalidation, B release and OPI+10 clearing. A D-address free event establishes its caller and timing. No D free during one bounded successful teardown establishes retention over that interval only, not process-wide permanence. Alternatively, statically close the tree payload QVariant/custom handler, QObject callback/private-delete, external aliases and exceptional paths before asserting a complete lifetime contract. Public Open-Save-Close and P-versus-B identity gates remain unchanged.
