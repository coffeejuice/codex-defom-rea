# CP169 Report document owner: complete default Save branch

## Decision

The complete original default Save branch narrows the document contract, but it does not admit a new internal owning-document source cut or public Report Open, Save, or Close continuation. A newly constructed `SfSessionManager D` starts with `D+0x68=1`, selecting `0x14064ab80` *if that value is still current when Save calls `0x14064a830`*. That branch has no direct `0x140645320` interactive-payload call in its selected body. It emits a possible Qt signal, refreshes an active task image, and then selects either full Session serialization or a task-specific update. The signal, virtual calls, fresh list reads, and later file/DOM work leave the actual current owner and branch outcomes unbound. A direct-call absence does not close transitive effects.

This is a read-only converter/static pass for original `DEF_GUI_MO_64.exe` **v11.0.2**, SHA-256 `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`, preferred base `0x140000000`. No reconstructed executable, original runtime occurrence, new REA Evidence ID, build, GUI/app-control session, test, source edit, deployment, or shared plan/state edit is claimed. Only this report was written.

## What the complete default branch adds

The half-open original PE selection `0x14064ab80..0x14064b14f` (RVA `0x0064ab80..0x0064b14f`) was checked at instruction boundaries with DUMPBIN 14.44.35228.0 and against the retained `FUN_14064ab80` decompile in `analysis/wave2-doe-manager-session-decompile.json`.

1. `0x14064abad` asks `0x14064c030(D)` for the current main/singleton. A null result exits at `0x14064b145`. On nonnull, virtual `+0x778` is called at `0x14064abd1`. A nonnull result is reread through `0x140cf94f0(result+0x10)` twice and compared with main virtual `+0x268` at `0x14064ac19`. When unequal, `0x1402cf3c0` is called at `0x14064ae54` with the literal `2signalChangeActiveStepData()` and ten QGenericArgument values. Its exact signal recipients and their effects are not selected by this PE body.
2. The active index is read via `0x140647560` then `0x140656200` at `0x14064ae61..0x14064ae69`, **before** `0x14064ab20(D)` at `0x14064ae7a`. A negative index exits; a fresh list/count from `0x140647560`/`0x140656240` after that call rejects an out-of-range index. A valid index selects a current task through `0x140a9a440`/`0x140160c10`, obtains the current main image through `0x140c9d4d0`, and assigns the image to that task at `0x14064af06`. The index is not reobtained after the signal and helper calls, while list/count and main are reread. Callback-sensitive identity remains material.
3. The selected task name from `0x140658410` is compared to literal `Custom` at `0x14064af59` and `SfTaskDeformMetalFlow` at `0x14064afb3`. For either name, `0x14064fc30` serializes at `0x14064b06d`, and the resulting DOM element is passed to `0x140653550` at `0x14064b0ce`. For other names, `0x140648780`/`0x14140c660` chooses `0x14064b160` when its count is positive or `0x14064aa80` otherwise. These callees and actual task/DOM data are not closed by the branch selection alone.

There is no direct call from this selected default branch to `0x140645320` or `0x140646370`, and no direct `D+0x68` write. This only narrows the visible branch. Virtual `+0x778/+0x268`, signal receivers, image/task helpers, serializers, and Qt operations can have indirect effects. The `0x14064ab20` helper itself selects a current object, tests a count, and conditionally calls `0x14065a9b0`; its bounded body has no direct `D+0x68` store or lazy payload call, but the callee's effects are not resolved here. Static evidence still does not prove whether Save uses Open's D, whether `D+0x30` is created or replaced, or whether a `SessionRoot` append succeeds.

## Smallest implementation cut and guard

The only current source-ready Report Open prefix remains the pure sibling `.DS` path helper already implemented. `source/apps/moproj2mst/src/ops/report.cpp` still refuses before the document accessor. `src/engine/report_document_slot.cpp` records only a qualified initial diagnostic null/non-null token. Its immutable token cannot represent the native post-construction publication, current reread, rebind, QObject-parent death, or Close guard clear. Building a second detached default-Save or `SessionRoot` helper would not establish the missing owner. **No new production source cut is admitted by this pass.**

The first productive internal implementation, once its owner is witnessed, is a root-owned parented document producer and **live per-SubProject slot** that publishes the constructor return, rereads the slot, and tracks document generation/death. Report Open should retain its returned D only for its own reset/read/traversal sequence. Report Save and accepted Close must resolve their current Project/SubProject/document and preserve the branch and release ordering above. Keep the public Report Open, Save, and Close guards in place until those effects are represented; do not treat the diagnostic slot tests or DOE `SessionRoot` fixtures as Report acceptance.

The exact missing witness is one natural original Report **Open→Save→accepted-Close** occurrence, after a supported GUI-control release operation and verifiable receipt become available in the parent workflow. Bind each fresh `P/S/D` selection and generation; the proposed and accepted QObject parent, child-list delta and connection registrations; both lazy slot reads; reset/read/traversal and current `D+0x20/+0x30/+0x40/+0x48/+0x58/+0x68/+0x2a`; the Save branch at `0x14064a891`, signal receivers, index/list/task/image and serializer/DOM outcomes, file open/close/error; any `0x140645320`/`0x140646370` call and `SessionRoot` append result; accepted Close admission, both `S+0x30` reads at `0x1400b5bc2`/`0x1400b5bd5`, deletion, guard clear, and parent-child destruction order. Record any intervening rebind or earlier death rather than assigning an assumed stable owner. A bounded immutable-only follow-up could resolve the exact signal and virtual receivers, but cannot supply occurrence values.

When implementation becomes admitted, focused tests should cover same-S publication/reuse and slot reread, active-S/rebind changes between commands, failed allocation or QObject parent acceptance, reset/read failure after publication, default versus alternate `D+0x68` and later `D+0x2a` paths, serializer/Qt append/file outcomes, and Close first-null versus changed-second-read cases. Then use the repository's normal source-stable focused/full/freeze gate. No such tests were run in this pass.
