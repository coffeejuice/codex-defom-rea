## Existing helpers versus public refusal

- CP113's path projection computes the native parent and joins the three filename attributes only in its qualified normal-constructor domain. It does not model full `QFileInfo` construction, handlers, ref/cache effects, or arbitrary aliases.
- CP114's `applyGeometryRowPrefix` implements the bounded row-key lookup/append and tail-flag/MorphMethod effects on the concrete `HeaderVariableRecord` owner. It stops at `CorrespondencePayload`.
- CP115's `appendGeometryCorrespondencePair` implements the indexed Upper/Lower value append, including invalid-index no-op behavior. It receives already converted points; it does not perform DOM token splitting or native locale conversion.

These are already-integrated isolated helpers and focused tests, not an integrated XML-reader path. `doe_study.cpp` passes `InputTableSource{path}` to `parseInputTable`, but the parser's source parameter is still `[[maybe_unused]]` and its comment explicitly leaves Geometry before QFileInfo (`source/apps/moproj2mst/src/doe/doe_study.cpp:427–431`). The public reader still stops at the Geometry child before the QFileInfo filename/path ownership boundary (`source/apps/moproj2mst/src/doe/variable_record.cpp:183–188`). Therefore the appropriate next operation is a bounded private-admission review that decides whether a specific absolute-drive/UNC source case can satisfy constructor and conversion requirements; do not remove this guard based only on helper availability.
