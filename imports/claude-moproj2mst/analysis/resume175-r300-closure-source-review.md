## Source-order and borrow audit

`rg -n 'stepOf\(' source/apps/moproj2mst/src source/apps/moproj2mst/include` now finds no declaration or call. Exactly five `withOpStep` calls are at current lines 279, 500, 545, 565 and 599. Each lambda returns only void or bool, satisfying the existing `OpStepCallback` constraint. The helper invokes `opModel` once and passes the same nullable `model->step.get()` value without adding a geometry gate. No lambda returns or stores the step address.

`saveSimCtrl` acquires the step first and returns false on null before computing the path, opening the native KEY, creating scratch capture, touching flags or starting PPV. The callback encloses the original native/captured branch. A native successful open still invalidates the overlay before writing and ignores close status; the scratch branch still invokes `captureKey`. Only after the KEY branch does recovery-B PPV preparation, before-open status, callback, file open, payload writing and ignored stream status run. The PPV/error text and `FileEffects` order visible in the source are unchanged.

`rebuildSystemContacts` still acquires the step before checking `lubSystem`; null or disabled lubricant returns without local-step allocation or inter-object clear. The remaining lubricant lookup/import, default-pair resolution, object writes and pair appends stay inside the callback in their former order. `saveObject` still acquires before item/path lookup and retains its unchecked `*step` in an admitted writer path; an empty path returns false. Adding a null guard here would change the current behavior and was correctly avoided. In both slot loops, admission occurs before each individual acquisition, a null callback return skips only the current slot, and the next loop iteration proceeds; no lookup was hoisted or merged.

The nested writer lambdas capture the borrowed pointer by reference only during the enclosing callback. `captureKey` directly invokes its writer, and `writeTaskKey` invokes either that capture or its native stream writer before returning. Neither stores the callable. This establishes no new post-callback escape at the inspected sites; it does not prove concurrent safety or invalidate aliases acquired elsewhere.
