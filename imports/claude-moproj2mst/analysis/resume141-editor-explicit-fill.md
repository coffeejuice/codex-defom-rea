## Implemented profile and state

Existing3D/KnownC, method/thermal radio and finite-CVGERR guards remain. Solver6 additionally requires finite p0/p1 and exact signed-int32 p2/p3, including either signed zero. A private bit-level predicate classifies zero/exponent/mantissa without executing a CVTT conversion merely to decide a rejected input. It accepts exact negative2^31 at exponent31 and integral values at exponents0..30; rejects fractions/subnormals/nonfinite/out-of-range values. Only admitted exact values reach the existing CVTT integer adapter, avoiding new invalid/inexact CVTT assumptions for excluded domains.

Fill sets visibility=true for admitted6 and populates explicitParameterText in native order: number(p0,'g',6), number(p1,'g',6), number(CVTT(p2),10), number(CVTT(p3),10). The existing numeric value adapter supplies formatting; whole native FP status/masks or Qt environment parity is not claimed. Raw source parameter bits and count0/4/77 are retained. CG normalization remains unchanged and is a no-op for6.

Other solvers keep visibility=false and unknown/disengaged explicit texts. Their existing CG/other numeric profiles are unchanged, including fractional CG parameters. No empty/default explicit values are invented for a later non6→6 radio selection. The bound visibility callback retains known texts when switching away/back, but does not populate missing ones.
