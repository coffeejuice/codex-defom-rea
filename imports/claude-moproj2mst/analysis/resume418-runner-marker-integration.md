# CP418 contained-runner terminal-write diagnostic

CP417 proved a nonterminal overlapped result returned before the parent terminal read's retry budget expired, but it did not show whether CP335's contained runner reached its terminal claim. CP418 adds a separate runner-owned sidecar. `cp418_runner_marker.py` derives a fixed `analysis/cp418-runner-<sha256>.txt` path from a domain tag, the exact validated 32-byte occurrence nonce and positive uint64 deadline. No path or handle is taken from argv. The first record is created exclusively and fsynced immediately before CP335's terminal transfer; a second fixed record is appended only after the 80-byte transfer returns exact count and custody validation passes. Readback is bounded to 33 bytes and exact records.

CP335 treats both marker operations as best-effort diagnostics. A collision or I/O error cannot replace the primary transfer result or gate success. On an exact absolute pipe deadline failure, CP333 reads the marker before abort cleanup and emits one fixed `cp333_runner_absent/entered/returned/malformed/unavailable` stage ahead of its existing primary-error stage. A read while the runner remains active is a snapshot: a present valid stage is positive progress evidence, while absence or partial/malformed data cannot prove nonexecution. CP349 retains its 40-record/2048-byte trace bounds; the CP417 failure prefix plus one runner stage would have 39 records. No CP339 protocol, Win32 call, clock/deadline arithmetic, process flags, ownership or acceptance condition changed.

The final injected validation passed 646 CP3xx tests plus four CP418 marker tests from each supported module root, with `-B`; raw output is `cp418-final-isolated-tests.log`. Tests cover exclusive creation, ordered append, bounded/malformed read, marker ordering, collision and failure noninterference, CP333 primary-error preservation, and CP349 parser acceptance. Two injected cross-owner tests initially wrote fixed fake-occurrence sidecars into analysis; those exact files were verified and removed, and both tests now stub marker I/O. The final run left zero sidecar files. `git diff --check` passed. Independent source review found no acceptance blocker; it noted marker file I/O consumes some of the existing five-second deadline and a diagnostic-only read/append race if an external actor mutates the sidecar. The reviewer could not inspect Git diff in its restricted checkout; root inspected the exact diff.

CP419 is the successor: freeze and push this candidate, independently gate one fresh monitored inert occurrence, then correlate its runner stage with the parent retry-budget stage and exact cleanup. Do not repeat CP417 or treat a missing sidecar as proof that CP335 never reached terminal write.
