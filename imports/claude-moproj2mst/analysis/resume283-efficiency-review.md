# CP281–283 efficiency review

This review follows three fixture/evidence checkpoints since CP280. CP281's first harmless child debug wait assumed CREATE_PROCESS would arrive before ResumeThread; it timed out and was corrected to one checked ResumeThread before the held creation event. CP282 review caught missing Win64 API widths and timeout-exit checks in the native fixture; those were repaired before freeze. CP283's first mapped-header gate was too strict about Windows rewriting ImageBase; the final gate permits exactly that eight-byte field to equal the observed loaded base and compares the other mapped header bytes. These failures were retained rather than repeated after correction.

CP283 root final-source focused runs took 3.652 seconds for eight probe tests, 12.278 seconds for six supervisor tests, and 2.399 seconds for twelve observer tests: 18.329 seconds of test execution, excluding tool startup, review, hashing, Git transport and agent time. CP282's corresponding root supervisor and observer runs were 12.333 and 2.294 seconds. The groups differ in scope, so these timings do not establish a speedup. The unchanged converter C++ baseline remains CP274's 369 registered tests and historical comparison. No C++ build or complete launcher was required for admin-only CP281–283 changes.

The next low-cost prevention step is a bounded static preflight of expected loader-written PE header fields before running a new native creation-event probe. CP283 already incorporated the one observed ImageBase rewrite; no before/after benchmark for this proposed preflight exists, so no time or token saving is claimed. Keep fixed-child tests and final-source receipt hashing together at the integration boundary to avoid stale manifests. Token usage telemetry remains unavailable. Original-app and GUI-control gates remain closed; testing speed does not change evidence requirements.
