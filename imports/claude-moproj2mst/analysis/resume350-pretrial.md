# CP350 fixed native inert-trial preflight

CP350 wraps exactly one CP349 top-controller occurrence. Before loading native exports, it verifies all current `admin/cp3*.py` source hashes, the absence of matching bytecode cache, fixed Python image, pinned CP316 WORKER executable, worker source and original build receipt. It repeats that manifest after the occurrence and writes a fresh exclusive JSON report. A failed occurrence retains its exact top-controller owner and makes one cleanup attempt; it is never retried automatically.

The independent PowerShell monitor starts only the fixed Python interpreter with `-I -B -c` and an exact CP350 report path. It owns that exact process object, waits at most 20 seconds, requests termination of that process on timeout, waits at most five more seconds, and writes a separate exclusive monitor receipt. It begins stdout/stderr drains asynchronously, gives each bounded completion time, and accepts only exit zero, terminal drains and a durable CP350 report that itself says accepted. A timeout, missing report, nonterminal drain or uncertain cleanup remains unaccepted. This monitor does not guarantee hard real-time or crash-atomic cleanup.

The CP3xx injected suite passed 588 tests from each module root; exact source and log hashes are in `analysis/cp350-pretrial-static-validation.json`.
