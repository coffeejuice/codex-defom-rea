## Limits for interpreting the run

The observed first AV need not be the terminal crash. Treat a module-qualified record as the original crash stack only when its fault location and exit evidence correspond to the prior baseline (QtCore4_64.dll RVA `0x32c0`, exit `0xC0000005`); otherwise retain it as a first-AV observation. The probe's `exceptionRecordQualified` requires a containing module at RIP, so a null or otherwise unmapped fault can be retained yet result in `INCOMPLETE`, as in the Python preflight. Windows absence is PID based; unexpected PID reuse can cause a conservative incomplete result. The helper cannot guarantee cleanup after abrupt launcher death, and a 20-second watchdog or five-second observation bound may end a slow run. These are interpretation or completion limits, not a reason to expand the one-run scope.

The prior uninstrumented baseline and instrumented attempt both reported the same original QtCore fault offset; neither supplied a call stack. This reviewed probe is limited to recovering that missing live context. No DMO build/deployment or reconstructed DEF_PRE instance was inspected or changed.
