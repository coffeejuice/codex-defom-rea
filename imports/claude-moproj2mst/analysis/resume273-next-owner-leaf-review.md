# CP273 HeatTreat Mode owner-command design review — PASS, restricted to private consolidation

The three one-word writes may share a **private `GuiModel` implementation** while the three existing named commands remain the public C++ caller seam. This approves a source cleanup, not a new recovered behavior or an ownership-boundary closure. The alternative in the candidate that changes `syncOwnerMode` to call one mode-taking command is not approved: the current `HeatTreatMode` is private to `props_heattreat_slots.cpp`, and making a mode selector callable across files would widen the model interface and undo CP246's deliberate finite named-command surface.

Keep `setHeatTreatPropertyDeformation(bool)`, `setHeatTreatPropertyDiffusion(bool)` and `setHeatTreatPropertyPhaseTransformation(bool)` as thin adapters. Each must call the shared private implementation once. The shared implementation performs exactly one `simCtl()` call before any control access, returns on null, and maps Deformation to `trans[1]` (SC+0x108), Diffusion to `trans[3]` (SC+0x110), and PhaseTransformation to `trans[2]` (SC+0x10c), storing `enabled ? 1 : 0` in only that 32-bit word. Retain the geometry barrier before nullable step resolution and propagate its existing refusal. Do not add a generic offset/pointer API, public selector, default/reset work, STEPDEF write or schedule mutation. If a switch is used internally, all three named adapters must map to their documented indices; no reached invalid-selector policy is needed.

Leave `props_heattreat_slots.cpp` unchanged. Its `setMode` currently applies pending schedule defaults, assigns the property flag, copies the bool, calls `syncOwnerMode`, then invokes `ht::propsRefresh`. Its `getMode` copies the flag, synchronizes native state, then constructs the Bool result. `syncOwnerMode` returns for absent owner/project, calls `opModel` once, then dispatches to a named command. Moving provider lookup, defaults, flag reads or refresh into the shared command would alter failure order and the pre-provider bool snapshot. On a geometry refusal, earlier setter effects survive and refresh is not reached; with a missing step only the native word write is skipped.

The candidate's proposed `src/engine/gui_model.hpp` does not exist. `GuiModel` is declared in `source/apps/moproj2mst/include/m2m/engine.hpp`; any private member declaration belongs there, with its definition in `src/engine/gui_model.cpp`. The existing named declarations should remain. The narrowest implementation can keep the property source untouched.

Retain and run both actual caller tests: `m2m.mdt.l6_slots` (all three setters/getters, true/false, unselected-word sentinels, detached-step controls) and `m2m.mdt.viewer_box` (direct calls to all three named commands on a parked model, followed by unchanged-word checks). Structural review must confirm each adapter reaches the single `simCtl()` admission. No new test is necessary if these assertions remain intact; adding only a private-helper test would not establish the caller path. Root still owns the grouped/source-stable run and freeze; this review ran no build or test.

The six original slot addresses are recorded in `source/docs/re/moproj2mst/moproj/props_rest_ledger.tsv`, not the cited MDT L2 ledger (which records other TRANS setters). The retained `hta.c`, `htla.c` and `tpla.c` decompile attribution and the CP246 design/implementation reviews support the existing slot mapping and order as qualified static evidence. The L6 and viewer tests are reconstructed copied-corpus fixtures. This refactor adds no fresh original execution, public Open/Save witness, Qt reentrancy proof, or HeatTreat lifecycle acceptance. CP246's earlier test-only HOLD was repaired by the per-mode sentinel, getter and parked-control assertions; preserve those corrections.

Only this review was written. No source, tests, build, original process, GUI control, mutable REA state or shared recovery state was changed.
