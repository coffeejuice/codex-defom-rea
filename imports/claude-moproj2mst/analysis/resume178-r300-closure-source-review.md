## Borrow and ordering review

The translation-unit-local `withOpSimCtl` returns void, requires an exact void callback result, calls `engine::opModel(p, op)` once per invocation, and immediately invokes the callback with `m ? m->simCtl() : nullptr`. `GuiModel::simCtl()` still checks `requireGeometrySyncAvailable()` before testing its step, so the old geometry refusal occurs before each word write. No `withOpStep` substitution, direct step read or new gate appears in this helper. Its 13 lambdas are noncapturing and write inline only after a null check; none publishes the control pointer or retains a callable. The void constraint alone would not prevent capture escape, but these concrete callbacks have none.

The current source has four separate `withOpSimCtl` calls after `baseLoadPrologue` in `heatTreatPrologue`, writing TRANS 1, 3, 2, then 0. `distortionPrologue` still calls the base prologue, then five separate callbacks: TRANS 1; TRANS 0; the grouped `+0x16c`, `+0x164`, `+0x160`, `+0x1d0` defaults in their old order; `+0x2e0`; and, only after `if (!c.current) return`, `+0x2e4` through `*c.current`. `slotNamesPostLoad` retains its object/rename loop before separate TRANS 1 and 0 writes. `dieStressPrologue` retains the base prologue before separate TRANS 1 and 0 writes. Null control suppresses only its current callback's writes; later acquisitions still occur. Because `opModel` can have effects, this per-site sequencing matters. No aggregation or exception-boundary move was found.
