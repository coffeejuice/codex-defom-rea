## Behavior and borrow audit

`diestressSaveKey` still calls `opModel(p, op)` once and returns immediately for a missing model. It then calls `activeSubProject`, conditionally `subProjectDbPath(..., true)`, and `app::changeSuffix(..., ".KEY")` before evaluating `m->step.get()` once. The new lambda returns on null before invoking `captureKey`; the previous `if (!m->step) return` had the same effect point after path construction. For a present step, it calls `captureKey(key, fx, ...)` once; the nested writer declares zero flags, calls `def::cmd::write_key_file(step, f, &flags)` once and ignores its result as before.

`captureKey` remains unchanged: it removes its scratch KEY, invokes the supplied `std::function` writer inline, records bytes only if the scratch file exists, then removes it. It does not store or queue the writer. The borrowed pointer is captured by the inner lambda while `captureKey` runs and leaves scope before the outer lambda returns; no pointer is returned or retained by this source. No `withOpStep` second lookup or `GuiModelAccess::withStep` geometry refusal was added. This narrow function still directly acquires public `GuiModel::step`; its callback scope does not close the broader public field or parked-model barrier.
