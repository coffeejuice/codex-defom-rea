# CP480 private typed NUM_CON rows

The imported original Type3 `.OPT` writer obtains all four row values before the first row insertion. Independent PE rechecks resolved a prior semantic-label conflict: its getter order is field4 (`+0x60`, value0c), double field3 (`+0x50`, value18), field2 (`+0x70`, value08), then field1 (`+0x40`, value04). Results are held in EBP, XMM6, ESI and EDI. Insertion order is different: two spaces, one-based ordinal, one space, field1, four spaces, field2, six spaces, double field3, four spaces, field4, `endl`. The original emits one more standalone `endl` after the signed row loop, before manager lookup. Exact call sites, vtable targets and PE qualifications are in `analysis/resume479-type3-numcon-header.md`, `analysis/cp479-numcon-source-contract.md` and the CP480 corrected independent audits.

The private typed-manager attempt now uses the NUM_CON count captured before its header sink calls as the signed loop bound. For each row it reads the existing DefOpt view's four fields into locals in native getter order, then attempts typed sink insertions in output order. A sink mutation after the first row can affect later row reads but cannot change the saved loop bound or already-captured current row. Ordinary false statuses are ignored; a throw stops later attempts. `Type3OptAttemptSink` has a distinct `insertDouble(double)` method so the row value remains binary64 until a stream adapter formats it. Typed mode suppresses the old opaque `p.rows` to avoid duplicate output; generic and WithGroups modes preserve their compatibility fragments. It emits the post-loop standalone `endl` even for an empty list. This remains a private event/state projection, not a public Save admission or physical `.OPT` writer.

The Qt double IAT is `0x141e058e0`, called at original row site `0x1409080a1`; it resolves to QtCore4_64 `QTextStream::operator<<(double)` at preferred VA `0x670C4330`. Static constructor/operator evidence establishes default SmartNotation, precision six, number flags zero and C-style numeric locale; this is distinct from the unresolved locale text codec. Existing `qt::formatDouble` is a source-backed default numeric projection, but universal binary64 equivalence and actual writer bytes remain unproven.
