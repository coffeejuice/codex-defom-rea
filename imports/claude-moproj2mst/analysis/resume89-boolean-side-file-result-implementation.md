## Production boundary

New `nativeBooleanSideFileSequence` borrows one actual Project/Operation/BooleanData call. Missing `Operation::props` represents absent data-owner and returns-1; non-Boolean/missing/mismatched data refuses. Its BooleanProps owner must be the same operation in the actual Project.operations collection with the same Project/props relation. Membership is checked before dereferencing the raw properties owner. Foreign or unavailable relations throw M2M_E_UNSUPPORTED before attempts.

The helper resolves the existing actual OperationInfoIdentity's OperationInfoGuard, corresponding to native5f8d90 ->properties+20 ->c1aef0. A committed QObject boundary can leave the raw adapter Props::owner pointer nonnull while its guard resolves null; that branch returns-1 without files. The helper creates no new owner-ready flags or persistent raw-pointer receipts. Callback injection is a synchronous test/device seam; destroying/rebinding its borrowed owners during a callback remains outside this represented call contract.

For an admitted owner, both writer callbacks must be available before either runs. The sequence calls BWZ, retains its typed native return path, calls INI regardless of BWZ0/1, discards INI's result and returns BWZ's integer. Returned open failure is not a C++ exception: unexpected callback exceptions propagate without an invented catch/replay policy. No failure maps to new public m2m status or suppresses a later Save/MST stage.

New `booleanSideFilesNativeResult` is the physical entry and refuses non-native recording mode. Its callbacks use existing FileDevice at final destination; failed open returns0, successful open serializes/closes and returns1 without consulting Stream's sticky status or claiming durable bytes. Explicit close still precedes stream destruction. BWZ and INI serialization were extracted once into private functions and are shared with the old recording path; literals/field order/dimension block remain the same.

The existing void `booleanSideFiles` delegates only its native branch and discards the integer where the original callers ignore it. Recording mode retains its prior directory/pending-directory checks, FileEffects writes and pendingWrites behavior, and does not fabricate native success. Existing two occurrences (earlier property pass and later MST helper call) remain in place; no output-attempt ordering was moved.

New source-qualified invalid-owner behavior is explicit: previously the native void helper did not represent Props::owner's expired guard/result; now native -1 produces no files. Foreign/mismatched data is guarded rather than treating it as that null branch. These do not admit a public fresh-Open callback or a native event schedule.
