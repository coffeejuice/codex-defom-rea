If a preflight source review finds an earlier negative-ID rejection, or the local XML/byte checks fail, **do not launch** this pair; report that no valid discriminating input has been established.

## Interpretation gate

The control must reproduce the `Lubricants` addition under valid encoded CLI transport; otherwise this pair gives no test of dependence and should be classified inconclusive. If control adds it and the variant also adds it, the specific claim that **a positive ID from these two parsed operations is necessary** for that directory is contradicted for this occurrence, assuming the exact variant diff and clean starts. Another constructor/caller, later stage, or negative-ID path remains possible. If control adds it and variant does not, that result is **consistent** with the positive-ID initialization chain but is not causal proof: no uninstrumented boundary observes parser completion, normal outer Open return, `setOperationId`, `0x14008c630`, or the QDir call. The unchanged diagram's positive ID references may cause an earlier variant failure. A crash, early natural exit, missing parse evidence, or an additional input difference makes variant absence especially inconclusive. Equal non-directory effects or passive logs can strengthen comparability, but do not replace a direct Open/creator witness.

If both inputs create different earlier files, fail to produce complete ownership/absence receipts, or the variant is found invalid during source/byte preflight, report the blocker and keep the CP217 Open-effect integration gate closed. Even a clean positive comparison cannot establish the exact mkdir caller, attempted path order, failure notification behavior, successful full Open, Save, accepted Close, or hook neutrality of CP213/214. The CP216 pure five-path collector remains descriptive; do not wire public directory writes from this experiment alone.
