# CP115 Spring page integration review

## Result

The native one-row reader and isolated page Fill/Apply adapter are internally aligned, but the change is not wired into the actual `InitialEditorSession` Open path. The blocking line is [`simcontrol300_lifecycle.cpp`](../source/apps/moproj2mst/src/engine/simcontrol300_lifecycle.cpp:122): `openInitialEditorInto` still calls the two-argument `fillExtra3D(io, context.numericLocale)`. That overload delegates to the combo-aware version with two empty ID spans ([`simcontrol300_io.cpp`](../source/apps/moproj2mst/src/engine/simcontrol300_io.cpp:162-165)). The populated-row gate requires `firstObject` and `secondObject` in those spans ([`simcontrol300_io.cpp`](../source/apps/moproj2mst/src/engine/simcontrol300_io.cpp:146-149)); consequently a real one-row `SPRING.INI` causes the actual Extra3D page fill to refuse. It cannot complete the constructor page sequence or reach the new Apply branch through the lifecycle owner.

The new `test_spring_page_io_roundtrip.cpp` explicitly describes its scope as native IO plus page Fill/Apply, not the full Session/native GUI, and supplies test-qualified ID arrays `{0,10}` and `{0,20}` itself. Its positive cases therefore establish the helper behavior, not that the original combo population produces those IDs or that Open→Save reaches them. `analysis/resume115-spring-page-io-acceptance.md` preserves that limitation. The next executable integration step is to source-qualify the two combo item-data lists from the actual owner/setup path, carry them in `InitialEditorContext` (or a narrower owned context), pass them at the lifecycle Extra3D fill, and add a lifecycle-level positive fixture. Do not remove the membership gate or infer IDs from a general model object list.

## Checked behaviors

- The one-row reader still clears the output and preserves the old missing/nonpositive and exact `x\r\n` behavior. It accepts only the retained seed bytes or the corrected writer-normalized bytes, and refuses a present `SPRING2.INI` before emitting a row ([`simcontrol300_native_io.cpp`](../source/apps/moproj2mst/src/engine/simcontrol300_native_io.cpp:221-258)). That normalization extension is needed because the writer's canonical bytes differ from the original input spelling.
- The writer list has literal LF separators after count, first object, direction component 0, and direction component 2. `writeStringList` adds a tab after each non-LF item and a final CRLF. This yields the asserted bytes `1\t\n10\t\n0.5\t1.5\t20\t0\t\n1\t0\t\n\r\n`; the test compares against this independent literal, then requires a second Fill/Apply to produce stable bytes. Writer implementation: [`simcontrol300_io.cpp`](../source/apps/moproj2mst/src/engine/simcontrol300_io.cpp:76-87,218-226); test oracle: [`test_spring_page_io_roundtrip.cpp`](../source/apps/moproj2mst/tests/s/test_spring_page_io_roundtrip.cpp:21-25,120-145).
- Before any scalar writes, Apply rejects a changed visible value or unsupported selected-row state. For the admitted row it formats/parses the five visible numbers, fixes flag zero, then preserves scalar sidecar order NBC, SW2SP, STRETCH, B_WEIGHT, STRAIN_DST, SPRING. The primary SPRING write is attempted before readable SPRING2 deletion. Both write/delete return values follow the existing best-effort behavior and are not promoted to an error; this is candidate behavior and does not claim more than the retained writer evidence.
- Empty/missing SPRING remains the legacy scalar-only page state: `form.spring` stays empty, and Apply removes SPRING then SPRING2 after the scalar sidecars. The test keeps the old no-combo overload and malformed/present-companion/count guards covered. Present companion is an Open-time refusal; the late-companion test separately covers Save-time deletion with flag zero.
- The public guard remains in place. `InitialEditorSession::completeForPublicSave` is still `false` in `simcontrol300_lifecycle.hpp`, and `InitialEditorSnapshot::completeForPublicSave` remains `false` in `simcontrol300.hpp:377-389`. The isolated page test does not enter the staged Session route, public palette, or C ABI. No public Save admission should be inferred from this integration.

## Qualification

Static source review only. I did not edit source, build, run tests, control the GUI, or mutate a REA session. The CP115 receipt states no focused build/test was run for this page test, so its assertions are not a passing runtime receipt. Historical PE evidence supports the narrow writer/parser/page transitions; native combo population and the actual lifecycle bridge remain the missing evidence and implementation edge.
