# CP476 private Type3 SUB construction projection

The original `FUN_1400b5470` separately allocates the Type3 DOE manager and optimizer. It publishes the completed manager at `SUB+0x20`, then constructs and publishes the optimizer at `SUB+0x28`. A null allocation publishes a null slot. Constructor unwind frees only the in-flight allocation; an optimizer-constructor failure does not remove the manager already published. The manager constructor performs base/derived setup and naming before its ordered directory attempts; a false directory-helper result stops further attempts but does not fail manager construction. These statements are qualified by `analysis/resume142-close-sub-disposer.md`, `analysis/cp465-type3-owner-close-report.md` and the wave2 manager-constructor evidence.

The new private `type3_sub_construction` seam models this post-model phase with opaque identities and an ordered event receipt. It distinguishes manager constructor prefix, directory attempts, completion and publication. Engaged zero identities follow the null-allocation path. It records only completed effects after a supplied failure boundary, including in-flight release, and keeps an already-published manager visible if optimizer construction fails. The model is not wired to public Open/Save/Close and does not assign native destruction ownership or claim field-by-field Qt behavior.

Independent review found and resolved two source issues before integration: identity equality in tests, and the zero-identity plus manager-prefix ordering boundaries. The first focused build (`analysis/cp476-build.json`) failed because Testkit's `CHECK_EQ` could not stream the event enum; the test assertions were repaired. Historical original comparisons retain 93 SAME/five DIFF and are not fresh acceptance.

CP476 also added independent static QtCore reports `analysis/cp476-qtcore-qstring-flush.md` and `analysis/cp476-qtcore-writer-review.md`. The copied DLL's preferred base is `0x67000000`. Its `QTextStream::endl` inserts LF then invokes the flush helper; for Text mode the helper replaces LF with CRLF in buffered Unicode before codec conversion, temporarily disables device Text mode for the byte write, clears the Unicode buffer before write, and records status 3 for nonpositive/short writes or failed QFile flush. These are PE-bound decisions, not proof of the selected runtime codec or physical `.OPT` bytes. The private Type3 writer and current shared Stream have not yet integrated this Text-mode behavior.
