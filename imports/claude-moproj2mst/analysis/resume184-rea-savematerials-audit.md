# CP184 independent material-save audit

The immediate callback in `saveMaterials` preserves the reconstruction's existing single model lookup, null-step return, ordered material traversal, filter, path generation and writer calls. Native evidence supports the loop/filter/writer contract, but **does not establish a native single-lookup or null-model/step no-effect contract**. Those two properties must be described as reconstruction behavior preserved by this local cut.

## Native contract at 0x140058cc0

1. At `0x140058ce6`, resolve the material manager once through `0x140055110` and retain it. At `0x140058cf8`, call model accessor `0x14005f770`; pass that result to count accessor `0x140c7cae0` and snapshot the returned signed 32-bit count. No model/step null test is visible in this caller before count acquisition.
2. Start index at 1. The signed `jg` at `0x140058d26` terminates when index exceeds the saved count. Zero/negative counts skip the body. Each body calls `0x14005f7a0` at `0x140058d34`, then `0x140830460(step, index)` at `0x140058d40`. Retained `evidence/gui_mo/s1/mdt/L0/A/b0.c` identifies `0x14005f7a0` as another `0x14005f770` call followed by `0x140c7acd0` if the model exists. Thus there is one initial model access, one additional model access per visited position and another per eligible writer call; the original does not retain one fixed model/step for the whole loop.
3. Null material skips the iteration (`0x140058d4a..d50`). Material int32 at `+0x1cc8` equal to 2 skips it (`0x140058d5b..d62`). All other values qualify. Read material number from offset 0. No sort, deduplication, positive-number filter, existence check or per-material early failure exit appears in this caller. Duplicate numbers can cause repeated writes to the same default path.
4. Call the retained material manager's virtual `+0x178` with the number (`0x140058d8a`). Convert its returned QString using `toLocal8Bit`, then obtain QByteArray data. The supporting retained decompile `evidence/gui_mo/s1/mdt/L0/A/d0.c`, entry `0x140042850`, plus qualified `L0/spec_A.md` identifies this default path as project Materials directory plus `Material` and a decimal number padded to minimum width five with zeroes, then `.KEY`, cleaned through the project path helpers. It is a generated default path, not an item's stored customized KEY path. Edge-case negative IDs and locale/path encoding equality were not newly tested.
5. Resolve model again (`0x140058dc6`), derive step through `0x140c7acd0` (`0x140058dce`), and call `0x1408959e0(step, local8Path, number, 0, 0, 0)` at `0x140058df3`. Destroy temporary QByteArray/QString, then continue in position order. The writer return value is not tested. A failed material write therefore does not stop this loop. The caller has no explicit list edits or deletes; called accessors/writers can have effects.

The writer listing independently shows null/empty path returns 1 (`0x140895a1a..a37`), material-by-number resolution before opening (`0x140895a3c..a63`), missing number returns 3 without opening/truncating, then fopen and failed-open return 1 (`0x140895a68..a8b`). Its successful path writes material content and closes the stream; this caller supplies zero optional arguments. The `wt`/CRLF interpretation comes from the retained qualified KEY-writer spec, not a new runtime probe. This audit does not claim complete transitive engine/global side-effect coverage.

## Current reconstruction and scoped cut

Inspected `source/apps/moproj2mst/src/engine/save_current.cpp`, hash `36b3b12693fd5c2b3d4f4bde9ec486a9b673f7575da4b6d94903de19ceb0cf8b`, with `saveMaterials` at lines 639 onward. The immediately invoked void lambda performs exactly one `opModel(p, op)` call; returns on `!m || !m->step`; retains `m->step.get()` locally; snapshots int32 count at `+0x1320`; visits positions `1..n`; skips null/type-2; reads number at 0; constructs `materialDefaultFile(p, no)`; synchronously invokes `saveMaterialKey(p, *step, no, path, fx)`. Its returned status remains ignored. No pointer is returned by the callback. This is a faithful lexical confinement of the pre-existing reconstruction algorithm.

`opModel` in `engine/loader.cpp` can install loader slots, ask classModel, or create an absent engine model. Therefore a null return means no material/file effects from the subsequent body; it does not prove that the whole helper is side-effect free. The callback neither pins model ownership nor prevents reentrant step replacement by callees. It adds no public Save admission or concurrency guarantee.

`materialDefaultFile` uses the project directory and cleaned `Materials/Material%05d.KEY`. `saveMaterialKey` is unchanged: nativeTaskKeys resolves the number before opening and dispatches through `writeTaskKey`; capture mode uses the existing scratch-file/FileEffects path. Native mode can call `beforeNativeKeyWrite`, opens the actual destination, erases an overlay entry after successful open, writes and closes. These existing modes are preserved; captured effects do not by themselves demonstrate original disk-write equivalence.

Current test source contains ordered effect-path/nonempty KEY/banner/type-2 exclusion assertions and detached-step no-write/delete/restoration assertions, using a synthetic helper fixture. I did not execute tests or establish public Save reachability. Null-step no-effects testing verifies reconstruction behavior, not native null-step equivalence. The native-versus-reconstruction repeated-access difference matters if model identity changes between accesses; the scoped cut does not introduce that difference. Any stronger equivalence claim requires separate stable-model/admission evidence.
