# CP110: pure invalid-parameter model and worker diagnostic consumer

Implemented a source-private per-occurrence decision value for the original first-null-FILE fprintf boundary. It has no host/native side effects. The existing isolated worker consumes it only as a diagnostic before its unchanged fixed endpoint. The native prelude, original runtime occurrence, selected palette and public C ABI/CLI behavior remain unadvanced.

## Implementation and boundary

NEW `src/engine/remesh_invalid_parameter_model.hpp/.cpp` defines Unknown, StaticFreshDefaultAssumption, SameOriginalModuleDecodedNull and SameOriginalModuleDecodedCustom evidence. The same-original cases describe hypothetical externally qualified pure inputs; no actual original witness is constructed here. Invalid input enum values conservatively retain Unknown.

Every model first records FirstNullFileChecked then modeled errno22/EINVAL (not numeric ERANGE34). Unknown stops at DecodeHandlerUnavailable without status/default flag effect. Custom selects its separate branch and stops at InvokeCustomHandlerUnimplemented, with neither debug flag clear nor predicted default status. Static-default and decoded-null inputs model the decoded-null selection then the single debug0 store to module1450540e8, and stop at CaptureContextUnimplemented. They carry a conditional predictedC0000417, never an observed status. Static assumption and decoded-value witness retain distinct provenance/qualification.

The ordered fixed array contains only modeled effects and an explicit count; the optional debug store is a value/address description, never a host write. No original module pointer is fabricated or decoded. No OS/context/filter function is called; no host errno is assigned; no callback or stack unwind occurs. The type has no observed-process-status, executed-native-prelude or Close-completion field. DefaultPrefixComplete denotes only the bounded modeled dispatcher/debug prefix. It does not mean RtlCaptureContext, RtlVirtualUnwind or TerminateProcess executed. RtlVirtualUnwind in the native prelude would modify a captured context, not unwind the live Save stack.

Existing `tests/s/test_terminal_remesh_worker.cpp` adds the header and retains an optional pure model value only after its existing exact request/profile validation. The worker selects StaticFreshDefaultAssumption, never a SameOriginalModule witness. Its bounded existing backend ledger now includes evidence/stage/next-operation, source-model-only qualification, predicted-status presence/value and modeled-only debug-store classification. The parent independently expects the literal static-assumption/default-prefix/capture-guard text in the existing dispatch/failClosed ledger assertions. Invalid-request failClosed diagnostics have an Unknown fallback rather than an invented default observation. The stack diagnostic buffer is bounded768 bytes; existing truncation/publication failure checks remain active.

The wire Boundary/BackendFailure layout and tags, nonce/status classifier, child cases, endpoint request, core saved.call snapshot, status dominance, failure/parking behavior, lock/fixture ownership and actual `TerminateProcess` call are unchanged. Diagnostic publication is still mandatory at the same existing point; failure retains the previous publication-failure route. No protocol meaning is broadened by a modeled value. Existing qualification `candidate-fixed-endpoint; native-default-handler-prelude-unimplemented` remains.
