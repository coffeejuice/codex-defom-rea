# CP303 fake-only creation-time Job Object seam

CP303 added a private fake-tested Windows x64 Job Object creation seam in new admin files. It stages an unnamed noninheritable supervisor-owned job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, duplicates a handle into an already owned worker, and prepares a persistent `PROC_THREAD_ATTRIBUTE_JOB_LIST` for suspended `CreateProcessW` with extended startup information and no inherited handles. It has no post-create `AssignProcessToJobObject` fallback and no resume path. The `Kernel32Api.CreateProcessW` method itself raises HOLD; no real child, original app, GUI or Frida was launched.

Independent review confirmed the fake Win32 ABI sizes, startup flags, attribute-list lifetime and ordered call pattern. The first review found that a fake-marked forwarding wrapper could reach a bound live `CreateProcessW` and that a supplied SHA string had been overstated as image proof. The implementation removed the live binding, added a forwarding-wrapper refusal test, and explicitly labels the image fields as a supplied contract rather than on-disk or loaded-image evidence. The final source review passed. Root ran all nine fake tests; raw log and machine receipt are `analysis/cp303-fake-tests.log` and `analysis/cp303-fake-validation.json`.

This is an unintegrated fake seam. It does not receive a fixed clone image from CP300, prove a real process's job membership, duplicate a returned child handle into the supervisor, or prove cleanup after helper failure. The creator-interrupted-during-`CreateProcessW` outcome remains unknown even with a creation-time job attribute. CP304 is selected to fake-test the separate supervisor/worker offer, identity acknowledgment and cleanup accounting protocol while leaving historical `color_entry_supervisor.py` unchanged. Real synthetic and original execution remain HOLD. The latest full converter candidate remains CP301: 392 CTests and 373 source-bound m2m tests.
