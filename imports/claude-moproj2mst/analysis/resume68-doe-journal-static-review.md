# Checkpoint 68: In-flight DOE XML journal review

## Snapshot and overall assessment

This is a read-only review of the current in-flight `StudyIo`/SaveEffects edits, not a source freeze or build assessment. The canonical `StudyXmlJournal` now owns the recording store, `xmlWrites()` is a view of its attempts, and `engine::saveProject` assigns that exact shared journal to caller-owned `SaveEffects.project` before entering the writer. The current `test_type2_save_node_prefix.cpp` exercises that path and retains the alias after the expected refresh guard. These are the right ownership choices for the first recording slice.

The device's accepted-span model is also sound for the stated simulation boundary. `RecordingFaultBinary` asks the fault profile for each raw span below `writeTextMode`, records that exact request/result, and appends only `bytes.substr(0, returned)` to the same in-memory map used by `readFile`/`openReadFile`. The short-write test verifies the resulting non-prefix sequence `ab\r\nZ`, which must not be inferred from source bytes or treated as native durable contents. Native attempts are marked untracked and do not fill the recording byte fields.

## In-flight review points

1. **The successful-open event sequence is coherent if defined as effect time followed by result observation.** `openRecordingInputTableXmlFile` clears the same store and appends `RecordingTruncated` during simulated WriteOnly open; `observeInputTableXmlFile` records `OpenResult` after the open object is returned. The order `OpenRequested -> RecordingTruncated -> OpenResult` can therefore represent truncation before the caller observes the returned open state, consistent with QFile truncating during open. Document that event meaning and keep failed open as `OpenRequested -> OpenResult` with no truncate.

2. **Fault profiles are positional and must stay explicitly test-only.** Root has clarified that vector entry `n` applies to XML-open attempt `n`; this is not original fault parity. There is no expected path in `RecordingXmlFault`, so each profile test must assert the corresponding attempt ordinal and normalized path from the retained journal before interpreting the injected result. Path-bound injection and unconsumed-step diagnostics can be a later slice if tests need stronger matching. Do not present the current factory as production/original fault configuration.

3. **Version IDs and explicit content-change events are a later completeness improvement.** The journal stores exact raw accepted spans and a post-close simulated snapshot, and `RecordingTruncated` plus per-span return events expose current mutations. No per-file version ID or separate `RecordingContentChanged` event exists. That does not block the current single-attempt shared-writer test, but it limits provenance claims for multiple attempts or a later PAR write to the same path; add version/event linkage before making those claims.

4. **Writer and refresh outcomes are outside the current attempt-level surface.** `Type2InputTableXmlResult` is local to `write.cpp`'s Type2 branch and disappears when the refresh guard throws. The journal has open/close/file-error/stream observations, but no writer Boolean, last-error value, GuardedStop, or RefreshBoundaryReached event. This is not a blocker for the current `engine::saveProject` device-journal test: the caller still receives the throw, and while its Project is alive it can inspect `StudyIo.lastError`. It does mean the journal is not a self-contained durable writer/refresh result. Add those observations only when a detailed public output contract needs them; keep ordinary writer false separate from the later unconditional refresh boundary and never imply delivery/timer/UI effects.

5. **Native public conversion still has no caller-owned alias.** `engine::saveProject` binds `out.project.xmlJournal` and its caller retains `SaveEffects` through the guard, so the updated tests validate that seam. `convert.cpp`'s native branch still creates `saved` inside `run()`'s `try` and calls `saveProjectFileNative` without an observation sink; that writer still passes a local `unused` FileEffects bucket. The current alias therefore does not preserve native/public conversion diagnostics after that guard. Treat this as out of the current recording prefix, or provide a separately owned output handle before claiming it is solved.

## Caller-owned integration test

`tests/doe/test_type2_save_node_prefix.cpp` now has tests named `type2_engine_save_retains_actual_xml_observation_after_refresh_guard`, `...failed_xml_open...`, and `...postclose_xml_error...`. They call `engine::saveProject` with an external `SaveEffects saved`, an actual `ConversionSession`/Project/Type2 SUB/Study, and a bound RecordingStudyIo; each asserts the expected guard and inspects `saved.project.xmlJournal`. This is materially stronger than testing only `writeType2InputTableXmlPrefix` directly and proves that the alias points to the same journal that receives the immediate device observations.

The tests are recording-sink evidence. They do not exercise the native `saveProjectFileNative` alias, nor prove any native disk residue. Keep the exact recording bytes explicitly labeled as simulated. The separate native-device test can establish normal scratch-file bytes for one success case, but not partial-byte persistence under native failure. For NativeStudyIo fault cases, assert attempted/opened state, raw acceptance where actually exposed, close sequence and post-close QFile.error only; leave final bytes unknown absent a separate readback observation.

## Minimal next source slice

For the current guarded stage, retain the existing single journal owner/store, document the open/truncate event semantics, and keep fault profiles explicitly positional/test-only with test assertions for ordinal/path. Keep the public test on `engine::saveProject` and assert its thrown refresh guard after ordinary XML true/false; do not invent receiver delivery. A self-contained writer/refresh result surface and public conversion overload are follow-on work, not prerequisites for this caller-owned recording test. Native writer observation remains a separate follow-on interface.

Before enabling multi-attempt/PAR/full Save claims, add version identity and event ordering across the journal and subsequent same-path store writes. XML-only sequencing is sufficient for the current refresh-guard prefix; it does not yet establish a single global order with later PAR and final `.moproj` writes.
