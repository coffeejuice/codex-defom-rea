# CP321–324 inert occurrence integration contracts

CP321 adds independently reviewed canonical Windows x64 ctypes layouts and an injected binder that gives each export its own function prototype. This avoids accidental mutation of cached DLL function signatures where earlier pipe, security and image helpers used different ctypes structures. Import and live factory remain inert.

CP322 joins the CP319 private descriptor owner to CP317's two named-pipe lifecycle in a fake-injected seam. Independent review found that a failed token close could lose its owner, failed `CancelIoEx` could prevent a retry, and event creation could consume the deadline before I/O submission. CP319 now carries a retryable token owner on both FALSE and exceptional close, while CP322 retains that owner, checks the deadline again before every submit and keeps failed cancellation retryable. CP322 accumulates short 48/80-byte transfers under the original deadline. CP323 independently models a separate empty CHILD job: only WORKER enters creation-time JOB_LIST, the CHILD handle is duplicated noninheritable into the suspended WORKER and retained as remote ownership. CP320 image verification and termination-before-I/O-cleanup order are represented. CP324 validates the inert 48/80/48 transcript, zero child telemetry and nonce; review added a required nonblocking check for already queued duplicate bytes before ACK. That check does not prove no future bytes will arrive.

Root ran CP3xx tests through CP324 from converter root and `admin`: 340 passed in each order. Exact source hashes, including the CP319 cleanup repair, are in `analysis/cp321-324-static-validation.json`. No CP316 worker, child, original application or GUI session was run. These are reviewed declaration/injected-contract layers; they do not establish native endpoint, job, loaded-image, process or cleanup behavior.
