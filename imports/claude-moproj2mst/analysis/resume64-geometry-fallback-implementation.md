# CP64 unqualified geometry fallback refusal

Unqualified positive-count geometry readiness now leaves the complete item
contribution unknown and returns before raw rectangle arithmetic. Qualified
Populated still performs both native getter rounds; known Skip remains a
successful edge-only contribution. This deliberately tightens historical
synthetic acceptance while preserving its retained diagnostics.

Exclusive edited files: `source/apps/moproj2mst/src/engine/viewer.cpp`,
`source/apps/moproj2mst/tests/mdt/test_viewer_box.cpp` and this report. No shared
interface/CMake edit, build, CTest, GUI or mutable REA action was performed.

## Source qualification and change

`analysis/resume64-geometry-fallback.md` supplies exact source/native routes,
original evidence references and limitations. Original DEF_GUI_MO_64.exe SHA-256
is `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`.
The native caller only reaches `14124bec0` after readiness `1408ee940` and the
second coordinate/connectivity getters at `14126d2c5`/`d2d4`. No demonstrated
route substitutes raw arithmetic for unknown virtual/synchronization effects.

`refreshGeometryItem` now handles Unqualified explicitly, sets rectKnown=false
and returns after its already sampled edge prefix. `geometryMeshRect` also
requires Populated at entry before reading builder fields; its second getter
round is unconditional after that check and uses the returned arrays. There is
no remaining raw pointer fallback for Unqualified.

Existing modelRectKnown propagation and scene-box candidate selection remain.
The adapter throws existing M2M_E_UNSUPPORTED only when the scene actually needs
the unknown rectangle contribution. Refresh itself does not throw, and the
change does not claim the original returns that adapter error. No owner, flag,
dimension table, default array, unknown virtual call or allocator is fabricated.
Positive-count preflight and zero-count early skip remain in their previous
order. CP62 ownerless and CP63 actual-owner/nonzero-byte branches are unchanged.

## Tests and intentional expectation changes

The Testkit file now has19 unique cases (two new cases plus expanded matrices).

- The CP63 guard matrix now expects unsupported for all rejected populated and
  null-connectivity profiles. This changes its four prior populated successes:
  actual owner/zero u1b58, opaque E owner, another valid model's N owner and id0
  registry. It retains the already refused absent-coordinate cases and adds an
  opaque N-owner profile. No getter dispatch or collection detach is accepted.
- The registry matrix now checks populated and null connectivity with id0, null
  entry, custom-derived slot2 and noncanonical count. A shared list-storage lease
  requires the same body/refcount through refusal, and the custom slot call count
  remains0. Registry restores precede variable-owning mesh destruction.
- New restoration case covers each of the four previously accepted profiles:
  qualified populated -> unqualified populated refusal -> restored qualified
  populated. Both successful phases observe two real n4/key0 getter dispatches
  with actual step dimensions and Ymax1 bounds; refusal observes no dispatch.
  Source arrays, restored owner/flag fields and unique COW body are checked.
- New zero-count case puts opaque owners and id0 registry on an otherwise
  populated fixture, then empties nodes or elements. It observes no getters or
  detach and retains known edge-only Ymax0, proving the count guards still
  precede owner/registry admission.

Existing qualified populated/shared/unique COW, actual-owner/nonzero truthiness,
known connectivity-null skip, malformed builder and populated-to-skip-to-
populated tests remain. All use CHECK/REQUIRE and the existing Testkit entry.
Static preflight confirmed19 unique names, no C assert or unsupported REQUIRE_EQ,

Root target: **`m2m_mdt_viewer_box`**; CTest: **`m2m.mdt.viewer_box`**. Root owns
