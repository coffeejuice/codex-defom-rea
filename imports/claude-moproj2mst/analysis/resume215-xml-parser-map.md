# CP215 original XML and project-reader boundary map

The prior valid encoded B98 Open observations establish suffix acceptance, a nonzero Project, and synchronous postOpen activation. They do **not** read the Project's XML status byte. A single same-occurrence read of `P+0x55` at the already qualified `OpenProject` return is the smallest direct status witness. The copied original's control flow then gives that byte a precise, narrower meaning: `ReadProjectFile` returned true after QFile opened, `QDomDocument::setContent` returned true, and `WalkProject` returned true. It does not certify every nested parser or a complete application Open.

## Exact original boundaries

Addresses are RVAs under image base `0x140000000` unless written as full VA.

The instruction bytes at `8ae0c` are `e8 8f 01 00 00`; at `8ae1d` they are `44 88 58 55`. At `8b27e` they are `e8 8d 01 00 00`. These exact direct edges and the source-qualified decompile support the return propagation. The `setContent` target is an imported QtXml call; its name is qualified by the retained decompile/import mapping, while the observed machine branch is the indirect call/test. This distinction matters if the loaded module or import binding changes.

## Result classification

**Established statically:** the `.moproj` caller stores `ReadProjectFile` AL in `P+55`; true implies successful QFile open, successful Qt DOM `setContent`, and true top-level `WalkProject` return; `OpenProject` AL=1 is independent. **Observed previously:** CP213/214 valid encoded-path acceptance; CP214 activation normal return, with no P+55 sample. **Still unknown for original B98:** actual P+55 value, whether the main diagram parser completed and with what state, subsequent view/timer effects, Save, accepted Close, and full original-versus-candidate lifecycle parity.
