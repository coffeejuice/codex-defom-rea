# CP408 contained WORKER console-creation experiment

CP407 correlated an extra exact inner outer-job PID with `conhost.exe` and the contained runner as reported parent. Its point-in-time snapshot does not establish which process-creation call caused the console host. The strict outer=2 gate remains required; accepting any third process by basename would weaken containment.

CP408 changes only the inert CP329 WORKER `CreateProcessW` flags from `CREATE_NO_WINDOW` to `DETACHED_PROCESS`, retaining `CREATE_SUSPENDED`, `EXTENDED_STARTUPINFO_PRESENT`, explicit `STARTF_USESTDHANDLES`, inherited pipe endpoints, `HANDLE_LIST`, `JOB_LIST`, exact image pin, deadline and no-resume-before-ACK contract. CP331/CP349 runner flags remain unchanged. [Microsoft's creation-flag contract](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags) describes detached console processes and states that `CREATE_NO_WINDOW` is ignored if combined with `DETACHED_PROCESS`; [STARTUPINFO](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-startupinfow) requires inheritable explicit standard handles when `STARTF_USESTDHANDLES` is set, as CP329 already provides. This is a bounded experiment to test whether the WORKER creation caused the extra console host. It is not yet a proven repair.

`analysis/cp408-detached-worker-tests.log` records 640 passing CP3xx tests from each supported root. Injected CP329 tests assert the exact detached flag set while preserving the shared runner flags. Independent review confirmed the worker-only source use, unchanged pipes/job/handle attributes and Windows flag semantics. Its first read mistakenly inspected an unrelated C++ supervisor; a corrected exact-file read and root Git diff resolved that discrepancy.
