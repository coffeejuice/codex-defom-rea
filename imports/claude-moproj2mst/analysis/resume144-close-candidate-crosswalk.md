## Exact missing witnesses

1. **Public entry:** no source-produced candidate application/main object supplies the actual singleton+9, current main phase/identity, QWidget stack index/main mode, process/modal state and accepted callback occurrence. Supplied qualified strings, run mutexes, MainView or previous Save's false-busy do not create that producer.
2. **Nonempty child dispatch:** no candidate native Mo deleting coordinator binds one manager child/epoch and its live Project through accepted preconditions, same-owner rereads and predecessor effects. `DbHandle::~DbHandle` cannot be used as that coordinator while also serving ordinary adapter cleanup.
3. **Project release:** actual P+60 needs its complete native constructor and Open feature registration/query/provider history. Current anchor starts the logical constructor attempt but stops at the first actual proxy heap profile; isolated C/M/A/H frames have no source-bound link to this Project and its unknown feature bytes. New encoded-role/CRT work does not supply that link.
4. **Published DOE objects:** ultimate typed virtual0/global-retainer closure for the exact manager/optimizer allocation remains missing. The feature-provider pointer and these raw SUB slots have different construction provenance; native bodies do not supply a deletion order or permanent-retention guarantee.

There is no need to rediscover the original deleting target. Native conditional chain/slot identities are closed; candidate/source-owned state and unfinished effects are the blockers. No new inert Close flag/frame or “all skipped” helper should be presented as resolving them.
