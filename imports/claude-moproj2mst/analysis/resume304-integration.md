# CP304 fake-only supervisor protocol

CP304 added a private in-memory supervisor/worker protocol for one suspended CP302 clone. It stages the CP303 job seam, binds a creation-owned worker handle, duplicates an offered worker-local child handle into the supervisor, and independently compares the duplicated handle's PID, creation FILETIME and image path with the offer and fixed supplied image contract. It models one occurrence-bound ACK and ordered job, child, worker and handle cleanup. It never launches a child, resumes a thread, uses GUI control or runs the original.

Independent review found two overclaims in the first draft. Echoing an ACK value did not prove that the worker accepted it, so the retained status is now `matching-unverified-claim`. Failed cleanup no longer discards exact handle values; repeated cleanup can retry them within the supervisor lifetime, and job closure is deferred until child and worker handles close and job accounting reports zero. Final independent review passed for the fake-only scope. Root ran all 12 fake tests. The source and log hashes, raw log and gate list are in `analysis/cp304-fake-validation.json` and `analysis/cp304-fake-tests.log`.

This is not evidence that a real worker receives the job duplicate or ACK, that an offered handle is live, that the child belongs to the job, or that a loaded image matches the pinned CP302 bytes. A worker interrupted inside `CreateProcessW` leaves child existence unknown. CP305 is selected to compose the fixed CP302 clone, CP289 retained-handle callback, CP303 creation-time job assignment and this protocol in a private fake-only transaction. A later separately reviewed fixed harmless run must independently establish real identity, containment, waits and cleanup before original execution can be reconsidered. The latest complete converter validation remains CP301: 392 CTests and 373 source-bound m2m tests, with six logged gaps, one diagnostic difference and five historical Save differences.
