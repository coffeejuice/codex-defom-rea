# CP279 positive-only color witness review

The independent methodological review found CP279's first draft over-applied CP277's five-address and overlap requirements. CP277 blocks the full CP214/Open occurrence contract. It does not automatically block a separately reviewed positive-only witness that claims only one helper entry. The CP279 design was corrected accordingly; original execution remains HOLD because no original-capable observer or independently reviewed lifecycle and neutrality proof exists yet.

A sound positive entry claim binds the immutable image and loaded module/base, exact entry/caller bytes, owned child and TID, verified breakpoint cause and RIP, raw entry RSP and `[RSP]` return PC, selected arguments, and an explicit failure result for unreadable state. The captured caller identity must be qualified by its call instruction. A paired return claim additionally preserves that entry record, matches TID and caller frame (normally entry RSP+8), handles other return hits without overwriting the selected record, and treats unwind, timeout and thread exit as incomplete. A continuation hit alone is weaker than proof of a normal return transfer.

The narrow positive witness cannot establish absence of nested/repeated/other-thread entries, callbacks, palette mutations between samples, complete color effects, binder continuation, completed Open, or the full CP214 chronology. Hardware comparator blind intervals remain recorded. Each later claim needs its own evidence and review. The CP278 synthetic RCX check is not an original ABI predicate. No original/GUI/REA execution occurred during this review.
