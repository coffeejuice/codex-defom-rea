## Write and failure order

**Original, source-qualified order:** native `0x1407617e0` forms the Cogging path and calls `fopen(path, "wt")` before `masterWrite` (`0x14076a8c0`). If open returns null, the writer jumps to its return-1 path without entering `masterWrite`; retained Save analysis says this is treated as handled success, so later property rows and MST writing can proceed. If open succeeds, `masterWrite` runs before Process Data fields. The retained CRT writer contract says individual `fprintf`/close results are ignored; after a failed buffer flush, later print calls are still attempted. These are defined write-failure order facts and do not resolve the separate invalid read for two reheats. If that read faults, later stages may not run; if it returns, the exact adjacent bytes are unknown.

**Candidate `M2M_FLAG_WRITE_MDT` / CLI `--write-mdt`:** `convert.cpp` uses the aggregate recorder (`nativeSave == false`). Cogging side files are serialized into memory by `saveCoggingMdts`/`writeMdtBytes`; they are applied only after the conversion has completed successfully. The writer emits up through `NoReheats`, then throws `M2M_E_UNSUPPORTED` for count 2 or greater. The exception is caught by the conversion boundary before the final side-file and MST write phase. Therefore a public `--write-mdt` test on a disposable project can pin the current candidate refusal and verify that the original MDT and requested MST remain untouched/absent. That result documents the port’s conservative guard; it does not predict original failure or bytes.

**Candidate `M2M_FLAG_WRITE_SAVE` / CLI `--write-save`:** this selects `nativeSave`. `saveCoggingMdt` opens/truncates the target through `CoggingFile` before it calls `writeMdt`; the candidate guard therefore throws after open, unlike the `--write-mdt` staging path. Exception propagation stops the property loop and candidate MST phase. `CoggingFile` closes during unwinding, but the exact buffered prefix left by this candidate path has not been exercised here and should not be claimed from inspection alone. This candidate behavior is a separate failure-order case from the original null-open continuation and from native undefined multi-reheat output.

For ordinary disk-write failures, the candidate paths also differ. `--write-mdt` stages all side bytes and `writeAtomically` applies Cogging MDTs only after conversion; an apply failure aborts later applies/MST. Native `--write-save` writes the Cogging file directly and its `fprintf` returns are ignored, allowing later writer calls if no C++ exception interrupts the path. Neither statement establishes old CRT disk-full byte parity beyond the specifically retained buffered-flush observations.
