# CP414 terminal pipe-phase diagnostic integration

CP413 established a CP328 absolute deadline Hold after CP333 entered terminal read, without locating the failing boundary within that transfer. CP414 stores a fixed `last_transfer_phase` on the existing CP328 transfer/finish path. It adds no native call or clock read. The phase persists through `_hold()` and cleanup so CP333 can emit one fixed `cp333_pipe_*` marker immediately before its existing primary-error marker, only when the original exception includes the literal `absolute pipe deadline expired`. The original exception and acceptance path are unchanged.

The phases bound initial operation/submit/I/O, wait budget/result, event close, post-operation budget, final budget, and completed transfer. They locate the last reached boundary, not elapsed time or a complete Win32 call trace. In particular `wait_budget` may represent an initial wait budget or a budget after a timed-out wait. The fixed CP349 parser allowlist retains its existing 40-record/2048-byte limits. The CP413 prefix has 36 records; adding one failure phase would make 37, so that known failure form fits. A full 40-record success trace adds no failure-only phase.

Injected CP328 tests cover deadline expiry before operation, at wait budget, and after operation completion; CP333 verifies marker order and preserved primary error; CP349 verifies parser acceptance of the fixed marker. The CP3xx suite passed 643 tests from both supported module roots, with `-B`, in `cp414-phase-integration-tests.log`. `git diff --check` passed. Independent current-source review found no concrete ownership, cleanup, deadline or acceptance regression, but could not compare Git diff because the reviewer agent lacked checkout access. Root inspected the exact diff and confirmed that limitation.

CP415 is the successor: freeze and push the candidate, independently gate one fresh monitored inert occurrence, then interpret the new phase only together with exact monitor and cleanup receipts. Do not retry CP413, extend the fixed deadline, or infer original application behavior from this inert harness.
