## `P+0x55` timing and meaning

Direct PE bytes confirm `8ae0c: e8 8f 01 00 00` calls `8afa0` and returns at `8ae11`; `8ae11` zero-extends AL into R11D; `8ae1d: 44 88 58 55` writes R11B to `[P+0x55]`. This is the selected `.moproj` suffix branch. Entry initialization zeros `[P+55]` at `8a9d5`; that early zero is not a read result. The common normal tail sets its independent acceptance byte to 1 at `8af74`, reloads AL at `8af87`, and returns at `8af95`. Thus an `8a9b0` acceptance onLeave read is after the branch's `P+55` store and before the outer loader's return, provided the decoded selected B98 `.moproj` path and normal caller return `1d0fb` are qualified. Read exactly one guarded raw byte from the saved entry RCX P, require AL=1 and later outer returned P equality; do not coerce an unreadable or non-0/1 byte to a Boolean. A zero is a failed `ReadProjectFile` result for that branch, while acceptance AL=1 can still occur.

Source-qualified `open0.c` and the bounded `8afa0` disassembly identify the true-return chain: QFile opens with ReadOnly|Text; QtXml `QDomDocument::setContent` returns true; `8b27e: e8 8d 01 00 00` calls `8b410`, whose AL is stored at `8b283` and propagated through `8b2b6` to return. The retained walk decompile shows an explicit false return from `Operation_List` parsing, but ignores `8f200` results for non-main subprojects. Main subproject zero is parsed lazily on activation via `8f530`. Therefore `P+55=1` supports the three top-level successes only; it does not certify every nested parse or application Open completion. A separate `8afa0` hook is unnecessary for the minimal field witness and would need its own reviewed release.
