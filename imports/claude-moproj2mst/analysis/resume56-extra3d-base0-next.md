# Checkpoint 56: Extra3D base-0 extraction follow-up

## Original versus candidate

The retained `analysis/wave2-save-diffs-qt-textstream-getinteger-complete.asm` is the QtCore `QTextStream` integer getter (`0x670c5210`). With the stream base field at zero, it inspects the first non-space character and dispatches prefix forms: `0x` to base 16 (`0x670c53d3`), `0b` to base 2 (`0x670c53ef`), and leading `0` without either prefix to a base-8 accumulator (`0x670c57cc`; multiply by 8/add digit at `0x670c5848`). Thus ASCII token `010` is the smallest next useful case: the retained original getter parses it as octal value 8. The original fill callsite reads one integer from `SW2SP.DAT`, so this can be isolated without a multi-field row.

The candidate currently accepts only exact lowercase `0x2` as a special case plus its bounded signed-decimal grammar. Its prior regression test still expects `010` to be unsupported. That is intentionally conservative but now leaves a concrete, source-qualified discrepancy. The next smallest increment should add only the exact token `010` → 8 (end or ASCII-whitespace delimiter), with the same candidate-only `SW2SP.DAT` adapter test pattern. Other octal forms should remain guarded until their range and digit-consumption behavior are separately pinned.

## Boundaries considered

- **Whitespace:** The getter first skips stream whitespace via its QChar classification calls before base selection. Candidate `readDecimalInt` skips bytes 9–13 and 32. Those ASCII cases are consistent with the observed `KnownC` input profile. Non-ASCII Unicode whitespace remains outside the candidate decoder's ASCII gate, and the original file codec/runtime behavior for such bytes is not established here.
- **Signed hex:** Do not expand `0x2` to signed or uppercase forms on this evidence alone. The retained getter contains sign handling in the ordinary numeric path, but the visible automatic-base dispatch tests the first non-space character for `0`/prefix before the ordinary branch. This audit does not establish whether a sign preceding a radix prefix reaches the prefix parser in the original call context.
- **Overflow:** The disassembly accumulates into a wider register and later applies sign/range logic, but this bounded note does not establish all boundary outcomes for `int` destinations. Candidate decimal overflow still returns the existing unsupported error; leave hex/octal overflow guarded.
- **Trailing/partial rows:** The original `0x1410da690` file helper initializes every requested destination to zero, then attempts extraction while `!atEnd()` and the index is below the requested count; it does not branch on the extraction result in that loop. The Qt operator wrapper distinguishes successful conversion from failure and updates stream status, but exact cursor/status/next-element effects for malformed prefixed tokens are not fully qualified by this note. Candidate initializes the destination span to zero but throws on unsupported syntax, so it has no returned partial row for malformed inputs. Keep that behavior guarded; the one-element valid `SW2SP.DAT` case avoids the distinction.
