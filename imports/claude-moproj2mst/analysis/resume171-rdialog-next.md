# CP171 default Report/dialog dispatch recovery audit

## Finding

No bounded original internal branch in the default Report property/dialog path is ready for production source work. The narrowest source-backed behavior is the Report property callback family (`0x1412b1f50`) and the original Report Open/Save/Close edges already documented in CP164/165/169. The callback family is not publicly reachable in the converter today: `saveCurrentOperation` refuses Report before `propsToEngine`, and Report load refuses at its document accessor. Do not loosen the generic `properties vt+0x60` refusal or add a standalone Report property helper; either would omit the actual owner and entry sequence.

The default-answer question does not change this conclusion. Static constructor/default-button evidence is not an observed answer or delivered modal-loop transcript for a Report Save occurrence. Existing dialog work (CP160) shows why: `QDialog::exec` performs show before entering the nested loop, and completion/unwind effects continue after `done(int)`. Timer registration/request is not proof of callback delivery. That modal trace cannot be transplanted onto Report without evidence that this Report path invokes that dialog and without binding its actual event/receiver state.

## Exact owner/modal blocker

The required owner is the live `SfSessionManager` document `D` published in the active `SubProject S + 0x30`, with generation and QObject parent/lifetime. Open obtains a fresh `P`, derives the sibling `.DS` path, then independently resolves active `S` and lazily constructs or reuses `D`; it uses that returned `D` for reset/read/traversal. Save does a fresh active-S/document lookup, so the same Report receiver does not establish that it gets Open's `S` or `D`. Save's current `D+0x68` selects the default branch only if still 1; signal/virtual callbacks, fresh task/list reads, serializers and DOM/file work leave effects unbound. Close rereads `S+0x30` twice and conditionally deletes its second current value before clearing the guard. Neither a stable owner nor parent-child destruction order is established.

The missing evidence is one natural original Report **Open → Save → accepted Close** trace. It must bind fresh `P/S/D` identities and document generation at every lookup; proposed and accepted QObject parent, child-list delta, connections, both lazy slot reads, reset/read/traversal, relevant D fields, Save's default branch and signal receivers, task/index/list/serializer/DOM/file outcomes, any interactive-payload or SessionRoot append path, Close admission, both slot reads, guard clear, and destruction order. The dialog portion must capture warning invocation, `exec` entry, show, nested-loop entry/exit, actual activation and `done(int)`, completion/unwind callbacks, exec/Save return, and timer/receiver delivery/liveness/affinity where applicable. A missing callback log is not evidence of an empty delivery interval without coverage/loss evidence.

## Source-ready boundary and tests

The only admitted Report prefix remains the pure sibling `.DS` path helper. The diagnostic `report_document_slot` token does not model constructor publication, live per-S slot reread, rebind, QObject-parent death, or Close guard clear. DOE `SessionRoot` fixture behavior is not Report acceptance. Keep Report Open/Save/Close public guards and the generic dispatcher refusal.

No tests were run or changed in this read-only audit. Once the owner/occurrence is represented, focused tests should cover same-S publication/reuse and slot reread; active-S rebind across commands; failed allocation/parent acceptance; reset/read failure after publication; default and alternate Save branch plus payload/DOM/file outcomes; and Close first-null versus changed-second-read. If the modal path is confirmed, add a trace-driven default answer/timer-delivery test that distinguishes requested, registered, due, delivered, and completed events. Then use the normal focused source-stable regression and freeze gate.
