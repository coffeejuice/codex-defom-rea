# CP276 mode-1 3D color helper: HOLD

The original is `evidence/original-binaries/DEF_GUI_MO_64.exe`, DEF_GUI_MO_64 v11.0.2, SHA-256 independently checked here as `fd8ae1f8dd50d068267b3b7e49efdf11eaa178889131e59ec4b6f8de64725acc`. New evidence is bounded MSVC DUMPBIN 14.44 read-only disassembly of the immutable PE, principally `0x1411f26e0..0x1411f28dd`, `0x14126ea90..0x14126eb07`, `0x14122fb10..0x14122fb87`, `0x14126f0c0..0x14126f0e6`, `0x14126f300..0x14126f330`, and `0x141696820..0x141696843`. ## Native control and partial-effect order

`FUN_1411f17f0` binds a nonnull object and calls `FUN_1411f28f0` before the optional Slice adaptation and node display. With effective mode 1, `FUN_1411f28f0` calls `FUN_1411f2430`; an ordinary non-2D, dimension-3 object enters `FUN_1411f26e0`. The latter returns immediately for View+`0x18 == 0`. For a nonnull object it performs the following sequence, with no catch, rollback, or failure-status branch visible in this body:

1. Construct a temporary color object at stack+`0x30` through import `0x141e0b5d0`. Read object+`0x0c`. For kind 5 call `0x1402d4f90(0x143d77590, ...)`; for every other kind call `0x1402d4e30(0x143d77590, ...)`. Assign the returned value into the temporary through import `0x141e0b5c8`.
2. Obtain another value from `0x1402d4df0(0x143d77590, ...)`; lazily obtain View+`0x38`'s first representation through `FUN_1411f36d0`; call `FUN_14126ea90(rep, value)`. Obtain the same representation again and call `FUN_14126ead0(rep, temporary-color)`. These two wrappers first update a receiver subobject at rep+`0x458` via `FUN_14126f0c0` or `FUN_14126f300`, then call `FUN_141237c70` or `FUN_141237d00`. `FUN_14126f300` assigns a color-like member at its receiver+`0x38` and sets receiver+`0x4c` to 1. The second calls are additional effects/callbacks whose bodies have not been qualified.
3. Obtain `0x1402d4e70(...)`; lazily obtain View+`0x40`'s first representation through `FUN_1411f3770`; call `FUN_14122fb10(rep, value)`. Obtain `0x1402d4eb0(0x143d77590, ..., object-kind)`; obtain that representation again; call `FUN_14122fb50(rep, value)`. The two wrappers have the same respective rep+`0x458` setter/callback pairs as step 2.
4. For `i = 0` through the current count of View+`0x48` items minus one, in increasing order: obtain `0x1402d4df0(...)`, get/create item `i` through `FUN_1411f3810`, call `FUN_14126dcd0(item, value)`; then obtain `0x1402d4e30(...)`, get/create the same item, and call `FUN_14126ddc0(item, value)`. Both item setters first seek an item subobject via `FUN_14126cae0`, then branch on its condition/count and call further unqualified helpers. A zero item count skips both per-item calls.
5. Call `FUN_1411f3430(view)` once after the loop. Its first instructions call `FUN_1411f3320`, `FUN_1411f19f0`, dimension predicate `FUN_1400c3530`, and on the 3D route `FUN_1411f36d0` followed by `FUN_141235890` when the representation exists. Its remaining body and effects were not recovered. The helper then performs the compiler stack-cookie check and returns.

The partial prefix is therefore constructor and palette selection, first representation's two ordered setters, second representation's two ordered setters, two calls for each item in order, then finalization. Any exception or nonreturn in a called constructor, lookup, lazy creator, setter, callback, or finalizer stops the later prefix and prevents the outer binder's Slice and node calls. Static inspection does not establish which calls can throw. In particular, the body is not a pure View flag update, and a zero geometry-item count does not avoid representation setters or finalization.

`FUN_141696820`'s DUMPBIN body returns the value from `FUN_1416990a0` or `FUN_141699130` in `eax`; the retained `void` pseudocode signature is wrong for this caller. Both branch getters read an integer through `FUN_1408085c0`, fall back to their respective constant-returning helpers (`FUN_141699090` and `FUN_141699120`, each returning 1) if the read value is below 1, and write that fallback via `FUN_1408086c0`. This proves a fallback minimum/default of 1, not that every fresh run selects 1: the stored preference may already be 2 or greater. The branch choice from `FUN_141696890` and the fresh-session preference state remain unqualified.

## Actual converter caller and implementation gap

`source/apps/moproj2mst/tests/mdt/test_viewer_slice.cpp::slice_rebind_for_canonical_3d_null_db_owner_preserves_collection` creates `GuiModel(nullptr, 3)`, obtains object 1 via `objectWrap`, and invokes `engine::viewerSync(model, object, true)` followed by two `viewerSync(..., false)` calls. `viewerSync` resolves a real View, calls `bind`, then proceeds to Settings and refresh when binding returns. `objectWrap` itself also calls `viewerSync` when it creates the object. This is an actual ordinary 3D bind witness, including a rebind with an existing Slice collection. It is not an original mode-1 color oracle: the test does not set or assert owner+`0x25c`, the process preference, object kind at +`0x0c`, the complete palette, representation color members, item subobjects, callback effects, or a failure prefix. Existing converter `Rep` retains only patch mode and box; `GeometryItem` retains binding/index/rect. The native rep+`0x458` color state and item color subobjects have no corresponding source state. The current `bind` leaves color and node behavior unimplemented after representation binding.

The smallest missing fact for implementation is the **observable contract of the first rep setter and its callback**: the value from `0x1402d4df0`, exact receiver state set by `FUN_14126f0c0`, and effect of `FUN_141237c70`, followed by the analogous second setter and finalizer. For the ordinary fixture, also establish the fresh effective mode and object kind. Without those, even a zero-item mode-1 3D path cannot be assigned faithful values or partial-effect behavior. A PASS-ready successor should recover these bounded callee contracts, map state to the converter and an actual `viewerSync` fixture, and state a checkable original-output or state oracle. No source/test/build/GUI/original-execution action was performed here; only this report was written.
