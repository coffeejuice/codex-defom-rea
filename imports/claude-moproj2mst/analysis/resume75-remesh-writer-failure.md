# CP75: remesh-open boundary and next writer-failure gap

## What CP74 establishes

The new public regression is candidate-specific: the project-output test service declares error 7 after its real delegated project QFile-like Close, then creates and write-locks `LOCAL_REMESH.DAT` from `aboutToClose`. It expects Boolean BWZ/INI and MST effects, preservation of the sentinel remesh bytes, and the current adapter's `M2M_E_UNSUPPORTED` guard. This is a useful orchestration test if it passes; it does not establish original runtime behavior for a failed remesh open.

The static original evidence makes the qualification important. `analysis/wave3-remesh-save-lifecycle-contract.json` binds Save's enabled branch to `0x1400abcc0`: `fopen("wt")`, then the ordered `fprintf` calls, then `fclose`, with no open, print, or close result checks. `analysis/wave3-remesh-invalid-parameter-startup-contract.json` shows that failed open passes null to the first `fprintf`; for the initialized default invalid-parameter handler, the conditional path reaches `TerminateProcess(0xC0000417)`. No original failure was induced, and custom handler state is not runtime-tested. Consequently the CP74 adapter's `M2M_E_UNSUPPORTED` result must remain identified as an intentional refusal boundary; it is not an original returned status. The terminal original path would leave earlier project/property/MST effects and retained target bytes, but would not reach Save status reporting or later Close.

## Next source-qualified branch

After a **successful** remesh `fopen`, the source has a separate, nonfatal writer-failure contract: all formatted writes and `fclose` are attempted, their return values are ignored, and the Save tail does not derive its return from them. This is distinct from the fatal/default failed-open boundary. A post-open write/flush/close failure can leave a truncated or partial `LOCAL_REMESH.DAT`; the exact residue is not established and must not be asserted from source alone. Earlier BWZ/INI/MST outputs remain in place. Absent an earlier project/MST/reporting outcome, the enclosing GUI Save returns its previously selected status local; the remesh writer contributes no checked failure status. The public adapter's current remesh implementation similarly treats post-open I/O errors as ignored, while failed-open remains guarded.

Coverage is incomplete. `tests/mdt/test_simcontrol300_remesh.cpp::remesh_native_save_matches_original_literal_derived_default_bytes_and_closes` and neighboring success cases prove the full successful output. `remesh_native_failed_write_open_preserves_file_and_marks_invalid_parameter_boundary` covers only open denial. No current fixture forces a failure after `fopen` succeeds or records the remaining fprintf/close attempt order. CP74's public test also fails at open and cannot exercise this branch.

## Smallest safe next test and dependency

Add a private, per-call remesh output seam at the existing Save-tail boundary, leaving the default production path on the real `CoggingFile`/CRT implementation. It needs only operations corresponding to successful open, each ordered formatted-write attempt, and close; injected results can fail after a chosen write while recording all later calls. A focused leaf regression can assert: Open succeeded; the selected write reports failure; subsequent writes and Close are still attempted; the helper reports its ordinary post-open completion (or no checked writer error); and no exact on-disk prefix is claimed. A public integration variant can then combine the injected remesh result with CP73's declared post-close project error and check the already-completed MST plus project-status precedence. Keep `Result` and Save-call adapter status explicitly separate from the original GUI's earlier status local.

The current seam does not exist: `saveRemeshAtProjectSave` constructs `CoggingFile` directly and calls the CRT formatter on its `FILE*`. The narrow dependency is therefore a private injected writer/operation interface, not another Windows lock recipe. The existing lock test is reliable for preventing open, but cannot produce a deterministic post-open disk write/flush failure or support a justified byte-residue assertion. Do not induce null-`FILE` host behavior, and do not treat this test-only seam as evidence of a fresh original runtime fault.
