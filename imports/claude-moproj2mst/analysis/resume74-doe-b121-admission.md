# CP74 B121 scalar admission boundary

## Decision

Do not wire the CP72/73 root-level model projection into public `readInputTable` or enable B121 Type 2 conversion yet. There are two earlier lifecycle gates and a parser-order mismatch:

1. **Type 2 ownership/selection:** public conversion currently calls `activateSubProject(p, 0)` (`src/core/convert.cpp:235`). B121's post-action project places the DOE Type 2 subproject after the Type 0 base project; index 0 therefore does not activate the study. `makeSubProject` does create an owned `Study` for Type 2 and aliases `sub.doe` to it (`src/model/subproject.cpp:289-306`), but `parseSubProject` will enter lazy DOE loading only for the active subproject's `<SfDoeStudy>` and requires the owned study, pointer identity, and configured project DOE I/O (`:384-388`). Thus the earliest public lifecycle prerequisite is selecting/activating the intended Type 2 subproject while preserving the real owner and I/O bindings.
2. **Input-table file lifecycle:** after `SfDoeStudy` admission, `readLazyStudy` sets the study name, reads `DoeInputTable.XML`, then loads `Samples_LHS.par`, `Samples_FF.par`, `Samples_USR.par`, and current `DEF_DOE.PAR` in that order (`src/doe/activation.cpp:31-45`). An exception in input-table parsing prevents those later sample reads; it cannot be modeled as a completed, successful variable parse.
3. **Root-child order and notification:** native outer reader `0x14090e080` visits each root child in document order. For B121, `DoeVariables` calls `0x14090ee20` first; root `Operations` is a later sibling and dispatches to `0x140912a20`. Within the variable reader, the scalar path appends variable/keyword state and nested `KwOperations`, reaches `2signalSetOprHasDoe(true, 1)`, then continues with parameter/type flags, nominal text setter, variable reindex and final return. Only afterward can the outer reader process the distinct root `Operations` map. The variable-body static receipt, `analysis/resume50-doe-variable-body-pe.md`, qualifies this order and the prefix mutations left behind if the unresolved delivery refuses.

The CP72/73 helper deliberately reads both nested `KwOperations` and the later root `Operations` map into a completed model at once. It is useful as an isolated candidate-only model/format projection, but integrating it directly at `DoeVariables` would move a later input effect earlier and leap over the unresolved signal, setters, and reindex. The public reader remains guarded at its existing nonempty `DoeVariables` branch (`src/doe/doe_study.cpp:375-386`); keep it there until those ordered stages and owners are supported.

## Earliest exact integration branch

After real Type 2 activation and owner checks, the first source integration point is the outer `readInputTable` child dispatch for **`DoeVariables`**, which maps to original `0x14090ee20`. It should eventually call a phased B121 variable reader that records the native prefix in order and stops at the first unresolved effect. It must not read root `Operations` at that point. The later `Operations` dispatch (`0x140912a20`) should be its own phase, preserving the root mapping separately from the nested keyword-operation list.

The first phase still cannot claim a successful B121 load. Static evidence says the manager emits `2signalSetOprHasDoe(true, 1)` after keyword/list commitment but before later selector/type/text stores and final index/relink. Current `B121ScalarVariablePrefix` (`src/doe/variable_prefix.cpp/.hpp`) represents this stop with a pending signal and refusal; it is not connected to the actual live receiver list. A clean integration test must preserve that stop and the prefix state until a live notifier/receiver binding, callback order, and normal completion are qualified. The isolated model helper's nominal fields and writer are not substitutes for that callback.

## Concrete next source/test files

1. `src/doe/variable_prefix.hpp/.cpp`: extend the staged candidate prefix into a typed scalar payload attached to the actual owned Study variable, while preserving the existing exact stop at pending `2signalSetOprHasDoe`. Tests should assert selector/type/text remain unset before delivery and are not silently applied after a refused delivery.
2. `src/doe/variable_notify.hpp/.cpp` and its focused binding tests (`tests/doe/test_variable_notify_binding.cpp`, `tests/doe/test_variable_prefix.cpp`): qualify the actual session-owned receiver registration and its ordered effects for the B121 `true, operation 1` event before allowing the parser to continue. Keep wrong/stale owners refusing without a success claim.
3. `src/doe/doe_study.cpp` plus a focused test in `tests/doe/test_b121_tloc_model_prefix.cpp` or a new `tests/doe/test_b121_tloc_read_order.cpp`: split the current all-at-once helper into ordered DoeVariables and later Operations phases. Assert the first phase leaves a pending boundary and the second phase does not run before it; preserve the distinct nested and root operation lists.
4. `src/model/subproject.cpp` and the conversion driver only after the parser phases are sound: add a candidate-only post-action B121 input selection test proving Type 2 owner identity and exact activation before `SfDoeStudy` lazy load. This step must not change default no-study selection semantics or synthesize a study for B120's before input.
5. Public `writeInputTable`, `saveInputTable`, `src/doe/activation.cpp` sample loading, DOE `temp.KWD` reconciliation and later Save effects are later dependencies. Keep current refusals and side-effect order until their own contracts/tests exist. The CP73 helper's exact B121 bytes are a candidate fixture-format test, not public writer completion.

## Evidence and limits

The retained B121 input table is the historical post-action file (707 bytes, SHA-256 `18ec0c482730c82ade12e91771ca67e53e4604573032624b99f3f4829a86b069`), not a fresh original Open–Save result for the no-study before project. `analysis/resume73-doe-tloc-writer-evidence.md` qualifies direct XML structural order and that the nominal getter is only a QString copy; `temp.KWD` belongs to the separate conditional dimension-reconciliation path, not automatically to direct XML serialization. The CP73 explicit attribute order is a fixture-specific byte regression, not a general Qt/native setter-order rule.

No source/test/build/GUI action or mutable REA operation was performed for this review. Public B121 Type 2 admission remains unresolved and no original parity claim follows.
