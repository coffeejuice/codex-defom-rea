## Method

* Graph: `deform-rea-work/out/pre64_funcs.tsv` direct calls plus the indirect edges of `docs/re/batch_scope.py` (function pointers `[p]`, pointer tables `[t]`, vtable slots `[v]` of the 62 vtables that batch_scope makes live). Edges into licence/Sentinel/process-monitor code are never followed (0x140090000-0x14012ffff, 1403c4504, not-needed rows whose note names licence or process-monitor code, and 1403c725d/1403c768e/14044cf00/14044cfc0, which carry the SDSPM/CLOSELM strings).
* Roots: main 14001c9f0, the -m path (14001b7b0, 14001c500), the KEY reader 1401b6520 / 1401b5f00 and the group parsers (14039aa90, 14038b8a0, 140388fb0, 140384a50, 140383120, 14037e530, 1402f76c0), every case of the dispatcher 140378e00 (the dispatcher itself is not expanded, as in batch_scope), the menus, the C++ static initialisers and the keyword-registry handler columns 2 and 3.
* Blocked nodes (a path through them does not count): every `not-needed` row of the merged status files (shape-roll subtree under 1402bd210, coating mesh 1401403c0, flag-gated and std::vector/STL replacements...), ported rows whose notes say the body is never entered in batch (1402a1df0 / 1401c5d20 short KEY writer, 14003dabe, 14005d44f, 1401d48d0, 1401d5820, 1401cf190, 1401cf220, 1403dc13f, 140202a70, 140401c40, 1404021a0, 140402c40, 14040dc00, 1402e24f0), the dead GENCTC pass (14001d99f, 140055162) and the kw-g1b rebuild branches 1401cbbc0->1401cf930, 1401cbc80->1401cfc30. Iostream users ported with stdio (above) are treated as ported-around for their STL callees.
* Chain: shortest path from the roots of the row's own `first_phase` (batch_scope phase roots, STOP nodes not re-expanded), falling back to any root. Written `root label: a > b > [v]c`, `[v]`/`[p]`/`[t]` marking an indirect edge. The TSV has the full chain; the tables below abbreviate long ones.
* Packets: per phase, the immediate-dominator tree (Cooper-Harvey-Kennedy, as `docs/re/phase5_8_9_10_packets.py`) of the blocked graph reachable from the phase roots; a subtree is cut into a packet once it holds >= 30 todo rows (bins <= 60). Rows that only the phase root dominates (shared helpers) are grouped by owner, then pooled per phase. Ported-but-status-missing rows are not in packets.
* Owner: the packet of the nearest dominator that a status file lists as ported/verified (not the generic p1-01 runtime or the dispatcher/KEY reader/main), else a status file listing the row as todo, else the packet owning most of its direct callers. Packet owner = majority of its rows.

## Caveats

* Vtable-slot edges are an over-approximation (a `call [reg+8k]` reaches slot k of every live vtable). 69 P3 rows are reachable only that way; all are MSVC STL iostream facet code. No other reachable todo depends on a slot edge alone. No reachable todo row has an unresolved `call reg` site.
* "Unreachable" relies on the flags documented in status notes and GENCTC.md; no new flag analysis was done and headless Ghidra was not needed (every unreachable chain ends in a documented block).
* The 49 P3 "ported around" rows and the 69 vtable-slot-only rows are not-needed only if every iostream user stays on C stdio; p8-01 (ARMCTL) and p9-01/p9-03 (CNVT3D logs) already do.
* Owners are a heuristic (nearest ported dominator); rows with owner basis "caller" were assigned from the packet owning most of their callers. "new packet" means no ported dominator or caller.
* Chains are shortest paths in the static graph, not necessarily the path a given KEY file takes.
