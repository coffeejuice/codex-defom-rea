# Group 2 (object) KEY parser `FUN_14038b8a0`: switch map

Source: `DEF_PRE_64.exe` v11.0.2. `FUN_14038b8a0(model, FILE *f, int keywordId)` is called by
the KEY interpreter `FUN_1401b6520` for every registry entry with `group_code == 2`.
The model it receives is `FUN_1401d81b0(model)`: the model itself, or the companion model at
`model+0x33e8` when that pointer is set and the byte `model+0x33f0` is nonzero. (On a
`DEFORM 3D` header comment the interpreter sets the model's dimension to 3 and the
companion's to 2, and the reverse for 2D; changing the dimension resets the whole model,
`FUN_1401c8ba0` → `FUN_1401cb440` + `FUN_1401c8c00`.)

Common prologue, object lookup, return codes and every reader helper are in
[group2-helpers.md](group2-helpers.md). In short: `fscanf("%i")` object number → get-or-create
object (`FUN_14019ccc0`, NULL for numbers < 1 → **2**) → `switch(keywordId - 0x90)` → helper
status nonzero → **2**, else **0**.

The 137 registry ids of group 2 run from 144 to 303 with gaps; the switch has 136 cases.
**OBJPHS (204, case 0x3c) has no case**: the `default:` label returns **2**, so a KEY file
containing `OBJPHS` fails with "Reading Error" after its object number has been read. The
writer never emits it (no name lookup of id 204 in any writer function).

Case bodies in the table refer to line numbers of the decompile of the function alone
(`deform-rea-work/out/g2/p_main.c`; regenerate with
`GPROJ=<copy> scripts/run.sh DEF_PRE_64.exe Decomp.java <out>/parser.c 1 14038b8a0` and
`scripts/fn.sh parser.c 14038b8a0 > p_main.c`). The table is produced by
[tools/g2_casemap.py](tools/g2_casemap.py). "Helpers" lists every function the case calls
other than the 2D/3D tests `FUN_1400015e0`/`FUN_1400015f0`.

In 2D, cases 0x9b, 0x9c and 0x9d (POLYTP, DIEPNT, DIEEDG) return 0 without consuming anything after
the object number, so the KEY loop then reads the leftover numbers as unknown keywords
(`WARNING: Keyword %s not found. Skip …`). Decompiled `if (FUN_1400015e0(model) == 0)` tests read as "not 2D": the first branch of STRAIN,
STRESS, NDTMP and MOVCTL is the 3D branch. Several cases branch on dimension (`FUN_1400015e0` = 2D, `FUN_1400015f0` = 3D); see each
keyword's spec.
