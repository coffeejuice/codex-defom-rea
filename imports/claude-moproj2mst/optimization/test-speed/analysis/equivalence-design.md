# Converter test speed equivalence

Use `admin/compare_test_speed_runs.py` after the baseline and candidate CTest runs. It reads four arguments in order: the baseline run directory, a preserved baseline `test-relocation-results.json`, the candidate run directory, and a preserved candidate receipt. The test launcher writes its detailed receipt to one shared analysis path, so preserve a copy immediately after each run. The comparator writes nothing and exits 0 for equivalent evidence, 1 for a difference, or 2 for missing or inconsistent evidence.

The comparator first checks each receipt against its own artifacts. It requires inventory, fixture manifests, JUnit, console and CTest logs, and every per-case log. It verifies registered test counts, unique names, reported versus unreported tests, receipt status counts, incomplete output lists, fixture change lists, JUnit names and failure/skip state, and case log text against JUnit `system-out`. This blocks acceptance of a truncated or partially copied run even when the compared receipts agree with each other.

Across runs, it compares complete inventory JSON after replacing only the two known absolute run/build roots. It compares the fixture manifests exactly, including size, timestamp, and SHA-256. It compares receipt status, exit code, counts, gaps, and unknown top-level fields; every test row's status, gap events, diagnostic differences, folder-sweep cases and tallies, and output completeness; and every case log as raw bytes. ABI test names are reported explicitly, and missing ABI tests block equivalence. Folder-sweep `SAME`, `DIFF`, `REFUSED`, notes, copy skips, and summary tallies remain in the compared row and log. The raw log hash is printed for a changed log.

Only declared timing fields, case `seconds`, receipt paths, and absolute run/build roots in CTest commands, inventory, or log text may differ without blocking equivalence. Such differences appear under `permitted_differences`; the raw log bytes are still compared and their hashes shown for path-only changes. Any other log change, including an unexplained numeric duration in diagnostic text, blocks equivalence. This deliberately avoids broad regex normalization that could hide a changed count, refusal, error, or ABI result. `elapsed_seconds` remains CTest-only and is not interpreted as whole-launcher time.

This check establishes equivalence of the recorded test evidence, not equivalence to a fresh original executable. The suite's historical oracles, permissive ABI assertion, diagnostic Save folder sweep, and skipped external fixtures retain the qualifications stated in each receipt. A faster CTest time alone is insufficient if a test disappears, a gap changes, a raw diagnostic changes, or output becomes incomplete.
