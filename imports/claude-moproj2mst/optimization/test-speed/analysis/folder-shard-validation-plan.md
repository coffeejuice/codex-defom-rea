## Current implementation evidence

`runCase` performs input/expected preflight before discovery and case counting; discovery freezes an ordinal and chosen moproj. Workers use `(ordinal - 1) % count`, preserve ordinal order within each child, and call the same comparator. `runShards` checks child process exit, result schema, echoed exact job bytes, result count, ordinal sequence, tally bounds, terminal state, and end-of-file before adding tallies or replaying events. These are source observations, not exercised failure guarantees.

`workerEnvironment` creates distinct TEMP, TMP and TMPDIR directories beneath each worker IPC directory, outside compared project leaves, and preserves the initial current directory. `FolderChild` terminates/reaps still-running owned children when unwinding. The parent reads children in worker order; case logs replay in discovery event order only after all children validate.

Two acceptance gaps remain visible in this capture. Raw output inventories/hashes and complete raw/adjusted decision vectors are not archived before per-case removal, and no same-path serial/sharded replay mode exists. Consequently adjusted SAME/DIFF totals and log equality cannot prove raw equivalence. Also, `folderWorker` captures all stderr into `worker.stderr`; the latest coordinator rejects even exit-zero children if that capture is nonempty. This prevents silent diagnostic loss, but a successful serial conversion emitting stderr becomes a sharded harness failure rather than matching serial behavior. Exact per-case stderr replay remains unimplemented. Repeat this review after edits; these findings may become stale.

## Controlled execution setup

The coordinator should use copied minimal fixtures and an isolated short scratch root under takeover scratch, with all generated test projects under C:/PROBLEM when project execution is involved. Freeze input inventory, executable hash, source hash, environment, schedule and chosen moproj for each attempt. Do not inject failures by editing evidence fixtures or interfering with unrelated processes. Use a deterministic test-only IPC/launcher seam or an owned helper binary for crash, delay and malformed-result cases; do not rely on polling races to edit production result files. If no such seam exists, mark those checks not run, rather than inferring coverage from happy-path runs.

Run the existing serial path (`M2M_FOLDER_WORKERS` absent), explicit 1, then 2 first. More workers only follow correctness. Gate variables remain unchanged; absent sweep/corpus gates must still perform no sweep. Validate worker values 0, 17, negative, empty, nonnumeric, whitespace, overflow-length and valid 1/2/16 while enabled. Use a manifest path containing spaces and Unicode to check process argument encoding.

## Interpretation and adoption

Keep conversion diagnostic differences/refusals separate from harness faults. Preserve all existing adjusted comparator behavior: raw comparison first, expected-only path relocation, case-sensitive extension exclusions, view masks, banner classification and three older-window exceptions. Exercise these differences in synthetic/copied fixtures so a naturally zero-refusal corpus cannot conceal a broken refusal/copy-skip path.

A passing 98-case adjusted sweep establishes schedule/status/comparator regression coverage for those inputs; it does not replace the raw parity gate or prove fidelity to a newly captured original application. Raw cross-run differences caused by differing PID/work/TEMP locations must be retained and qualified, not called byte-equivalent after normalization. If same-path replay is unavailable, report that limit and keep the serial default.

Archive every fault injection's expected/actual status, captured streams, result/manifest hashes, child PIDs and teardown receipt. Freeze the candidate before timed runs. After all focused gates pass, benchmark the frozen isolated sweep with paired warm repetitions, then normal full CTest membership and complete launcher timing including both fixture snapshots. Select a worker count only from complete passing runs. Do not sum child times as wall time or claim speedup from source inspection.
