# defmodel: module card

## Purpose

The in-memory keyword model of DEF_PRE_64: the session and step objects (`DB_STEP_DATA`,
`LLOBJ_DATA`, the database info `Cls_1401dbfe0`), object, mesh, material, boundary-condition and
state-variable classes, linked lists and copy-on-write containers, the keyword registry (304
records generated from the binary), units, options and model globals. Class layouts sit at the
binary's offsets (`docs/re/model-layout.md`), so `*(int*)(this + 0x1b60)` in a decompile maps to
a named member.

## Interface

* `defmodel/keyword_registry.hpp`: `lookup_keyword` and the other registry accessors.
  `keyword_registry_table.hpp` is generated by `scripts/gen_keyword_registry.py`; do not edit it.
* `defmodel/layout/*.hpp`: the real classes with `static_assert(sizeof)` and
  `DEF_LAYOUT_OFFSET` checks.
* `defmodel/llobj/`, `mesh2d/`, `statevar/`, `material/`, `bc/`, `geo/`, `topo/`, `linked/`,
  `sdctl/` (COW handles, `cow.hpp`), `tree/`: one folder per family.
* Cross-packet calls that were open during the port went through `llobj/ext.hpp`
  (`g_hook`, defaults `DEF_NOT_PORTED`); the generated block lists the stubs that are left.

## Fidelity class

F1 bit-exact for everything that reaches KEY or DB output. Layouts are part of the contract:
adding a member never moves an existing one. Model storage starts zero-filled like the original's
static storage (`UNIT` at sim_ctrl+0xfc is never written).

## Oracle tests worth knowing

`defmodel.keyword_registry_matches_binary` (table vs. the installed DEF_PRE_64.exe; skipped
without DEFORM), the layout tests, and the KEY round trips in `defkey` that construct these
classes.

## Perf baseline

Not measured yet. Record machine, build (Release, commit), input, wall time and peak memory, as
the `profile` skill (.claude/skills/profile) prints them.

## Swap notes

A new API should wrap these classes rather than change them: the offsets are what makes the
decompile readable and what the ported code relies on. STL placeholders keep the VS2010 sizes;
where no ported code uses an offset, a modern container already replaced the original.
