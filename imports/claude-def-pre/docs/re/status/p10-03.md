# p10-03: registry column-3 (axis label) handlers — verdict not-needed in batch

Check T10-1 of docs/phase5_8_9_10-packets.md, static analysis of DEF_PRE_64.exe v11.0.2 (headless
Ghidra, copy ghidra_p671; scripts deform-rea-work/scripts/RefsTo.java and AddrInfo.java; outputs
deform-rea-work/out/p671/p1003_refs.txt, regbase_refs.txt, regacc_refs.txt, reg.c, reg2.c).

## Evidence

1. **The 49 handlers have no caller.** For each address the full reference list and a raw scan of
   the whole image (8-byte pointer and 4-byte RVA patterns) find exactly two hits: one 8-byte
   pointer inside the keyword registry (0x140544400, 304 records of 0x30 bytes), always at record
   offset **+0x28** (handler3, the column-3 slot; 49/49), and one RVA in `.pdata` (its own
   unwind entry). No code reference, no other pointer.
2. **Only `FUN_1402f7a70` reads +0x28.** Code that touches the registry: `FUN_1402f7790` (id by
   index, +0), `FUN_1402f78d0` (record by name) and `FUN_1402f7950` (record by id). The record
   pointers they return are used by `FUN_1402f7680` (+0), `FUN_1402f76c0` (+0, +0x10),
   `FUN_1402f7720` (+8), `FUN_1402f77e0` (+0x14), `FUN_1402f7830` (+0x18), `FUN_1402f7880`
   (+0x10), `FUN_1402f79c0` (+0x20, the KEY write handler) and `FUN_1402f7a70` (+0x28). No other
   code references the table or the two lookups (their other references are `.pdata`).
3. **`FUN_1402f7a70` is never called.** Its references are its `.pdata` entry (0x140b9ad6c) and an
   EH `IPToStateMapEntry` (0x1405ac79c, exception metadata); the raw scan finds no pointer to it.

So no path of DEF_PRE_64 (batch or menu) can invoke a column-3 handler: **not-needed**.
